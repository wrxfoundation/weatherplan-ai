# 토스페이먼츠 결제 연동 (2026-09-23)

kcare-app 에 토스페이먼츠 결제를 붙였다. 이 문서는 키 등록 · 심사용 모바일웹 URL ·
동작 확인 순서를 적는다.

## 1. 무엇이 붙었나

| 자리 | 종류 | 화면 |
|---|---|---|
| 스토어 주문 | 일반 결제 (결제위젯) | 보호자 스토어 → `물품 담기` → `N원 결제하기` |
| 해주세요 요금 | 일반 결제 (결제위젯) | 보호자 해주세요 → 결제대기 건 → `N원 결제하기` |
| 월 구독료 | 자동결제 카드 등록 (빌링) | 보호자 마이 → 결제 관리 → `카드 등록하고 자동결제 시작` |
| 가입·설치비 | 일반 결제 (결제위젯) | `/pay?kind=entry&amount=385000` 로 연결 가능 |

연동 방식은 토스페이먼츠 JavaScript SDK v2 (`@tosspayments/tosspayments-sdk`) 다.
일반 결제는 결제위젯(주문서형)이고, 구독은 `requestBillingAuth('CARD')` 로 카드만 등록한다.

## 2. 키 등록 (이걸 해야 결제창이 열린다)

토스페이먼츠 개발자센터 > 내 개발정보에서 두 값을 받아 등록한다.

```
NEXT_PUBLIC_TOSS_CLIENT_KEY=   # 클라이언트 키 — 브라우저 노출 전제
TOSS_SECRET_KEY=               # 시크릿 키 — 서버 전용
```

- **로컬**: `kcare-app/.env.local` 에 넣는다. `.gitignore` 가 이미 막고 있으니 git 에 올라가지 않는다.
- **Vercel**: 프로젝트 Settings > Environment Variables 에 같은 이름으로 등록하고 재배포한다.

키가 없으면 결제 화면이 "결제 키가 설정되지 않았습니다" 안내를 띄우고, 승인 API 는 503 을
돌려준다. 가짜로 성공시키지 않는다.

테스트 키(`test_` 로 시작)를 넣으면 화면 오른쪽 위에 **테스트 모드** 배지가 뜨고 "실제로
청구되지 않습니다" 문구가 붙는다. 실키로 바꾸면 자동으로 사라진다.

## 3. 심사용 모바일웹 URL

토스 쪽에서 "모바일웹 URL이 나와야 한다"고 한 건 심사에 쓸 실제 동작 주소가 필요하다는 뜻이다.
kcare-app 은 저장소 안의 독립 Next.js 앱이라 **Vercel 프로젝트를 따로 만들고 Root Directory 를
`kcare-app` 으로 지정**해서 배포하면 자체 URL 이 나온다.

심사에 낼 주소:

| 항목 | 경로 |
|---|---|
| 서비스 소개 | `/service` |
| 가입 (요금 표기) | `/onboarding` |
| 결제 화면 | `/pay?kind=store&amount=26000&orderName=영국산%20비타민C` |
| 결제 결과 | `/pay/result` |

주의: 지금 배포에 Deployment Protection 이 걸려 있으면 심사자가 못 연다. 심사 기간에는
보호를 풀거나 심사자 접근을 허용해야 한다.

## 4. 동작 확인 순서

1. 키를 넣고 배포한다.
2. 휴대폰에서 `/family/store` 를 연다 → 물품을 담고 `결제하기` 를 누른다.
3. 결제수단 UI 가 뜨는지 확인한다 (이게 뜨면 클라이언트 키가 맞다).
4. 결제를 마치면 `/pay/result` 로 돌아온다 → "결제가 완료되었습니다" 와 영수증 링크가 보이면
   시크릿 키까지 맞는 것이다.
5. `/family/my` > 결제 관리 에서 결제 내역과 등록된 카드가 보이는지 확인한다.

## 5. 안전장치

- **금액 위변조 차단**: 이 앱에는 주문 DB 가 없어서, 결제 시작 때 서버가 (주문번호+금액)에
  HMAC 서명을 만들고 승인 때 다시 검증한다. 브라우저에서 금액을 바꾸면 승인이 거부된다
  (`AMOUNT_MISMATCH`). 실서비스로 갈 때는 이 서명 대신 **주문 테이블을 두고 서버가 보관한
  금액과 대조**해야 한다.
- **시크릿 키**: `lib/toss-server.js` 에서만 읽고 응답·로그 어디에도 싣지 않는다.
- **승인 기준**: 결제창에서 돌아온 것만으로 완료 처리하지 않는다. 서버 승인 API 가 성공해야
  주문·요청이 다음 단계로 넘어간다.
- **카드정보**: 토스페이먼츠가 보관한다. K-CARE 서버에 저장하지 않는다. 빌링키는 브라우저로
  내려보내지 않는다.

## 6. 남은 일 (실서비스 전)

- **주문 테이블** — 위 HMAC 서명을 대체한다. 결제 전 주문을 서버에 만들고 금액을 대조.
- **billingKey 보관과 월 청구** — 지금은 카드 등록까지만 한다. 매월 청구하는 스케줄러가 필요하다.
  (`POST /v1/billing/{billingKey}` · 서버 작업)
- **취소·환불 API** — 화면에는 "고객센터로 연락" 으로 안내하고 있다.
  (`POST /v1/payments/{paymentKey}/cancel`)
- **웹훅** — 가상계좌 입금·취소 등 비동기 상태 변경 수신.
- **현금영수증·에스크로** — 상점 정책에 따라 결정.

## 7. 이 환경의 제약 (작업 기록)

작업한 컨테이너에서는 `api.tosspayments.com` · `js.tosspayments.com` · `docs.tosspayments.com`
이 네트워크 정책으로 막혀 있어 **실제 결제창을 띄운 종단 확인은 하지 못했다**. 연동 코드는
설치한 SDK(`@tosspayments/tosspayments-sdk@2.8.1`)의 타입 정의를 근거로 작성했고, 화면 렌더링 ·
키 미설정 안내 · 승인 실패 처리 · 금액 서명 검증은 로컬에서 확인했다. 실제 결제는 키를 넣고
배포한 뒤 위 4번 순서로 확인해야 한다.
