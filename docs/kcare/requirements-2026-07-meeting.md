## 1. 요약

회의 결정 16건을 기존 문서와 대조한 결과:

- **기존 문서에 전혀 없는 신규 기능 7건** — 공유 캘린더(REQ-02), 해주세요 요청 시스템(REQ-03), 장바구니·결제권한(REQ-07), 컨시어지 쇼핑탭(REQ-08), 안심케어박스 교체 워크플로(REQ-10), 방문기록·긴급 영상 모드(REQ-12 일부), 병원 검색(REQ-13). 프로토타입 33화면·PRD F1~F12 어디에도 대응 화면/기능이 없음.
- **기존 기능의 변경·구체화 6건** — 병력 기반 날씨 우선표시(REQ-01, F8 확장), 관제·긴급 대응 범위(REQ-04, S3·F5-7 구체화), SOS UX(REQ-06, F3-3 변경), 컨시어지 당일 동선(REQ-09, Assignment 확장), 관찰 리포트(REQ-11, Report 구체화), 지역 심사(REQ-15, 거주지 적합도 5축의 제품화).
- **가격 최초 확정** — PRD 11.3은 전 항목 미확정이었고, 프로토타입의 가입비 300,000원·플랜 390,000~1,690,000원은 목 데이터. 회의 확정치(가입비 12~15만, 1급지 월 57,000)가 첫 실제 가격 결정이며 기존 문서·프로토타입 수치와 전면 상충 → §5 정합화 필요.
- **규제 경계와의 충돌 없음, 단 4건은 조건부** — 케어박스 의약품 취급(REQ-10), 방문 영상(REQ-12), 보험 입점(REQ-14), 병원 검색(REQ-13)은 기존 도메인 규칙(의료법 17·27조, 개보법)의 경계 안에서만 성립. 각 항목에 준수 조건 명시.

## 2. 요구사항 상세

### REQ-01 · 병력 기반 맞춤형 날씨 우선표시 — 변경 (조건부 반영 확정)

**회의 결정** 병력에 따라 중요 웨더 요소를 우선 표기(갑상선=온도, 호흡기=습도·미세먼지). 단, **자동 추론이 아니라 컨시어저·보호자·어르신이 직접 설정**하는 방식(민감정보 자동 처리 인상 회피 — 이성준 검토, "조건부 반영").

**요구사항**
- 케어 프로필에 "우선 표시 환경 요소" 설정 항목 추가. 설정 주체: 보호자·어르신·컨시어지(담당 고객 한정). 설정 이력(누가·언제) 기록.
- 어르신 홈 "지금 우리 동네"·"오늘 외출 컨디션", 가족 앱 환경 카드에서 설정된 요소를 최상단 정렬·강조. 미설정 시 기본 정렬 유지.
- 설정 화면 문구는 "건강 상태에 맞춰 먼저 보고 싶은 날씨 항목"류의 **사용자 선택 프레임**으로 작성. "질환 등록" 프레임 금지.

**기존 문서 매핑** PRD F8-1~3(외출 컨디션, 구현), F8-9(호흡기 질환자 관리 P3 — "등록 어르신" 기반이므로 본 결정의 수동 설정 원칙과 정합. 자동 감지가 아니라 등록 기반임을 F8-9 설명에 명시 필요), F7 케어 프로필. 핸드오프 `04-data-model.md` OutingCondition.factors, Elder.conditions[].

**규제 체크** 건강 민감정보 자동 프로파일링 회피 원칙은 PRD 16장 리스크("건강 민감정보 취급") 대응과 일치. conditions[] 기반 **자동** 우선표시는 하지 않음 — 설정값(`priorityFactors`)과 병력(`conditions`)을 별도 필드로 분리 저장.

### REQ-02 · 보호자·사용자·컨시어저 공유 캘린더 — 신규

**회의 결정** 공유 일정 9종(병원 예약 / 복약 알림 / 컨시어지 방문 / 약상자 교체 / 건강검진 / 보호자 방문 / 상품 배송 / 추가 요청사항 / 다음 진료 예정일). 권한 4단계. 컨시어지가 병원에서 다음 예약을 등록하면 보호자·사용자에게 즉시 공유. **홈 화면에는 "다음 일정: 8월 5일 오전 10시, 내과 진료" 한 줄만 노출, 클릭 시 달력** (원 회의의 "마이탭 숨김" 안은 이성준 검토로 홈 노출안으로 대체).

**권한 매트릭스 (확정)**

| 역할 | 권한 |
|---|---|
| 보호자 | 조회 · 등록 · 수정 · 결제 |
| 사용자(어르신) | 조회 · 알림 확인 · 간단 등록 |
| 컨시어저 | 담당 고객 일정 조회 · 업무 관련 일정 등록 |
| 관리자 | 전체 조회 · 조정 · 감사기록 |

**요구사항**
- 일정 엔티티 신설: `CareEvent { id, elderId, kind(9종), at, title, source(역할), visibility, linkedId }`. `linkedId`로 Assignment·해주세요 요청·배송 건과 연결.
- 지정 기간 내 알람은 팝업(푸시)으로 표기, 탭하면 달력 열림. 어르신 화면의 알림·달력은 핸드오프 접근성 규격(본문 18px+, 히트 타겟 44px+) 준수.
- 컨시어지 등록 일정은 즉시 보호자·사용자 캘린더에 반영 (PRD 비기능 "역할 간 상태 전파 3초 이내" 적용).
- 관리자 권한의 "전체 조회"는 **감사·조정 목적으로 한정**하고 접근 로그를 남김 — 핸드오프 "관리자는 개별 사건을 보지 않는다" 원칙과의 충돌을 피하기 위해 관리자 기본 화면에는 캘린더를 노출하지 않고 감사 화면에서만 진입.

**기존 문서 매핑** PRD F2-3(다가오는 일정)·F3-2(오늘 일정)·F3-6(복약 알림 P2)은 **조회 전용** — 공동 편집·역할 간 등록 개념은 신규. 프로토타입 family `book` 탭·일정 변경 바텀시트는 UI 출발점으로 재사용. 핸드오프 `02-core-roles.md` family 카드 8(다가오는 일정), elder 카드 2(오늘 일정).

### REQ-03 · 양방향 "해주세요" 요청 시스템 — 신규

**회의 결정** 단순 채팅이 아닌 **업무형 요청 시스템**. 보호자→컨시어저(약 구매·병원 예약 확인·집 상태 확인·물품 전달·다음 방문 때 확인), 컨시어저→보호자(결제 필요·약 부족·병원 예약 확인 필요·추가 동행 필요·집안 안전조치 필요).

**상태 모델 (확정 8종)** `요청됨 → 확인됨 → (결제대기) → 처리중 → 완료` + `취소` / `처리불가` / `관리자 확인필요`

**요구사항**
- 엔티티: `CareRequest { id, elderId, from(역할), to(역할), type, status(8종), photos[], amount, preferredDate, urgency, assigneeId, proofPhotos[], createdAt, history[] }`. 요청별 첨부 6종(사진·금액·희망일·긴급도·담당자·완료증빙) 필수 스키마.
- 상태 전이는 서버가 소유. 전이 이력(`history[]`) 전건 기록 — 분쟁 대비 감사 로그.
- `결제대기` 상태는 REQ-07 결제권한·한도 규칙과 연동 (한도 초과 시 보호자 승인 필요).
- `관리자 확인필요`는 품질·CS 화면(`quality`)의 티켓으로 승격되는 경로 정의.
- 컨시어지 측 처리는 오프라인 큐 대상 (핸드오프 오프라인 우선 원칙 + `POST /concierge/*` 멱등키).
- 요청 유형 중 "약 구매"는 REQ-10의 의약품 취급 경계를 따름 (구매대행·전달만, 복약 관여 금지).

**기존 문서 매핑** 기존 문서에 대응 기능 없음(프로토타입 검색 결과 0건). PRD F2-4(컨시어지 연결)는 상담 연결일 뿐 업무 요청 아님. 핸드오프 `quality` 화면(SEV 티켓)과 상태 설계 관례 공유.

### REQ-04 · 관제실 24시간 운영 · 긴급 대응 범위 — 변경(범위 확정)

**회의 결정** 기본 서비스는 **긴급신호 접수 + 119 신고 지원까지**. 보호자 부재 상황 대응과 임시보호자 역할 범위를 **계약서(약관)에 명시**. 긴급 초동 대응·야간 출동은 별도 서비스(외주)로 분리.

**요구사항**
- SOS·이상 징후 처리 플로우(S3, F5-7)에 서비스 경계 반영: 관제 화면의 조치 옵션은 "컨시어지 급파(주간·가용 시)"와 "119 연계"로 구분하고, **기본 상품에서는 119 연계까지가 보증 범위**임을 상태 모델에 반영.
- 야간 출동(외주)은 옵션 상품 플래그로 분리 — 가입 가구별 활성 여부에 따라 관제 조치 옵션이 달라짐.
- 약관 작업 항목(제품 외 병행): 보호자 부재 시 조치 권한, 임시보호자 역할 범위, 119 신고 지원의 한계(응급의료 행위 아님) 명시. REQ-12 영상 동의 조항과 함께 가입 약관 개정 1건으로 묶음.
- 관제 SLA(핸드오프: SOS 초동 응답 60초)는 유지 — 이는 "접수·연계" SLA이지 현장 도착 SLA가 아님을 문서화.

**기존 문서 매핑** PRD S3(응급 흐름)·F2-8(가족+컨시어지+119 자동 알림 P1)·F5-7(SOS 대응 콘솔, 119 연계 기록)·리스크 "응급 상황 대응 실패 — 119 연계 절차 문서화". 핸드오프 사건 A 정보 비대칭 매트릭스(가족에게는 "이미 대응 중"만, SLA 비노출) 유지.

### REQ-05 · 기본상품 구성·가격 — 확정(일부 미결)

**회의 확정**

| 항목 | 값 |
|---|---|
| 가입비 | **120,000원 또는 150,000원 (미결)** — 25% 수수료 언급(의미 확정 필요, §7) |
| 월 구독료 | **1급지 57,000원** / 2급지 별도 산정(미결) |
| 기본 제공 | 갤럭시 워치 · 생활안심 약상자(케어키트) · 웨어러블 건강 모니터링 · 보호자 알림 · 공유 캘린더 · **월 1회 재택 케어방문(연 12회)** · **연 4회 병원동행 또는 픽업** · 상비약·생활물품 구매지원 · 월간 케어리포트 · 긴급신호 접수·119 신고지원 |

**요구사항**
- 모든 단가는 PRD 11.3 지침대로 **운영 중 변경 가능한 설정값**으로 구현 (하드코딩 금지).
- 구독 상품 스키마에 급지(`regionTier`)별 요율, 포함 수량(방문 12회/년, 동행 4회/년) 및 **소진 카운터** 필요 — 포함분 초과 동행은 건별 과금(수익원 01)으로 전환되는 경계 로직.
- 가입비는 "전담 컨시어지 배정 + 초기 상담 + 프로필 구축"이라는 실체적 가치에 대응 (PRD 11.3 원칙 유지).
- 워치·케어박스는 기본 제공 기자재 — 재고·지급 관리는 파트너/조달 관점 확인 필요(핸드오프 1.3 "자본집약 자산 소유 금지" 원칙과의 관계: 워치·키트는 소모성 제공물로 예외인지 렌탈 구조인지 미결).

**기존 문서와의 상충 (조치 필요)**
- 프로토타입 onboard 화면: 가입비 300,000원, 플랜 베이직 390,000/프리미엄 890,000/시그니처 1,690,000 — **전부 목 데이터. 회의 확정치로 교체** (IR 덱·증빙 리포트 등 reference 문서도 동시 수정 대상, 핸드오프 "변경 시 4곳 동시 수정" 규칙).
- PRD 11.3 시뮬레이션(구독 단가 25,000~100,000원 구간)과는 정합 — 57,000원은 구독 비중 약 20~25% 가정선.
- 회의의 "기본 구독에 연 4회 동행 포함"은 PRD 수익원 01(병원동행 건별)·03(월 구독) 구조에 **포함분/초과분 경계**를 신설하는 변경.

### REQ-06 · SOS 버튼 위치·오작동 방지 — 변경(확정) → **2026-08-12 시트로 일부 대체 (§8-1)**

**회의 확정** 하단 메뉴가 아닌 **항상 보이는 위치**: 화면 오른쪽 상단 고정 또는 하단 중앙 플로팅(디자인 시안에서 택일). 오작동 방지: **2초 길게 누르기 → 5초 취소 카운트다운 → 미취소 시 자동 접수**.

> **현재 구현은 이 결정과 다릅니다.** 8/12 시트가 화면 안 SOS 버튼을 빼기로 했습니다 —
> 지금 진입점은 바탕화면 바로가기 하나이고, 5초 취소 유예만 남았습니다. 경위는 §8-1.

**요구사항**
- 어르신 홈 전 탭에서 SOS 버튼 상시 노출 (스크롤·탭 전환과 무관).
- 인터랙션: long-press 2초(진행 표시) → 접수 예고 + 5초 취소 버튼(대형) → 자동 접수. 취소 시 아무 알림도 발신하지 않음.
- 접근성: 히트 타겟 44px 이상(어르신 규격은 그 이상 권장), 색+텍스트 병행, 누름 상태의 물리적 피드백(핸드오프 elder 버튼 규격). 오른쪽 상단 고정안 채택 시 버튼 크기가 접근성 하한을 지키는지 디자인 검증 필수 — 상단 코너는 도달성이 낮아 **하단 중앙 플로팅안을 권장**(디자인 결정으로 위임).
- 접수 후 화면은 기존 원칙 유지: "선생님이 오고 있습니다" 안심 화면 (핸드오프 사건 A).

**기존 문서 매핑** PRD F3-3(대형 버튼 1회 터치)·S3. **"1회 터치" → "2초 길게+취소 유예"로 PRD 변경** 필요. 오작동(오탐) 방지 취지는 핸드오프 알림 철학(오탐이 신뢰를 깎는다)과 일치.

### REQ-07 · 장바구니·결제권한 — 신규

**회의 결정** 부모(어르신)가 담고 보호자가 결제하는 장바구니. **가입 시 결제권한 선택**: ① 사용자만 ② 보호자만 ③ 양쪽 모두 ④ 한도 기반(일정 금액 이하 사용자 직접, 초과 시 보호자 승인). **권장 기본값: 5만원 이하 사용자 직접 결제, 초과 보호자 승인.**

**요구사항**
- 가구(계약) 단위 결제정책 엔티티: `PaymentPolicy { householdId, mode(4종), limitAmount(기본 50,000), approverGuardianId }`. 온보딩 플로우(onboard)에 선택 단계 추가, 이후 마이페이지에서 보호자가 변경 가능(변경 이력 기록).
- 어르신 장바구니 UI는 elder 접근성 규격 적용. 담기 → 정책에 따라 "바로 결제" 또는 "보호자 승인 요청"으로 분기, 승인 요청은 REQ-03 상태 모델(`결제대기`) 재사용.
- 보호자 승인 화면: 품목·금액·요청자 표시, 승인/거절 + 사유. 모든 승인·거절 로그 보존.
- 고령 소비자 보호: 반복 결제·고액 이상 패턴 알림(PRD 리스크 "불완전판매" 대응 준용). 자비 결제 원장에 기록(급여 원장과 분리 — 핸드오프 1.4).

**기존 문서 매핑** 기존 문서에 없음(프로토타입 "장바구니" 0건). PRD 수익원 06(헬스케어 커머스)의 실현 수단. 핸드오프 1.1 "제안은 근거(trigger) 동반" 원칙은 **추천 노출**에 적용되고, 어르신 자발적 담기에는 미적용(관측 근거 불필요).

### REQ-08 · 컨시어지 쇼핑탭(구매대행) — 신규

**회의 확정 플로우** 물품 확인 → 상품/요청사항 등록 → 예상금액 표시 → 보호자 승인 요청 → 결제 → 구매 → 배송 또는 다음 방문 전달 → 완료사진 업로드.

**요구사항**
- REQ-03 `CareRequest`의 특수형(type=구매대행)으로 구현 — 상태 모델·첨부 스키마 공유. 승인·결제는 REQ-07 정책 엔진 경유.
- 완료증빙(구매 영수증·전달 사진) 필수. 금액 확정 전 "예상금액" 표기와 확정 금액의 차액 규칙(재승인 임계값) 정의 필요(미결).
- 컨시어지 화면·성과 지표에 판매액을 귀속시키지 않음 — **구매대행 건수·처리 시간만 기록** (핸드오프 1.1 절대 원칙. Concierge 엔티티 `salesAmount` 금지 필드 유지).
- 상비약 구매대행은 REQ-10 경계 준수: 일반의약품을 고객 요청에 따라 약국에서 구매·전달만. 의약품 추천·복약 지도 금지.

**기존 문서 매핑** PRD F4-5(업셀링 제안 도구 P2)와는 별개 — F4-5는 "제안", 본 건은 "요청 수행". PRD 수익원 16(생활지원 — 구매대행 포함, "인증 불필요·즉시 착수 가능" 분류)과 06(커머스)의 실현 기능.

### REQ-09 · 컨시어지 당일 동선 표시 — 변경(확장)

**회의 확정 표시 항목** 현재 출발지 · 고객 주소 · 병원 주소 · 예상 이동시간 · 주차정보 · 환자 승하차 위치 · 휠체어 진입 가능 여부 · 다음 일정까지 여유시간. **고객 상세 주소는 담당 확정 이후에만 노출.**

**요구사항**
- `Assignment`에 동선 필드 확장: `route { originAddr, destAddr, etaMin, parkingNote, pickupPoint, wheelchairAccess }` + 다음 배정과의 buffer 계산.
- 주소 노출 게이팅: 배정 승인(approvedAt) 전에는 행정동 수준까지만, 승인 후 상세 주소 노출 — API 응답 레벨에서 강제(화면 숨김이 아니라 데이터 미전송).
- 주차·승하차·휠체어 정보는 Elder 주거 프로필에 축적(최초 방문 시 기록 → 재사용). 거주지 적합도 5축 심사(REQ-15) 입력값과 공유.
- 오프라인 선캐시 대상 (핸드오프 컨시어지 오프라인 우선).

**기존 문서 매핑** PRD F4-1(오늘 배차 조회 — 시간·병원·고객·소요시간)의 확장. 핸드오프 concierge 블록 2(동행 대상자 카드)·dispatch 지도. 주소 게이팅은 신규 보안 요구사항.

### REQ-10 · K-CARE 안심케어박스(약상자) 관리 — 신규

**회의 확정** 명칭 **"K-CARE 안심케어박스"**(잠정 — 더 좋은 명칭 접수 중). 기본 품목: 체온계·밴드·거즈·소독용품·마스크·손소독제·냉찜질팩·비상연락카드·복약체크표 + 진통제·파스 등 상비약. 월 1회 방문 시 소진량 기록 후 **새 키트로 교체**.

**방문 기록 필드 (확정)** 기존 키트 전체사진 · 품목별 잔여량 · 유효기간 · 개봉 여부 · 보충 필요 여부 · 보호자 승인 · 새 키트 전달사진.

**의약품 취급 경계 (확정 — 이성준 검토안 채택)**
- 상비약은 **고객 요청에 따라 약국에서 구매한 것을 보관**하거나 **고객 소유 의약품의 수량만 확인**하는 구조. K-CARE가 의약품을 직접 판매·조제·배분하지 않음(약사법). 컨시어지의 복약 보조·투약 행위 금지(의료법 27조 — 핸드오프 2.3 "컨시어지 직무는 이동·소통·기록"). 회의 원문의 "약 채우기"는 **비의약품 품목 보충 + 의약품 수량 확인·구매대행**으로 한정 해석.
- 복약체크표는 어르신 본인 기록용 인쇄물 — 컨시어지가 복약 여부를 기록·판단하지 않음.

**요구사항**
- 엔티티: `CareKit { householdId, items[{name, qty, expiry, opened, isMedicine, ownedBy}], lastSwapAt }` + `KitVisitLog { photosBefore[], remains[], needsRefill[], guardianApprovedAt, photosAfter[] }`.
- 컨시어지 방문 체크리스트에 키트 점검 단계 내장, 사진은 오프라인 큐 → 동기화. 소진 패턴은 보호자 리포트·구매 제안 trigger로 활용(근거 동반 제안 원칙).
- 보충 필요 품목 → REQ-03/08 구매대행 요청으로 원클릭 전환.

**기존 문서 매핑** 기존 문서에 없음(프로토타입 "약상자·키트" 실질 0건). PRD 수익원 03(구독 기본 제공물)·06(커머스 연계). 핸드오프 concierge 체크리스트 관례.

### REQ-11 · 가정환경·정서 상태 관찰 리포트 — 변경(구체화)

**회의 확정** 월 1회 방문 시 워치로 못 보는 정보 수집: 집안 정리·냄새·환기·식품 보관·낙상 위험물·조명·냉난방·의복 상태·대화 반응·식사 여부·외로움 호소·수면 호소·반복 불안 표현 (12항목). **컨시어지가 우울증·치매·정신질환·자살위험을 진단하게 해서는 안 됨** — 관찰 사실과 직접 발언만 기록. 좋은 예: "지난 방문보다 대화량이 감소했고, '아무것도 하기 싫다'는 말을 세 차례 함."

**리포트 열람 (회의)** 본인 작성 리포트는 전부 표시, 타인 작성 리포트는 공유된 부분만. 비밀(비공유) 내용 구분 관리, 보호자 열람 범위 설정 가능.

**요구사항**
- 관찰 체크리스트 12항목을 구조화 입력(선택지+자유 관찰문)으로 제공 — 자유문 입력란 상단에 "관찰한 사실과 들은 말만 적어주세요" 고정 안내.
- `Report` 스키마의 금지 필드 원칙 유지(diagnosis·opinion·prescription_interpretation 없음 — 의료법 17조, 핸드오프 04). **정서 관련 판단성 어휘(우울함·치매 의심 등)는 입력 단계 경고 + AI 초안 생성 프롬프트 레벨 차단.**
- 열람 범위: 리포트 섹션 단위 `visibility(shared|internal)` — internal은 관제·품질 관리용. 보호자별 열람 범위 설정은 핸드오프 1.2 "가족 정보 접근에 위계를 두지 않는다" 원칙과 충돌 소지 → **가족 간 차등이 아니라 [가족 전체 공유 / 운영 내부] 2단계로 구현**하고, 민감 문서 예외(장례 의향서류)만 별도 규정. 회의 원안(보호자가 볼 수 있는 부분 설정)은 이 경계 안에서 재해석 — 미팅 확인 안건(§7).
- 리포트 누적 열람(타임라인) 화면 제공 — 작성자 본인 전체 / 타 역할은 shared만.
- 정서 신호 임계(예: 불안 표현 반복) 도달 시 진단 없이 **연계 절차**만 개시(정신건강복지센터 등 — PRD 11.9 행위 경계 준용, F1-6 정서 케어 응답과 동일 원칙).

**기존 문서 매핑** PRD F4-3(동행 완료 리포트)·S2(AI 초안 60초)·수익원 21(행위 경계). 핸드오프 `profile` 화면(관찰·진술 병합, 미확정 정보 관리), 증빙 보고서 양식.

### REQ-12 · 영상 기능 3모드 + 감사 기록 — 신규(일부는 기존 tele 확장)

**요구사항**
- `VisitAuditTrail { assignmentId, events[{at, kind(gps|video|photo|checklist|report), ref}] }` — Assignment 체크인·REQ-10 키트 로그·REQ-11 리포트와 자동 연결.
- 열람 권한: 당일 담당 컨시어지·등록 보호자·(원격상담 시) 지정 의료진로 제한, 전 접근 감사 로그 — **프로토타입 tele 화면의 기존 설계 재사용** (영상·음성 전 구간 암호화, 열람 제한, 접근 감사 로그, 스마트 글래스 가드레일: Privacy LED·물리 렌즈 셔터·패닉 뮤트·화각 정리·작동 안내 뱃지·세션 개시 전 명시 동의).
- 방문기록 모드 간편 촬영 버튼은 컨시어지 수행 중 화면에 배치 — 촬영 시작 시 활동 태그(약상자 점검 등) 선택 → 감사 기록에 자동 연결.
- 회의 원안의 "가정 진입 시 바디캠 · 보호자 동시 시청(구글 글라스)"은 ①·② 모드 규칙으로 흡수: 상시 바디캠이 아니라 동의·순간 중심. 보호자 실시간 시청은 원격상담 모드(3자 세션)로 제공.
- 오프라인 대응: 병원 지하 등에서 영상 업로드는 로컬 암호화 큐 → 복구 시 전송.

**기존 문서와의 관계 (중요)**
- 프로토타입 `tele` 화면에 **원격상담 모드의 실질 설계가 이미 존재** (글래스 1인칭 공유·3자 세션·AI 노트·실시간 통역 + 프라이버시 가드레일 6종) — ① 모드는 신규가 아니라 이 설계의 채택·구현.
- ②·③ 모드는 신규. 단, 기존 문서의 **"카메라 없음" 비침습 원칙**(PRD F8-8 비접촉 안부 확인 "카메라 미사용", device 화면 "동작 감지 센서 4구 · 카메라 없음 — 프라이버시 원칙")과의 서사 충돌 주의: **상시 설치 카메라는 계속 두지 않으며, 영상은 "사람이 방문한 순간"에 한정**된다는 구분을 약관·마케팅 문구에 명시. 센서 기반 안부확인의 "영상이 없으면 계속 켜 둘 수 있다" 논리를 훼손하지 않는 것이 원칙.
- PRD 리스크 "리포트 공유를 통한 제3자 건강정보 노출"·개보법 이동형 영상정보처리기기 규정 → 법률 검토 선행 항목(§7). 2인 1조 리스크(H11 성희롱·금품 의혹 양방향) 완화책으로서의 영상 기록은 긍정 효과 — 목적 명시에 포함.

### REQ-13 · 병원 검색 — 신규

**회의 결정** MOU 체결 병원 찾기. **진료 과목마다 최소 1곳** 확보 목표.

**요구사항**
- 제휴 병원 디렉터리: 진료과목·지역·패스트트랙 여부 필터. 데이터는 dispatch 지도의 제휴 병원 데이터(패스트트랙 대기일·슬롯 운영)와 단일 출처 공유.
- **의료법 27조 3항 준수(핸드오프 C4)**: 검색 결과는 항상 **2곳 이상 병렬 제시**(1곳뿐인 과목은 "제휴 외 일반 안내" 병기), 선택 근거 기록. 특정 병원 단독 추천 UI 금지. 검색·연계는 "제휴 병원 안내 + 예약 행정 대행" 프레임 — 건별 유치 수수료와 연결 금지(월정액 용역료 구조).
- 검색 → 예약 요청(F1 접수 흐름) → 캘린더(REQ-02) 연결.
- 과목별 최소 1곳 MOU는 제품 요건이 아니라 제휴 영업 목표로 관리 — 미충족 과목은 "준비 중" 정직 표기(PRD 정직성 원칙).

**기존 문서 매핑** PRD 수익원 05(병원연계 — C4 구조 전환 필수)·F1-3(슬롯 매칭). 프로토타입 dispatch 지도·partner 화면. 검색 UI 자체는 신규.

### REQ-14 · 옵션 판매·보험 연계 — 신규(선결 조건부)

**회의 결정** 신규 등록·판매 프로세스 = 옵션 판매(접수, 결제요청). 보험 → 보험회사 연계 = 입점 수수료.

**요구사항**
- 옵션 상품(야간 출동, 추가 동행, 생활지원 등) 카탈로그 + 접수·결제요청 플로우 — REQ-03/07 인프라 재사용.
- 보험 입점: **GA 등록(또는 등록 GA 제휴) 완료 전 모집 관련 기능 전면 잠금**(기능 플래그) — PRD 수익원 11·리스크 H4, 핸드오프 2.5. "입점 수수료" 모델도 보험업법상 모집 행위·특별이익 제공 금지와의 관계를 법률 검토로 확정한 뒤 설계(§7). 컨시어지는 '안내'까지만, '모집'은 등록 인력.

**기존 문서 매핑** PRD 11.4(보험 연계 상세)·수익원 09~11 후행 원칙.

### 8-1. REQ-06 SOS — 화면 안 버튼 제거 (2026-08-12 시트)

7월 회의는 "상시 노출 + 2초 길게 누르기"였으나, 8/12 시트가 **화면 안 SOS 버튼을 빼기로**
했습니다. 이유는 어르신 화면에 SOS와 즉시방문요청이 나란히 있으면 급할 때 둘 중
무엇을 눌러야 할지 고르게 된다는 것입니다. 현재:

- 진입점 = 바탕화면 바로가기 하나 (`/elder?sos=1`). 첫 안심방문 때 컨시어지가 만들어 드립니다.
- 오작동 방지 = **5초 취소 유예는 그대로 유지**. 2초 길게 누르기는 바로가기 방식에서
  성립하지 않아 빠졌습니다.

7월 회의 참석자에게 전달이 필요한 변경입니다 — "항상 보이는 위치"라는 결정이
뒤집힌 것이므로, 다음 회의에서 재확인 대상입니다.

### 8-2. REQ-12 촬영 공간 — 욕실 허용 (2026-08-12 실무진)

7월엔 욕실이 촬영 불가였으나, 낙상 위험이 가장 높은 곳이라 안전진단과 안전바 설치
확인에 사진이 필요하다는 실무 요청으로 **"사람이 없을 때 · 안전 점검 목적"에 한해
허용**으로 바꿨습니다. 화장실 사용 중·탈의공간·침실은 그대로 금지입니다.
약관의 "촬영되지 않는 공간" 조항(§REQ-12 동의 항목)도 같이 고쳐야 합니다.

### 8-3. 이 문서보다 뒤에 결정된 것

없으므로 다음 개정 때 정식 편입이 필요합니다.

- **자택 / 요양병원 이원화** (`care_location_type`) — 대상이 자택 거주로만 한정되지 않음

### 8-4. §7 미결 15건 — 현재도 미결

가입비 택일, 2급지 요율, 영상 보관 기간, 케어박스 조달 구조 등 §7의 15건은 이 문서
