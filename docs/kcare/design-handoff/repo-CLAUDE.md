# K-CARE — 프로젝트 상시 브리프

이 파일은 K-CARE 코드베이스의 모든 Claude Code 세션에서 자동으로 읽힙니다.
**아래 규칙은 코드 리뷰로 잡히지 않습니다. 문서로 상주해야 합니다.**

전체 설계 문서는 `docs/design_handoff_kcare/`에 있습니다.
새 화면·기능에 착수하기 전 `01-domain-rules.md`를 읽으십시오.

---

## 무엇을 만들고 있는가

고령자 케어 플랫폼. **자녀(보호자)가 결제하고 부모(어르신)가 서비스를 받는** 구조에서
출발해, 그 신뢰 관계를 축으로 22종 수익원을 붙여 나가는 사업.

**핵심 자산은 UI가 아니라 역할 간 정보 비대칭 설계입니다.**
같은 사건이 5개 역할 화면에서 각각 다른 정보량·다른 톤으로 보입니다.

| 역할 | 성격 |
|---|---|
| 가족 (보호자) | 결제자. 안심이 상품. 모바일 우선 |
| 사용자 (어르신) | 실사용자. 큰 활자·저인지부하 |
| 컨시어지 (동행자) | 현장 실행자. 오프라인 대응 필수 |
| 배치관리자 | 관제·배차. 밀도 높은 정보 |
| 관리자 (경영) | 수익·리스크 총괄. 개별 사건 안 봄 |

## 절대 원칙

1. **신뢰 우선 · 필요 기반 제안** — 업셀링이 케어 품질보다 앞서는 화면은 만들지 않습니다.
   **컨시어지 평가 지표·데이터 모델에 판매액을 넣지 않습니다.**
   제안은 항상 관측된 근거(`trigger`)를 동반합니다.
2. **가족 멤버십이 해자** — 가족 구성원 간 이해충돌을 만드는 기능은 수익성과 무관하게
   범위 외입니다. 형제 분담을 순위로 비교하는 UI 금지.
3. **자본집약 사업은 소유하지 않습니다** — 렌탈 자산·시설은 연계·중개로만.
   자산 재고 관리 기능을 만들지 마십시오.
4. **급여 재원과 자비 결제는 별도 원장.** 하나의 결제 테이블에 섞지 마십시오.
5. **데이터 방화벽 4원칙** — 테넌트 ID를 모든 질의의 필수 조건으로 강제 ·
   교차 조회 경로를 만들지 않음(권한이 아니라 구조로) · 고객사 데이터를 CRM에 합치지 않음 ·
   가명처리 k≥50.

## 절대 금지 (규제 근거)

### 상속·자산 자문 — 변호사법 제109조
7년 이하 징역 또는 5천만원 이하 벌금.
- 상속 상담·자산 자문 금지. **유료 전문가 알선도 금지** (소개료·성공보수·구독 배분 전부)
- 허용: **사후 행정 대행만** (사망신고·명의변경·서류) ₩250,000/건. 상조 수익의 연장
- 제휴 법무사·세무사는 **무보수 연결만.** 수익 배분 경로 자체를 만들지 마십시오

### 병원 소개 대가 — 의료법 제27조 제3항 (CRITICAL)
- 건별·성사 연동 수수료 금지 → 월정액 광고·행정 지원 용역료
- **어르신에게 병원 선택지를 2곳 이상 제시하고 선택 근거를 기록.**
  단일 병원만 추천하는 UI 금지

### 무면허 의료행위 — 의료법 제27조
컨시어지 직무는 **이동·소통·기록**으로 한정.
- 컨시어지가 혈압·혈당을 **입력**하는 기능 금지. 기기 연동 또는 본인 입력만

### 리포트 기재 — 의료법 제17조
관찰 사실과 의료진 발언 인용만. `diagnosis` `opinion` `prescription_interpretation`
필드를 스키마에 만들지 마십시오. AI 초안 프롬프트에서도 차단.

### 자격 미취득 사업
GA 등록(보험) · 장기요양기관 지정(재가급여) · 제공기관 인증(가사) ·
사전 승낙(통신 상품) · ISMS-P(기관 공급) 등.
**자격 미취득 사업의 결제·계약 기능은 기능 플래그로 잠그십시오.**

## 화면별 정보 비대칭 규칙

### 어르신에게 보여주지 않는 것
- **자신이 낙상 의심·이상 징후 대상이라는 사실.** 감시받는 느낌은 수용성을 파괴합니다
- 어르신 화면의 데이터는 전부 어르신에게 **유용한 것**이며,
  어르신을 **평가하는** 데이터는 없습니다

### 가족에게 보여주지 않는 것
- 경과 시간·목표 SLA·오탐률. 불안과 CS를 만듭니다
- 가족은 **이미 대응 중**이라는 사실만 봅니다. 행동은 확인 1개

### 관리자에게 보여주지 않는 것
- 개별 사건. 실시간 사건 티커를 경영 화면에 넣지 마십시오
- 급여 사업(수익원 12)을 단독 마진으로 평가하는 뷰 금지 —
  13.4% 마진은 의도된 것이고 KPI는 12개월 누적 기여입니다

### 반드시 함께 렌더할 문구 (제품 약속)
- 가족 알림: **"AI는 감지·제안만 하고 조치는 사람이 결정합니다 ·
  오탐 신고는 모델 재학습에 반영됩니다"**
- 관제 AI 배차: **"승인 없이는 실행되지 않습니다"** + "승인 이력은 감사 로그에 기록됩니다"
- 가족 요약: **"숫자를 읽고 판단하는 일은 저희가 합니다. 한 줄이 초록이면
  연락하지 않으셔도 됩니다."**
- 어르신 방문자: **"두 분 다 목에 K-CARE 이름표를 걸고 옵니다. 이름이 다르면
  문을 열지 마시고 노란 버튼을 누르세요."**

## 구현 제약

### 알림 · 규칙 엔진
- 원시 계측값이 직접 알림이 되지 않습니다. 규칙 엔진을 반드시 경유
- **낙상 단독 충격(3G)은 알림 미발송, 로그만.** 오탐률 38.9%
- 낙상 복합(충격 + 모션 정지 + 자동 통화 실패, 3개 모두)만 즉시 알림. 오탐률 8.3%
- 오탐률 30% 초과 규칙은 `log_only`로 강제

### 배차
- **단독 배차 없음.** 2인 1조가 스키마 제약입니다 (lead + assist 모두 필수)
- 어르신 성별과 동일한 성별 최소 1명 강제
- 같은 페어 4회 연속 배정 금지 (담합·유착 방지)
- 수습은 assist로만. 주 동행 승격은 부 동행 12건 이후
- AI 배정안은 **항상 사람 승인**을 거칩니다. 자동 실행 경로 금지.
  근거(`fitReason`) 없는 배정안은 렌더하지 않습니다

### 컨시어지 앱 — 오프라인 우선
병원 지하·엘리베이터에서 네트워크가 끊깁니다.
- 오늘 일정·대상자·체크리스트는 로컬 선캐시. 네트워크 없이 열려야 합니다
- 체크인·기록·사진은 로컬 큐 → 복구 시 동기화. 전송 실패로 데이터를 잃지 마십시오
- 큐 잔여 항목 수를 UI에 표시
- **`POST /concierge/*`는 전부 멱등키 필수** (큐 재전송 중복 방지)

### 외부 연동
**모든 연동에 대체 경로를 구현하십시오.** 연동 실패로 서비스가 멈추면 안 됩니다.
워치 SDK → 수기 입력·안부콜 / 병원 예약 API → 전화 대행 /
IAQ → 실외 기상값 표기 / 기상청 특보 → 케이웨더 + 재난문자.

## 접근성

- **히트 타겟 44px 하한** — 전 화면 공통
- **어르신 화면 최소 본문 18px** (대부분 19~20px). 버튼 패딩 28px, 라벨 21~22px
- 색만으로 상태를 전달하지 않습니다. 항상 텍스트 라벨 동반
- 어르신 화면에 링크를 쓰지 마십시오 — 버튼으로
- `prefers-reduced-motion: reduce`에서 무한 애니메이션 정지
