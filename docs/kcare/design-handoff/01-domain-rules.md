# 01 · 도메인 규칙 · 규제 경계

**구현 전에 이 문서를 읽으십시오.** 여기 적힌 것들은 UI 결정이 아니라 사업 존립 조건입니다.
아래 원칙을 위반하는 기능은 기술적으로 잘 만들어져도 폐기 대상입니다.

---

## 1. 절대 원칙 (Non-negotiable)

### 1.1 신뢰 우선 · 필요 기반 제안
업셀링이 케어 품질보다 앞서는 화면은 만들지 않습니다.

**구현 규칙**
- 컨시어지 평가 지표에 **판매액을 넣지 않습니다.** 성과 API·대시보드·랭킹에서
  매출 관련 필드를 컨시어지 개인에 귀속시키지 마십시오
- 상품 제안은 관측된 필요에서 파생돼야 합니다. 제안 객체는 항상
  근거(`trigger`)를 함께 들고 다닙니다 — 근거 없는 제안 카드는 렌더하지 않습니다
- 예: 미끄럼 방지 매트는 "낙상 위험 리포트 연계"라는 trigger가 있을 때만 노출

### 1.2 가족 멤버십이 모든 것의 해자
가족이 분열되면 22종 수익원 전부가 죽습니다.

**구현 규칙**
- **가족 구성원 간 이해충돌을 만드는 기능은 수익성과 무관하게 범위 외입니다**
- 형제 간 분담금·기여도를 경쟁적으로 비교하는 UI를 만들지 마십시오.
  현재 설계는 분담 현황을 **사실로만** 보여주고 순위를 매기지 않습니다
- 연락 담당은 한 명으로 고정하되 **결과는 전원에게 동시 전달**.
  정보 접근에 위계를 두지 않는 것이 원칙입니다
- 예외: 장례 사전 의향서 등 민감 문서는 열람 권한 분리 (어르신 본인 의사 우선)

### 1.3 자본집약 사업은 소유하지 않습니다
렌탈 자산·시설은 연계·중개로만 취급합니다.

**구현 규칙**
- 렌탈은 1단계 대리점형 — 자체 자산 재고 관리 기능을 만들지 마십시오
- 시설·레지던스는 서비스 공급 계약. 시설 운영 시스템이 아닙니다
- 데이터 모델에서 자산 소유권 필드는 항상 파트너사를 가리킵니다

### 1.4 급여 재원과 자비 결제는 장부를 분리합니다
- 국민건강보험공단 급여 청구와 고객 자비 결제는 **별도 원장**입니다
- 하나의 결제 트랜잭션 테이블에 섞지 마십시오. 부당청구 감사 시 추적 불가가 됩니다
- 본인부담금(급여의 10~15%)은 자비 결제 원장에 기록되지만 급여 건과 연결키를 유지합니다

### 1.5 데이터 방화벽 · 멀티테넌시 격리
4원칙 (`life` `tech` 화면에 구현):
1. **기관별 논리 분리 · 키 분리** — 테넌트 ID를 모든 질의의 필수 조건으로 강제,
   암호화 키를 기관별로 분리
2. **교차 조회 원천 차단** — 기관 A 계정이 기관 B 세대를 조회할 **경로 자체를 만들지 않습니다.**
   권한 체크가 아니라 구조로 막습니다
3. **고객사 데이터는 K-CARE CRM에 합치지 않습니다** — 진화형 케어 프로필 학습 대상에서 제외
4. **가명처리 · k-익명성 k≥50** — 데이터 라이선싱 시 최소 집단 크기 검증

## 2. 명시적 범위 외 (규제 근거 있음)

이 항목들은 "아직 안 만든 것"이 아니라 **만들면 안 되는 것**입니다.
제품 요구가 들어와도 거부하고 이 문서를 근거로 제시하십시오.

### 2.1 상속 · 자산 자문 — 금지
**근거: 변호사법 제109조 (비변호사의 법률사무 취급·중개 금지)**
위반 시 7년 이하 징역 또는 5천만원 이하 벌금. 리스크 등록부 H13.

- 상속 상담·자산 배분 자문 **금지**
- **유료 전문가 알선도 포함해 금지** — 소개료·성공보수·구독 배분 전부

**허용되는 것은 1층뿐:**

| 층 | 내용 | 상태 |
|---|---|---|
| 1층 | 사후 행정 대행 — 사망신고·안심상속 원스톱 신청 동행·명의변경 서류 준비 | **허용.** ₩250,000/건 |
| 2층 | 제휴 법무사·세무사 연결 | **무보수 연결만.** 수익 배분 절대 금지 |
| 3층 | 상속·자산 자문 직접 제공 | **금지** |

1층은 상조 수익(수익원 11)의 연장으로 포지셔닝합니다. 별도 사업부가 아닙니다.
상조 상품 정의도 **유료 알선을 제외하도록 개정**되었습니다.

### 2.2 병원 소개 대가 — 구조 전환 필요
**근거: 의료법 제27조 제3항 (환자 유인·알선 금지)** · 리스크 등록부 **C4 (CRITICAL)**

수익원 05(병원연계 수수료)의 현재 구조는 소개 대가로 해석될 위험이 있습니다.
형사처벌 대상이며 수익원 중단 리스크입니다.

**구현 시 강제할 것 (3가지):**
1. 건별·성사 연동 수수료 폐지 → **월정액 광고·행정 지원 용역료**로 전환.
   데이터 모델에서 수수료를 건별 이벤트에 연결하지 마십시오
2. 계약 목적에서 "환자 소개" 삭제 → 예약 행정·기록 연동·홍보 대행으로 특정
3. **어르신에게 병원 선택지를 2곳 이상 제시하고 선택 근거를 기록** —
   유도 정황 차단. UI에서 단일 병원만 추천하는 화면을 만들지 마십시오

### 2.3 무면허 의료행위 — 컨시어지 직무 경계
**근거: 의료법 제27조**

컨시어지 직무는 **이동·소통·기록**으로 한정됩니다.
복약 보조·혈압 측정·상처 처치는 직무 범위 외입니다.

- 앱에서 컨시어지가 혈압·혈당 수치를 **입력**하는 기능을 만들지 마십시오.
  기기 연동으로 자동 수집하거나 어르신 본인이 입력합니다
- "약 좀 먹여달라"는 요청 거절이 컨시어지 개인 판단에 맡겨지지 않도록,
  2인 1조 배차가 상호 감시 장치로 설계돼 있습니다 (`roster` 화면)

### 2.4 리포트 기재 제한
**근거: 의료법 제17조 (진단서 작성·교부)**

동행 리포트·AI 케어 리포트에는 **관찰 사실과 의료진 발언 인용만** 기재합니다.
소견·진단·처방 해석을 생성하지 마십시오.

- AI 리포트 초안 생성 시 프롬프트 레벨에서 이것을 강제하십시오
- 증빙 보고서 양식은 `reference/K-CARE 증빙 보고서.dc.html` 참조

### 급여 사업의 논리 (구현자가 오해하기 쉬운 지점)
재가급여(12)의 매출총이익률은 **13.4%**입니다. 단독 손익으로는 매력이 없습니다.
이것은 **국가 재원으로 고객을 확보하는 채널**로 설계된 것입니다 —
급여로 진입한 가구가 자비 결제 상품으로 확장됩니다.
따라서 급여 사업의 KPI는 마진이 아니라 **12개월 누적 기여**입니다.
대시보드에서 급여를 단독 마진으로 평가하는 뷰를 만들면 잘못된 의사결정을 유발합니다.

## 4. 리스크 등록부 요약

**CRITICAL 4 · HIGH 13.** 전체는 `risk` 화면 참조.

구현에 직접 영향을 주는 것:

| ID | 리스크 | 구현 대응 |
|---|---|---|
| C4 | 국내 환자 유인·알선 (의료법 27조 3항) | 수익원 05를 건별 연동에서 분리 |
| H4 | 보험 무자격 모집 | GA 등록 전까지 모집 기능 잠금 |
| H8 | 급여 청구 오류·부당청구 환수 | 자격·한도·수급기간 **사전** 검증 |
| H11 | 가정 내 성희롱·폭언·금품 의혹 (양방향) | 2인 1조 배차 강제 · 페어 순환 |
| H12 | 심리 모니터링 중 무자격 상담 개입 | 행위 범위 코드 레벨 제한 |
| H13 | 상속·법률사무 유상 알선 | 수익 배분 경로 자체를 만들지 않음 |

### H11 관련 배차 규칙 (알고리즘 요건)
- 동성 페어 우선 배정. **어르신 성별과 동일한 성별이 최소 1명 포함되도록 강제**
- 같은 페어가 4회 연속 배정되지 않도록 순환 — 담합·유착 방지
- 수습은 반드시 부 동행으로만 시작. 주 동행 승격은 부 동행 12건 이후

## 5. 미해결 결정 사항

구현 착수 전 사업 담당자에게 확인받아야 합니다.

1. **지자체·경찰 재난 소스** — 수동 운영으로 시작할지, API 확보를 선행할지. 미결정
2. **거주지 적합도 5축**에 실제 주민등록·컨시어지 밀도·심평원 데이터를
   Phase 1에 연결할지. 미결정 (현재 목 데이터)
3. **가사서비스** — 제공기관 인증 취득 vs 제휴. 미결정
4. `prd.txt`가 아직 v2.0 (8종 수익원 기준) — 22종 정본과 불일치.
   **PRD를 참조할 때는 `uploads/KCARE_PRD_v3.2.docx`를 쓰십시오**
