## 0. 이 화면의 존재 이유 (먼저 읽으십시오)

가족 앱은 **결제자를 안심시키는** 화면이고, 이 화면은 **실사용자가 오늘을 살아내는** 화면입니다.
두 화면은 같은 데이터를 쓰지만 **목적이 반대**입니다.

| | 가족 앱 (`family`) | 어르신 앱 (`elder`) |
|---|---|---|
| 사용자 | 자녀 (결제자) | 어르신 (수혜자) |
| 목적 | 안심 · 통제감 · 지불 근거 | 오늘 할 일 · 즉시 도움 |
| 정보량 | 추세·통계·비용·이력 전부 | **지금 필요한 것만** |
| 숫자 | 준수율 90%, 수면 6.4h, ₩320,000 | 숫자 거의 없음. "완료 / 남음" |
| 톤 | 리포트 | 말 걸기 |
| 위험 표현 | "실내 31° 주의 — 조치 권고" | "집 안이 너무 덥습니다" |

### 절대 금지 (설계 무효화 조건)
1. **가족 앱 컴포넌트 재사용 금지.** 통계 카드·추세 그래프·금액을 이 화면에 넣지 마십시오.
2. **비용·결제·구독 정보 노출 금지.** 어르신은 자신이 상품임을 체감해선 안 됩니다.
   "아들이 월 32만원을 냅니다" 같은 표현은 제품 실패입니다.
3. **감시 표현 금지.** "센서가 감지했습니다"가 아니라 "집 안이 너무 덥습니다".
   주체는 시스템이 아니라 어르신의 상황입니다.
4. **부정 피드백 금지.** 복약 미완료는 빨강이 아니라 **호박색(주의)** 입니다.
   "안 드셨습니다"가 아니라 "저녁 약 남음". 어르신을 질책하는 UI를 만들지 마십시오.
5. **스크롤 없이 SOS에 닿아야 합니다.** SOS·전화는 스크롤 영역 **밖**에 고정.

### 탭 전환 방식 — 중요한 구현 디테일
프로토타입은 카드를 **언마운트하지 않고** `display: block|none`으로 전환합니다
(`eToday` / `eHealth` / `eFamily` 값이 그대로 `display`에 들어감).
카드 순서는 **CSS `order`** 로 지정돼 있어, 탭이 바뀌어도 각 카드의 상대 순서가 유지됩니다.

| order | 카드 | 소속 탭 |
|---|---|---|
| 0 | 오늘 찾아뵙는 분 | `today` |
| 1 | 오늘 일정 | `today` |
| 2 | 오늘 약 | `health` |
| 3 | 지금 집 안 | `health` |
| 4 | 오늘 여쭤볼 것 | `today` |
| 4 | 병원 가는 길 | `today` |
| 5 | 지금 우리 동네 | `today` |
| 6 | 아들 민수 (음성) | `family` |
| 7 | 토요일 배송 | `family` |
| 8 | 자녀들이 보고 있습니다 | `family` |

**`today` 탭 실제 표시 순서:** 오늘 찾아뵙는 분 → 오늘 일정 → 오늘 여쭤볼 것 →
병원 가는 길 → 지금 우리 동네.
(order 4가 두 개라 소스 순서로 갈립니다 — 의도된 동작입니다.)

**정렬 원칙:** 긴급·시간 임박 순. 방문자 확인(안전) → 일정 → 준비 → 환경.
`health` 탭은 복약 → 실내 환경. 실제 구현에서 카드를 추가할 때 이 우선순위를 지키십시오.

- 리드: `잊으셔도 됩니다.\n선생님이 대신 여쭤봅니다.`
- 리스트 (`askDoctor`) — 번호는 Montserrat 19px/700 `#B08D57` (`flex: 0 0 22px`),
  질문 `20px/500/lh1.5`, 출처 `18px/500/#5C5A54` (marginTop 5px)

|---|---|---|
| 1 | 어지러운 게 약 때문인지 여쭤보기 | 어르신이 말씀하신 것 |

## 4. 고정 액션 (스크롤 영역 밖)

### 4.1 SOS 버튼 — 이 앱의 존재 이유

```
width: 100%
padding: 30px 20px
borderRadius: 16px
background: #C0392B
backgroundImage: linear-gradient(180deg, rgba(255,255,255,.2), rgba(255,255,255,0) 55%)
color: #FFFFFF
fontSize: 32px            ← 화면 내 최대 활자
fontWeight: 900
letterSpacing: .02em
boxShadow: inset 0 1px 0 rgba(255,255,255,.4),
           inset 0 -4px 0 rgba(96,20,14,.45),
           0 12px 24px -10px rgba(192,57,43,.55)
animation: sosPulse 2.4s infinite
:active → transform: translateY(2px); boxShadow: inset 0 2px 7px rgba(96,20,14,.5)
라벨: SOS 도움 요청
```

**동작 (`triggerSos`)** — 프로토타입은 **역할까지 `family`로 전환**해 파급을 즉시 보여줍니다:

```js
this.setState({ role: 'family', sos: true, sosDispatched: false });
this.push('SOS', '김순자(78) SOS 발신 · 가족·관제 동시 점등', '#FF8A80');
```

실제 구현에서 역할 전환은 없습니다. 대신 아래가 **동시에** 일어납니다:

| 대상 | 반영 |
|---|---|
| 가족 앱 | 상단 SOS 배너 점등 (`sosPulse`) |
| 관제 (`dispatch`) | 긴급 티커 + 좌측 이벤트 스트림 |
| 컨시어지 | 급파 지시 대기 상태 |
| KPI | **응답 목표 60초 이내** |

> 확인 다이얼로그를 넣을지는 **미결정 항목**입니다. 오작동 방지 vs 긴급성.
> 권장: 다이얼로그 없이 발신하고 **10초 취소 창**을 제공. 어르신에게 "정말입니까?"를 묻지 마십시오.
> `padding:30px 20px` + 32px 활자 = 실측 높이 약 **88px** — 접근성 요건(44px)의 2배.
>
> **[구현 확정 — REQ-06]** 2026-07 실무회의에서 오작동 방지 UX가 확정됨:
> **2초 길게 누르기(진행 표시) → 5초 취소 카운트다운 → 미취소 시 자동 접수.**
> 본 문서의 "10초 취소 창" 권장안 대신 REQ-06을 따른다.

background: #FFFFFF

color: #0A1F3C

> SOS를 누르면 관제 리소스가 낭비됩니다. **"선생님"** = 컨시어지의 어르신용 호칭. 통일하십시오.

## 5. 상태 모델

```js
elderTab: 'today' | 'health' | 'family'   // 기본 'today' (undefined 허용 → 'today' 폴백)
med:      boolean   // 저녁 복약 완료. false 시작

**단방향 잠금:** `med` `cooled` `askAdded`는 1회성(`if (this.state.x) return`)입니다.

실수 정정은 컨시어지·가족을 통해 처리하십시오. 어르신에게 "취소" 부담을 주지 않습니다.

**예외:** `voice`는 재클릭 가능(듣기 → 답장). `sos`는 관제의 `ackSos`로만 해제.

- [ ] 시스템 글자 크기 확대(iOS Dynamic Type / Android font scale) 200%에서 레이아웃 유지 —

      자동 줄바꿈에 맡기지 말고 카피의 개행을 보존하십시오 (`text-wrap: pretty` 병용)

  outdoor: { tempLabel: string; feelsLabel: string;
             factors: { label: string; value: string; level: 'ok'|'caution'|'danger' }[] };

  trip: {                                           // F8 엔진 결과 (서버 계산)
    legs: { kind: 'origin'|'destination'; place: string; score: number;
            grade: '좋음'|'보통'|'주의'|'위험'; detail: string }[];
    advice: string;                                 // 문장형. 점수→행동 번역
    kit: string[];
    source: string;                                 // "100점 감점식 · 케이웨더 제공"
  } | null;

  questions: { seq: number; text: string;
               source: 'elder'|'family'|'concierge'; sourceLabel: string }[];

  voiceMessage: { fromLabel: string; whenLabel: string;
                  durationSec: number; played: boolean; transcript?: string } | null;

  delivery: { dayLabel: string; timeLabel: string;
              itemsSummary: string; itemCount: number } | null;   // 금액 필드 없음

  familySeen: { initials: string; displayName: string; seenLabel: string }[];
};
```

**설계 제약 (스키마 레벨):**
- `delivery`에 금액 필드를 **넣지 마십시오**. 타입이 방어선입니다.
- `familySeen`에 `contributionAmount`를 넣지 마십시오.
- `grade`는 서버가 확정합니다. 클라이언트가 점수→등급을 재계산하면 화면 간 불일치가 생깁니다.
- `level: 'ok'|'caution'|'danger'` → 색 매핑은 클라이언트. 서버가 hex를 내리지 마십시오.

## 9. 우측 설명 패널 (프로토타입 전용 — 구현 대상 아님)

폰 목업 옆 데스크톱 설명 패널은 **프로토타입 문서화 장치**입니다. 앱에 만들지 마십시오.

- 역할 라벨: `역할 02 / 사용자 · 어르신` (11px/700/letterSpacing .16em)
- 제목: `한 화면에 한 가지,\n오늘 할 일과 도움 요청뿐`
- 본문: 본문 19pt 이상, 터치 타깃 최소 88px, 명도 대비 7:1 이상 — **PRD 12장 접근성 요건을 상회**.
  정보는 **4블록(일정 · 동네 날씨 · 병원 가는 길 · 행동)** 으로 제한하고,
  SOS와 전화는 하단에 고정해 언제든 닿게 함.
- **F8 외출 컨디션 엔진 · 케이웨더 연계** (네이비 카드):
  - F8-1: 100점 감점식으로 기온·체감·미세먼지·자외선·강수 판정
  - F8-2: 출발지와 병원 **두 구간을 각각 산출**
  - F8-3: 판정 결과에 따라 **준비물 자동 생성**
  - F8-4: 위험 수준이면 **일정 조정 권고**
  - 같은 판정이 관제 브리핑·컨시어지 앱에 그대로 내려감
- SOS 파급 설명: 가족 앱 배너 · 관제 긴급 티커 · 좌측 이벤트 스트림 동시 반영. **KPI 60초**
