# 02 · 핵심 역할 화면 명세 (P0 + admin)

이 문서는 `family` `elder` `concierge` `dispatch` `admin` 5개 화면의 상세 명세입니다.
**P0 구현 범위는 앞의 4개**이고, `admin`은 정보 비대칭의 최상위 계층을 이해하기 위해 포함했습니다.

---

## 0. 정보 비대칭 매트릭스 — 이 제품의 핵심

**이것이 K-CARE의 설계 자산입니다.** 같은 사건이 역할마다 다른 정보량·톤·행동으로 나타납니다.

### 사건 A — SOS 발생 (김순자 78세, 강남구 대치동)

| 역할 | 보이는 것 | 톤 | 가능한 행동 |
|---|---|---|---|
| **어르신** | 큰 노란 버튼을 눌렀다는 사실만. 이후 화면은 "선생님이 오고 있습니다" | 안심시킴 | 없음 (수신 대기) |
| **가족** | "어머니가 도움을 요청했습니다" + "박지현·서다인 2인 급파 중 (1.2km) · 관제센터 확인" | 사실 + 이미 조치 중임을 먼저 | `확인했습니다` 1개 버튼만 |
| **컨시어지** | 배차 지시 · 대상자 위치 · 주의사항 · 도착 목표 | 실행 지시 | 수락 · 이동 · 현장 기록 |
| **배치관리자** | "김순자 (78) · 강남구 대치동 — 최근접 컨시어지 박지현 (1.2km)" + **"경과 00:14 · 목표 응답 60초 이내 · 119 연계 대기"** | 계측 | `급파 지시` · `해제` |
| **관리자** | 개별 사건 없음. SLA 집계만 — "SOS 초동 응답 목표 60초 / 현재 41초 / 오늘 2건 · 최장 52초" | 통계 | 없음 (기준 조정) |

**구현 규칙**
- 가족에게 경과 시간(00:14)과 목표 SLA를 노출하지 마십시오. 불안을 유발하고
  "왜 아직 안 갔냐"는 CS를 만듭니다. 가족은 **이미 대응 중**이라는 사실만 봅니다
- 가족 화면의 행동은 `확인했습니다` 단 하나입니다. 가족이 조치를 선택하게 하지 마십시오
- 관리자는 개별 사건을 보지 않습니다. 경영 화면에 실시간 사건 티커를 넣지 마십시오

### 사건 B — AI 낙상 의심 감지 (새벽 03:12)

| 역할 | 보이는 것 | 행동 |
|---|---|---|
| **어르신** | **아무것도 보이지 않습니다.** | — |
| **가족** | "새벽 3시 12분, 거실에서 5초간 급격한 움직임 후 정지" + 3개 신호 타임라인 + "어르신은 아직 SOS를 누르지 않았습니다" | `지금 확인 요청` · `괜찮습니다` |
| **배치관리자 / 디바이스** | 규칙 판정 — "낙상 복합 3조건 충족 (충격 3G + 모션 정지 + 자동 통화 실패)". 단독 충격은 **알림 미발송, 로그만** | 긴급 출동 지시 |
| **관리자** | 규칙별 오탐률 — 복합 8.3% / 단독 38.9%. "오탐률 30% 초과 단독 규칙은 발송 금지" | 규칙 임계값 조정 |

**구현 규칙 — 가장 중요**
- **어르신에게 자신이 낙상 의심 대상이라는 사실을 보여주지 마십시오.** 감시받는다는
  느낌은 이 제품의 수용성을 파괴합니다. 어르신 화면의 데이터는 전부 **어르신에게 유용한 것**
  (오늘 일정·약·실내 온도·방문자 얼굴)이며 어르신을 **평가하는** 데이터는 없습니다
- 가족 화면에 반드시 함께 렌더할 문구:
  **"AI는 감지·제안만 하고 조치는 사람이 결정합니다 · 오탐 신고는 모델 재학습에 반영됩니다"**
  이것은 장식이 아니라 제품 약속입니다
- 단독 충격 감지는 **알림을 만들지 않습니다.** 오탐률 38.9%로 신뢰를 깎습니다.
  알림 생성 로직을 규칙 엔진 레벨에서 분리하십시오

### 사건 C — 폭염 · 실내 고온

| 역할 | 보이는 것 |
|---|---|
| **어르신** | "지금 집 안 33°" + 큰 버튼 `에어컨 켜고 가족에게 알리기` — 행동 하나로 끝 |
| **가족** | 실내 온도 + 어르신이 조치했는지 여부. 조치 완료 시 초록 상태 |
| **컨시어지** | 방문 시 준비물에 보냉백 자동 반영 |
| **배치관리자** | 위험 관찰 목록 — "김순자(78) · 실내 31° + 폭염 특보 + 심부전 이력 → 냉방 확인 콜 + 동행 시 보냉백 지참 · 위험도 높음" |

어르신 화면의 버튼은 **1개 행동 = 2개 결과**입니다 (에어컨 제어 + 가족 통보).
어르신에게 두 번 누르게 하지 마십시오.

## 1. `family` — 가족 (보호자) · 역할 01

### 목적
**결제자의 화면. 상품은 "안심"입니다.**
해외·타지에 사는 자녀가 부모의 상태를 확인하고, 필요한 조치를 승인하고, 형제와 조율합니다.

### 레이아웃
데스크톱에서 폰 목업(392×812) + 우측 보조 패널. 실제 구현은 모바일 앱/반응형 웹.

- 루트: `display:flex; flexWrap:wrap; gap:34px; padding:clamp(20px,4vw,36px) clamp(16px,4vw,40px)`
- 폰 내부: `flexDirection:column`, 상단 고정 헤더 + `flex:1; overflowY:auto` 스크롤 영역
- 스크롤 영역: `padding:4px 22px 26px; display:flex; flexDirection:column; gap:14px`

### 탭 (`famTab`)
`home` (기본) · `book` · 그 외. 탭 전환은 카드의 `display` 속성으로 제어되며
`order` 값으로 순서가 정해집니다. **실제 구현에서는 라우팅 또는 조건부 렌더로 바꾸십시오** —
`display:none` + `order`는 프로토타입 편의 장치입니다.

## 2. `elder` — 사용자 (어르신) · 역할 02

### 목적
**실사용자의 화면. 저인지부하 · 큰 활자 · 행동 1개.**

### 접근성 요건 — 타협 불가
| 항목 | 값 |
|---|---|
| 최소 본문 | **18px** (대부분 19~20px) |
| 제목 | 30px / `fontWeight:900` |
| 큰 숫자 (온도 등) | 44px Montserrat/700 |
| 버튼 라벨 | 21~22px / 700 |
| 버튼 패딩 | **28px** (일반 화면의 2배) |
| 아바타 | 44~56px |
| 카드 반경 | 20px |
| 배경 | `#FDFCF9` (가족 화면보다 밝음 — 대비 확보) |

- 버튼 `:active`에서 `transform:translateY(2px)` + inset shadow 반전 —
  **누른 느낌이 물리적으로 분명해야 합니다**
- 버튼 텍스트가 2줄이면 `<span style="display:block; lineHeight:1.35">`로 명시적 줄바꿈.
  자동 줄바꿈에 맡기지 마십시오
- 색만으로 상태를 전달하지 마십시오. 항상 텍스트 라벨 동반

### 탭 (`elderTab`)
`today` (기본) · `health` · `family`. 카드마다 `display` 제어.

## 3. `concierge` — 컨시어지 (동행자) · 역할 03

### 목적
**현장 실행자의 화면. 오프라인 대응이 필수 요건입니다.**
병원 지하·엘리베이터에서 네트워크가 끊깁니다.

### 오프라인 우선 — 구현 요건
`isOffline` 상태에 대응하는 배너가 최상단에 렌더됩니다
(`border rgba(138,93,18,.32)`, `background linear-gradient(180deg,#FFF7E8,#FBEFD8)`,
`borderRadius:14px`, `padding:14px 15px`).

**실제 구현에서 반드시 지킬 것:**
- 오늘 일정·대상자 정보·체크리스트는 **로컬에 선캐시**. 네트워크 없이 열려야 합니다
- 체크인·기록·사진은 **로컬 큐에 쓰고 복구 시 동기화**. 전송 실패로 데이터를 잃지 마십시오
- 큐에 남은 항목 수를 UI에 표시하십시오 (컨시어지가 "보냈는지" 알아야 합니다)
- GPS 체크인은 오프라인에서도 좌표+시각을 기록하고 나중에 검증

### 레이아웃
폰 목업 안. 상단 고정 헤더 + `flex:1; overflowY:auto`,
`padding:16px 20px 24px; display:flex; flexDirection:column; gap:12px`

### 주요 블록
1. 오프라인 배너 (조건부)
2. 오늘 동행 대상자 카드 — 이름·연령·목적지·시각·주의사항
3. 준비물 체크리스트 — 외출 컨디션에서 **자동 반영된 항목** 포함 (KF94·양산·보냉백)
4. GPS 체크인 버튼
5. 동행 기록 입력 — **관찰 사실만.** 소견·진단 입력 필드를 만들지 마십시오 (의료법 17조)
6. 리포트 발송

### 절대 금지
