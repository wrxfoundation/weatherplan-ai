# Handoff: K-CARE 고령자 케어 플랫폼

## Overview

K-CARE는 고령자 케어 플랫폼입니다. **자녀(보호자)가 결제하고 부모(어르신)가 서비스를 받는**
구조에서 출발해, 그 신뢰 관계를 축으로 22종의 수익원을 붙여 나가는 사업입니다.

이 번들은 33개 화면의 HTML 프로토타입과 그것을 실제 코드베이스로 옮기기 위한 명세입니다.

**이 제품의 핵심 자산은 UI가 아니라 역할 간 정보 비대칭 설계입니다.**
같은 사건(예: 새벽 낙상 의심)이 5개 역할 화면에서 각각 다른 정보량·다른 톤·다른 행동 유도로
나타납니다. 가족에게는 "확인이 필요하다"로, 관제에는 "3조건 중 2개 충족"으로,
컨시어지에게는 "도착 시 확인할 항목"으로 보입니다.
**이 비대칭을 하나의 공통 알림 컴포넌트로 통합하면 제품이 죽습니다.**
구현 중 가장 주의할 지점입니다 — 자세한 내용은 `02-core-roles.md`의 정보 비대칭 매트릭스.

## About the Design Files

이 번들의 `reference/` 안에 있는 파일들은 **HTML로 만든 디자인 레퍼런스**입니다.
의도한 외형과 동작을 보여주는 프로토타입이며, **그대로 복사해 쓸 프로덕션 코드가 아닙니다.**

작업의 성격은 **이 HTML 디자인을 대상 코드베이스의 기존 환경에서 재현하는 것**입니다.
(React·Vue·SwiftUI·네이티브 등 — 이미 환경이 있다면 그 환경의 확립된 패턴과 라이브러리를 따르고,
없다면 이 프로젝트에 가장 적합한 프레임워크를 선택해 거기서 구현합니다.)

프로토타입은 단일 파일 인라인 스타일로 작성돼 있습니다. 이것은 프로토타이핑 도구의 제약이며
설계 의도가 아닙니다 — 실제 구현에서는 컴포넌트 분리와 디자인 토큰 시스템을 쓰십시오.
`05-design-tokens.md`에 토큰화할 값이 정리돼 있습니다.

### 프로토타입에 없는 것
- 백엔드·API·인증·DB (전부 하드코딩된 목 데이터)
- 실제 웨어러블·공단·병원 연동 (화면상 "연동 대기"로 표기된 것들)
- 다국어 (한국어만. 해외 자녀 대상 영어는 미구현)
- 접근성 속성 (aria-label 일부만. 어르신 화면은 실제 구현 시 스크린리더 검증 필수)

## Interactions & Behavior (공통)

### 애니메이션
프로토타입에 정의된 keyframe은 4개입니다. 전부 상태 표시용이며 장식이 아닙니다.

| 이름 | 용도 | 스펙 |
|---|---|---|
| `sosPulse` | SOS 배너 | 1.8s infinite. 배경 밝기 미세 변동 |
| `livePing` | 실시간 수신 중 점 | 1.6s ease-in-out infinite. opacity + scale |
| `escalateGlow` | 즉시 조치 필요 버튼 | 2.2s ease-in-out infinite. box-shadow 확산 |
| 전환 | 아코디언 화살표 | `transform .18s ease` |

`prefers-reduced-motion: reduce`에서 위 3개 무한 애니메이션을 정지시키십시오
(프로토타입에 미구현 — 구현 시 추가 필요).

### 버튼 press 상태
모든 주요 버튼은 `:active`에서 `transform: translateY(1px)`.
어두운 버튼은 추가로 inset shadow가 눌린 느낌으로 반전됩니다.
터치 디바이스에서 hover 상태가 sticky하지 않도록 `@media (hover: hover)`로 감싸십시오.

### 반응형
- 브레이크포인트: `vw < 1024` → 모바일. 프로토타입은 `window.innerWidth`를 state로 추적
- 모바일에서 사이드 내비게이션은 오버레이 드로어로 전환 (`navOpen` state)
- 모바일 상단 고정 헤더 56px, 콘텐츠에 그만큼 `paddingTop`
- **히트 타겟 44px 하한** — 어르신 화면은 이것이 타협 불가 요건입니다
- 데스크톱 패딩은 `clamp(16px, 4vw, 40px)` 패턴

### 폰 목업
`family` `elder` `concierge` `global` `onboard` `payout` 화면은 데스크톱에서
폰 목업 안에 렌더링됩니다 (max-width 392px, height 812px, borderRadius 36px,
외곽 베젤 44px). **이것은 프로토타입 표현 장치입니다** — 실제 구현에서
가족·어르신·컨시어지 앱은 별도 모바일 앱이거나 반응형 웹입니다. 베젤을 만들지 마십시오.

### 프로토타입 읽는 방법
9,486줄이라 통째로 읽으면 안 됩니다. 화면별로 `<sc-if value="{{ isXxx }}">` 블록으로
구분돼 있으니 grep으로 해당 블록만 보십시오.

```
grep -n 'sc-if value="{{ is' 'reference/K-CARE 5역할 프로토타입.dc.html'
```

템플릿 문법 요약 — 읽는 데 필요한 만큼만:
- `{{ name }}` = 값 삽입. 로직 클래스의 `renderVals()`가 반환한 이름
- `<sc-if value="{{ x }}">` = 조건부 렌더
- `<sc-for list="{{ xs }}" as="x">` = 반복. `$index` 사용 가능
- 로직은 파일 하단 `class Component extends DCLogic`의 `renderVals()`에 전부 있음
- `style-hover` `style-active` = 의사 상태 스타일
