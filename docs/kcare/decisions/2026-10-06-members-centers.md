# 회원가입 · 영역별 입구 · 관제 1/2/3센터 분리 (2026-10-06)

요청: "신규 회원가입 · 신규 컨시어지나 관리자 회원가입 기능 추가. 컨시어지 · 어르신 · 보호자 · 영업자 · 관제 관리자
권한을 부여할 수 있어야. 어르신 보호자는 유저뷰, 컨시어지 · 영업자는 세일즈뷰, 관제관리자는 별도 영역이라 가입 진입
페이지를 달리. 관제 1 2 3 아이디를 만들어 새로운 db 1 2 3 에서 테스트 — 관제1 에는 어르신 · 보호자 · 컨시어지 · 영업자가
새로운 id, 기존 db 가 없어야."

## 구조

| 영역 | 역할 | 가입 | 로그인 | 사용 시작 |
|---|---|---|---|---|
| 이용자 (유저뷰) | 어르신 · 보호자 | `/join` | `/login` | 그 센터 관제 승인 뒤 (점검 반영 — 아래) |
| 현장 · 영업 (세일즈뷰) | 컨시어지 · 영업자 | `/partner/join` | `/partner/login` | 그 센터 관제 승인 뒤 |
| 관제 (별도 영역) | 관제 관리자 | `/ops/join` | `/ops/login` | 그 센터 관제 승인 뒤 |

- **가입 코드(센터마다 8자리 · 무작위)가 센터를 정한다.** 관제가 계정·권한 화면에서 영역별 가입 링크를 나눠 주고, 코드를 바꿀 수 있다.
- **권한은 관제가 준다** — 승인 · 거절 · 역할 바꾸기(다섯 역할 중 무엇이든) · 정지 · 다시 사용. 자기 계정 · 테스트 계정은 바꾸지 않는다.
  정지 · 역할 변경은 상대의 다음 서버 요청부터(15초 안) 막히고, 바뀐 역할의 입구로 다시 로그인한다.
- 영역이 다른 입구로 로그인하면 맞는 입구를 알려 준다. 로그인한 계정은 자기 역할 화면만 연다 (경영 콘솔은 관제만).
- 비밀번호는 scrypt 해시만 저장한다. 바꾼 것은 `account_audit` 에 남고 관제 감사로그에도 한 줄 남는다.

## 관제 1 · 2 · 3센터 — 따로 쓰는 공간

- 관제 아이디 `ops1` · `ops2` · `ops3`(센터 관리자 비밀번호 `CENTER_OPS_PASSWORD` — 테스트 계정 비밀번호와 따로). 각자 자기 센터 공간(`HH-C1` · `HH-C2` · `HH-C3`)만 본다.
- **"새로운 db 1 2 3"** — 표를 센터마다 새로 만들지 않고 같은 표 안에서 센터 번호로 나눴다. 화면 · 서버 코드가 한 벌이면 되고,
  센터끼리 섞일 길(다른 표를 잘못 읽는 일)이 없다. 대신 Supabase Table Editor 에서 센터별로 따로 보이게
  `center1_accounts` · `center1_household` · `center1_activity` · `center1_signups` · `center1_payments`(2 · 3센터도 같은 모양)
  보기를 두었다 — 읽기 전용이고 브라우저용 키로는 열리지 않는다.
- **기존 데이터 없이 시작** — 센터 공간은 빈 기록으로 시작한다 (예시 처방 · 예시 방문 담당자도 비운다).
  화면의 어르신 · 보호자 · 컨시어지 · 영업자 이름은 그 센터에 가입한 회원 이름이다 (아직 가입 전이면 '어르신' · '보호자').
  관제 명부(어르신 · 보호자 · 컨시어지 관리 · 방문관리 · 웨어러블)는 센터 회원만 보이고 예시 명부는 숨긴다.
  SOS 파견 후보 · 담당 컨시어지 선택도 그 센터 컨시어지만.
- 예전 테스트 계정(`test-…`)과 **테스트 가구 1**(김순자 · 김민수 · 박지현)은 그대로 둔다.

## 아직 정할 것 · 알아 둘 것

- **센터 하나 = 가족 한 집** (베타). 가입 코드는 '어느 센터'만 정한다 — 코드를 바꿔도 같은 센터 · 같은 가족 기록이다 (2026-10-08 현장 테스트에서 '새 코드 = 새 가족'으로 오해 → 코드 바꾸기 · 두 번째 어르신 승인 확인창과 어르신 화면에 안내를 더했다). 한 센터에 보호자 · 어르신이 여럿 가입하면 같은 기록을 함께 쓴다 — 먼저 가입한 어르신 ·
  보호자 · 컨시어지가 화면의 주인공이다. 한 센터가 여러 가구를 따로 관리하려면 가구 단위 저장(가구마다 상태)으로 옮겨야 한다.
- 예시로 표시된 화면 요소(관제 대시보드의 '예시' 숫자 · 컨시어지 앱의 긴급확인 · 오늘의 짝 등)는 센터 공간에도 '예시'로 남는다.
- 비밀번호 찾기 · 바꾸기, 가입 때 본인 확인(문자 인증)은 아직 없다 — 관제가 정지 후 새로 가입시키는 것으로 대신한다.
- 가입 코드를 알면 누구나 가입 **신청**은 된다 (승인 전에는 아무것도 못 본다) — 코드를 바꾸면 바로 막힌다.
  운영에서는 초대 링크(1회용) · 문자 인증이 필요하다.
- SOS 사건 기록(관제 SOS 센터 단계 메모 등)은 여전히 그 관제 PC 에 저장된다 (센터 공간별 칸으로 나뉜다).

## 점검 반영 (2026-10-06 "ux 및 코드 빡세게 점검")

보안 — 배포 전 점검에서 나온 것을 막았다.

- **이용자 가입도 관제 승인 뒤에 로그인** — 가입 코드만 알면 센터 기록 전체(어르신 · 요청 · SOS)를 읽고 쓸 수 있었다.
- **센터 관리자(ops1~3) 비밀번호 분리** — 테스트 계정 공용 비밀번호를 아는 사람이 회원 승인 · 정지까지 할 수 있었다.
  `CENTER_OPS_PASSWORD`(센터마다 `_C1`~`_C3` 가능) 없이는 ops1~3 이 열리지 않는다.
- **로그인 잠금** — 같은 아이디 5번 실패 → 5분(되풀이하면 최대 60분) · 서버 인스턴스별 아이디 · IP 빈도 제한.
- 가입 코드 8자리(40비트 · 암호학적 난수) · 틀린 코드 빈도 제한 · 승인 대기 30명 넘으면 새 가입 멈춤.
- 관제 역할을 주고 빼는 일 · 관제 회원 정지는 **센터 관리자만** (관제 회원이 스스로 권한을 올리지 못하게).
- 변경 요청은 같은 사이트의 JSON 만 받는다 (다른 사이트가 몰래 보내는 요청 차단) · 비밀번호 해시 강도(scrypt p=5).
- 비관제 화면에는 회원 아이디를 싣지 않는다 (이름 · 역할만).

화면 — 실제로 가입 · 승인 · 정지 · 역할 변경을 돌려 보고 고쳤다.

- 정지 · 역할 변경된 사람에게 '로그인 만료' 띠 대신 **화면 전체 안내** — 무엇이 일어났는지와 갈 곳 하나. 저장 · 확인을 멈춘다.
- `/login` 은 **가입한 아이디** 탭이 먼저 (테스트 탭에 회원 아이디를 넣으면 옮겨 준다). 로그아웃 · 계정 칩은 자기 입구로.
- 관제 확인창이 카드 안에서 그려져 화면 밖으로 열리던 것 → 화면 기준으로. 휴대폰 회원 목록은 카드로.
- 가입 코드는 8자리를 다 적으면 저절로 확인 · Enter 는 확인 · 틀린 첫 칸으로 이동 · 코드가 바뀌면 그렇게 알려 준다.
- 센터 공간에 남아 있던 예시 — 영업자 예시 실적과 공용 추천 코드(S-0012 → 회원마다 `S-아이디`), 보호자 마이의 예시 가족 ·
  영상 · 접근 기록, 관제 '지금 처리할 일'의 예시 고객 할 일, 컨시어지 머리 · SOS 배너의 예시 이름 · 거리, 복지혜택 예시 프로필.
- 같은 역할 회원이 여럿이면 각자 자기 이름으로 기록된다 (컨시어지 2명 — 도와줘요 · SOS 급파 수락 · 해주세요 승인).
  센터에 승인된 컨시어지가 없으면 '담당 컨시어지' 같은 자리 이름을 담당으로 저장하지 않고 급파 · 출동 지시를 막는다.
