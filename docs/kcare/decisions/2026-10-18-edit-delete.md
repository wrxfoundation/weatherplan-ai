# 등록한 것 고치기 · 지우기 — 역할별 규칙과 증명 잠금 (2026-10-18)

요청: "보호자가 다니던 병원 등록하기 하면 변경 · 수정 · 삭제. 각 메뉴별로 수정해야 할 사항이 있는데 해당 부분 삭제 · 수정 내지
취소가 되어야 함. 어르신 · 보호자 · 컨시어지 · 관제 각각 메뉴 역할에 맞게 수정 · 삭제가 되어야 하는데 지금 등록이나 기재는
되지만 수정 · 삭제가 안 된 경우가 있음. 다만 증명이나 처리 완료 등 증명이 필요한 성격은 수정되면 안 됨."

네 역할 화면을 전수 조사해 '등록은 되는데 고치거나 지울 길이 없는 것'을 찾고, 아래 원칙으로 채웠다.

## 원칙

1. **등록한 쪽이 고치고 지운다.** 다른 역할이 남긴 것은 보기만 한다 (보호자는 어르신이 남긴 가족 일정 · 컨시어지 진료 예약도 함께 관리).
2. **증명 · 처리 완료 기록은 고치지 않는다.** 승인 · 결제 · 완료 · 발송 · 해결 뒤의 내용은 잠그고, 바꾸려면 *취소하고 다시* 한다.
3. **지울 때는 한 번 묻는다.** 되돌릴 수 없는 '완료로 닫기'도 한 번 묻는다.
4. **고친 것 · 지운 것은 흔적을 남긴다.** 고치면 이전 글을 남기고(prev), 지운 것은 감사로그(activity 표)에 글이 남는다.
   처리 이력 줄 · 감사로그 자체는 고치거나 지우지 않는다.
5. **확정된 것을 바꾸면 다시 확인받는다.** 관제가 확정한 일정의 날짜 · 시간 · 종류 · 동행을 바꾸면 관제 재승인 대기로 돌아간다.
   관제가 바꾼 내용을 반려하면 **원래 확정 일정으로 돌아간다** (확정 일정이 바꾸려다 사라지지 않게).
6. **저장되지 않는 버튼은 두지 않는다.** 실제 가구 · 센터 회원 줄에서 눌러도 화면에만 바뀌던 버튼은 빼고 실제 바꾸는 곳을 적었다.

### 같은 요청이 두 번 가던 것 (화면 기억 → 요청 상태로)

화면이 기억하던 '보냄' 표시는 새로고침하면 사라져 같은 요청이 또 갔고, 취소해도 다시 보낼 수 없었다. 열려 있는 요청에서 읽게 바꿨다 —
제휴 병원 예약 · 상담 요청, 복지혜택 신청 도움(보호자) · 안내 부탁(어르신), 건강식품 재구매, 컨시어지 해주세요 제안(수락 대기 중인 같은 서비스).
컨시어지 '컨시어지 요청'은 보내면 글을 비워 다른 요청을 이어 쓸 수 있고, 안전용품 제안은 '다른 물품 새로 담기'로 다시 고른다.

### 어르신 '부탁해 둔 것'

진행 중인 부탁은 모두 보이고(전에는 6건에서 잘려 7번째부터는 취소할 길이 없었다), 끝난 것은 최근 3건만.

### 같은 날 리뷰에서 고친 것

- **재승인 반려 → 원래 일정으로.** 확정 일정을 바꾸면 확정 값을 `prevApproved` 에 남기고, 관제가 반려하면 그 값으로 되돌려 다시 확정한다.
  보호자 달력에는 '바꾼 내용 관제 반려 — 사유 · 원래 일정 그대로', 어르신 화면에는 지금 할 일 카드 · 홈 다음 일정 줄 · 이번 달 일정에 '원래대로',
  관제 배차 화면에는 재승인 줄에 원래 일시가 같이 보인다.
- **재승인 대기 일정은 주 보호자가 바꾼다** — 확정됐던 일정이라 부 보호자는 보기만.
- **지난 진료 예약 · 지난 재승인 대기 일정도 기록으로 잠근다** (컨시어지 화면은 '지난 예약 · 기록').
- **보낸 동행 기록은 다음 방문 기록을 시작할 때 방문 기록과 함께 보관**하고 동행 칸을 비운다 — 다음 방문 리포트에 지난 동행 글이 다시 실리지 않는다.
- **보관된 지난 방문 리포트도 보인다** — 보호자 기록 · 리포트 목록은 보낸 방문을 모두, 관제 방문 관리에는 '보관된 지난 방문'. 보호자가 지난 리포트를 열면 그 기록에 '열람 완료'가 찍힌다.
- **마감한 방문에는 리포트를 덧붙이지 않는다** (제출 · 발송 뒤 잠금과 같은 규칙).
- **방문 영상 동의**는 정보 동의에서 철회한 값을 먼저 읽는다 (`lib/consent.js`) — 철회하면 방문 영상 화면 · 컨시어지 화면이 같이 바뀐다.
- **먼저 결제한 해주세요도 승인 전이면 내용 · 희망 일시는 고친다** — 결제가 묶인 종류 · 금액은 그대로.

## 증명이라 고치지 않는 것

- 처리 이력 줄 · 감사로그 · 결제 · 환불 기록
- 관제가 확정했고 지난 일정 · 승인 · 결제 · 완료된 해주세요의 내용
- 보호자에게 발송한 안심방문 리포트 · 동행 리포트
- 해결 완료로 닫은 도와줘요 · SOS · 이행 완료한 약속
- 받는 분이 들은 음성
- 이름 · 생년월일 · 휴대전화 번호 (본인 확인 정보 — 고객센터)

## 관제 콘솔에서 뺀 '저장되지 않던 버튼'

| 화면 | 전에 | 지금 |
|---|---|---|
| 어르신 관리 › 상담·관제메모 | 센터 공간에서는 눌러도 아무것도 남지 않았고, 테스트 가구는 새로고침하면 사라졌다 | 가구 기록(`opsNotes`)에 저장 — 관제 기기끼리 같이 본다. 예시 메모를 실제 가구에 붙이지 않는다 |

| 컨시어지 관리 (센터 공간) | 정보 수정 · 계정 비활성화 · 교육 이수 등록이 화면에만 바뀌고 '이력 저장'이라고 떴다 | 버튼 대신 '계정 · 역할은 회원 · 권한에서' |
| 보호자 관리 (실제 줄) | 전화 연결 기록 · 재알림 발송 · 보고서 재발송 · 어르신 연결이 저장되지 않았다 | 버튼 대신 실제 기록이 쌓이는 곳을 안내 |

## 데이터 (households.state — SQL 변경 없음)

- `events[].by · editedAt · editedBy · reapproval · rejectReason`, `eventsRemoved[]` (지우거나 취소한 일정 · 누가 · 왜)
- `events[].prevApproved · changeRejected` (재승인 대기 중 원래 확정 값 · 반려되어 원래대로 돌아간 때와 사유)
- `visit.returned · returns[]`, `visitHistory[]` (발송한 방문 기록 보관 — 보낸 동행 기록 `escort` 도 같이)
- `requests[].editedAt · editedBy` (고친 내용은 처리 이력 한 줄)
- `opsNotes[]` (관제 메모 · `prev` 이전 글)
- `reviews[].editedAt · prev`, `escort.rating { score, reason, at, by, forSentAt, prev }`
- `guardian.consents { [동의]: { on, at, by, purge } }` — 방문 영상 동의는 가입 상담의 `videoConsent` 와 같이 바뀐다
- `opsMessages[].kind` — `membership`(해지 · 변경 상담) · `order`(주문 문의)

## 다음 단계로 남긴 것

1. **보내기 취소한 음성의 녹음 파일** — 가구 기록에서 빠져 받는 화면에서는 사라지지만, 파일은 서버(voice_clips)에 30일 보관 뒤 지워진다.
   바로 지우려면 서버 삭제 API 가 필요하다. 보내기 취소는 보호자 → 어르신 안부 음성에 먼저 붙였다 — 어르신 · 컨시어지가 보낸 음성은 다음 단계.
2. **자녀 초대 링크 회수** — 보낸 사람이 정지되면 멈추지만, 링크만 따로 거두려면 DB 에 링크 기록이 필요하다.
3. **관제 해주세요 관리의 실제 비용 · 영수증 · 평가 · 반복 요청** — 아직 그 기기에만 저장된다.
4. **동행 기록이 한 칸** — 보낸 동행 기록은 다음 방문 기록을 시작할 때 보관되고 칸이 비워진다. 그 사이에 동행이 또 있으면
   다음 방문 기록을 시작한 뒤에 적는다 (점수는 받은 리포트에 묶여 새 리포트가 오면 다시 묻는다). 동행을 여러 건 따로 쌓으려면 목록 구조가 필요하다.
5. **어르신 주소 · 연락처 변경** — 가입 상담 값이라 앱에서 바로 고치지 않는다(고객센터). 바꾸는 절차가 정해지면 붙인다.
6. **멤버십 셀프 해지** — 해지 기준(약정 · 위약금 · 환불)이 확정되면 상담 요청 대신 앱에서 바로.
7. **예시 화면**(웨어러블 · 관제기준 · 함께해요 예시 명부)은 그 화면 안에서만 바뀐다 — 실제 기기 연동 때 다시 본다.
