# 2026-11-18 내 정보 관리 — 비밀번호 바꾸기 · 임시 비밀번호 · 회원 탈퇴

계정 재점검(같은 날)에서 '정해야 할 것'으로 남긴 두 가지를 만들었다. **SQL · 환경변수 변경은 없다.**

## 만든 것

| 무엇 | 어디서 | 어떻게 |
|---|---|---|
| **내 정보 관리** | `/account` — 보호자 마이 › 멤버십, 어르신 마이, 로그인 화면의 '로그인됨' 카드(직원 포함)에서 연다 | 이름 · 아이디 · 구분 · 가입한 날 · 휴대폰(보기만) + 비밀번호 바꾸기 + 회원 탈퇴 |
| **비밀번호 바꾸기** (본인) | 내 정보 관리 | 지금 비밀번호 확인 → 새 비밀번호. 바꾸면 이 아이디로 로그인한 **모든 기기가 다시 로그인**한다 (바꾼 화면도 로그아웃 → 새 비밀번호로 로그인) |
| **비밀번호를 잊었을 때** | 로그인 화면 '비밀번호를 잊으셨나요?' → 관제 계정 · 권한 `[비밀번호]` | 관제가 전화로 본인을 확인하고 **임시 비밀번호**(10자리)를 발급해 불러 준다. 임시 비밀번호로 로그인하면 **새 비밀번호를 정해야** 앱을 쓸 수 있다 |
| **회원 탈퇴** (본인) | 내 정보 관리 | 지워지는 것 · 남는 것을 먼저 보여 주고, 비밀번호 확인 + 동의 표시 뒤 **내 계정을 바로 지운다** |

회사가 보낸 개인정보 처리방침의 "앱 내 [설정 > 내 정보 관리] 메뉴"가 이 화면이다 (이름을 맞췄다).

## 정한 것 — 이유와 함께

**비밀번호 찾기는 '관제가 임시 비밀번호 발급'으로.**
앱에 문자 · 전자우편을 보내는 수단이 없고(회사 처리방침의 문자 · 알림톡 대행사도 아직 '예'로만 적혀 있다), 가입할 때 전자우편을 받지 않으며 휴대폰은 선택 칸이라 확인된 연락처가 없다. 그래서 본인 확인은 사람이 한다 — 고객센터로 전화 → 관제가 이름 · 휴대폰으로 확인 → 발급.
문자 본인인증이 붙으면 그때 '스스로 재설정'을 더한다.

- 임시 비밀번호는 **발급한 창에 한 번만** 보인다. 서버에는 해시만 남고, 권한 변경 기록 · 감사로그에는 발급 사실만 남는다.
- 발급하면 지금 비밀번호는 바로 못 쓰고, 로그인해 있던 기기는 모두 끝난다. 로그인 잠금(5번 틀림)도 풀린다.
- 임시 비밀번호 상태에서는 서버가 기록을 주지 않는다 (가족 기록 · 초대 링크 · 결제 모두) — 화면만 막는 것이 아니다.
- 관제 회원의 비밀번호는 센터 관리자(ops1~3)만 발급한다. 자기 계정 · 승인 대기 · 거절 · 정지 계정 · 테스트/센터 관리자 계정은 발급하지 않는다.

**탈퇴는 '내 계정을 지우는 것'이고, 서비스 해지와는 따로다.**

| 탈퇴하면 | |
|---|---|
| 바로 지워지는 것 | 내 계정 줄 — 아이디 · 이름 · 연락처 · 비밀번호 해시 · 가입 때 적은 것. 관제가 적어 둔 내 연락 정보(보호자 기본정보). 이 기기에 받아 둔 기록 사본 |
| 남는 것 | 가족이 함께 쓰는 기록(일정 · 요청 · 리포트 등) — 남은 가족과 서비스 제공에 쓰는 기록이다. 결제 기록(법정 보관). 권한 변경 기록 · 감사로그의 '본인 탈퇴' 한 줄(이름 · 역할) |
| 그대로인 것 | **월 구독(서비스 이용계약)** — 탈퇴로 해지되지 않는다. 화면이 그렇게 알리고 고객센터로 안내한다 |
| 관제에 뜨는 것 | 그 가족의 '지금 처리할 일'(관제 연락)에 "회원 탈퇴 — ○○ 님(보호자) · 남은 앱 회원 n명". **남은 회원이 없으면** "서비스 해지 여부와 기록 정리를 확인해 주세요" |

- 앱 계정이 없어도 서비스는 계속될 수 있다(어르신이 앱을 안 쓰고 방문만 받는 경우). 그래서 마지막 회원이 나가도 가족 기록을 자동으로 지우지 않는다 — 관제가 해지인지 확인한다.
- 같은 아이디로 다시 가입할 수 있지만 지난 계정과 이어지지 않는다. 탈퇴한 사람의 옛 로그인 · 초대 링크는 새 계정에 통하지 않는다.
- 컨시어지 · 파트너 · 관제 회원도 탈퇴할 수 있다 (맡던 담당은 '지정 전'으로 돌아가 관제 화면에 뜬다). 센터 관리자 계정(ops1~3)과 테스트 계정은 가입한 계정이 아니라 대상이 아니다.
- 탈퇴 단추는 빨강이 아니다 — 빨강은 위험 신호(SOS · 낙상) 전용.

**표를 바꾸지 않았다.** 임시 비밀번호 상태와 비밀번호를 바꾼 때는 `accounts.profile` 안의 `sec` 칸에 둔다(`{ temp, pwAt }` — 초대 표시 `profile.invite` 와 같은 방식). 관제 화면으로는 이 칸을 보내지 않는다.
옛 로그인을 끝내는 판단: 세션에 적어 둔 로그인한 때가 `pwAt` 보다 1초 넘게 앞서면 다시 로그인. 지워졌다 다시 만들어진 아이디는 세션의 '계정이 만들어진 때'와 견준다.
틀린 비밀번호는 계정마다 10분에 5번까지 (서버 인스턴스마다).

## 회사가 정해야 하는 것

1. **탈퇴 때 무엇까지 지울지.** 회사 처리방침은 "회원 탈퇴 시 24시간 이내 파기"다. 지금은 계정과 그 사람의 연락 정보만 바로 지우고, 가족이 함께 쓰는 서비스 기록은 남긴다. 탈퇴 = 서비스 해지 + 가족 기록 파기로 볼 것이면 해지 정산(약정 · 기기 회수)과 함께 절차를 정해야 한다.
2. **가족 기록 파기 수단.** 서비스가 끝난 가족의 기록을 지우는 관제 기능은 '기록 비우기' 하나뿐이다 (가족 줄 자체를 지우는 것은 빈 가족만). 해지 뒤 파기 절차 · 보관 기간에 맞춘 기능이 필요하다.
3. **본인 확인 기준.** 임시 비밀번호를 발급할 때 관제가 무엇을 물어 확인할지 (지금은 화면이 '이름 · 휴대폰'을 안내한다. 휴대폰을 안 적은 회원도 있다).
4. **내 정보 고치기.** 이름 · 연락처를 본인이 고치는 칸은 만들지 않았다 (고객센터 · 센터 관제로 안내).

## 알고 둘 것

- 비밀번호를 바꾸거나 임시 비밀번호가 발급되면 **이번 배포 전에 로그인해 둔 기기는 모두 다시 로그인**하게 된다 (로그인한 때가 적혀 있지 않은 예전 세션).
- 다른 기기의 화면은 서버를 다시 부를 때(15초 안팎) 멈춘다.
- 임시 비밀번호에는 기한이 없다 — 회원이 쓰지 않으면 그대로 유효하다 (5번 틀리면 잠기는 것은 같다). 발급 사실은 누가 언제 했는지 기록에 남는다.
- 서버가 여러 대면 틀린 비밀번호 5번 제한은 서버마다 따로 센다.
- 앱스토어 심사(5.1.1(v))가 요구하는 것은 '앱 안에서 계정 삭제를 시작할 수 있을 것'이다 — 내 정보 관리의 회원 탈퇴가 그 입구다. 앱으로 포장할 때 이 화면으로 가는 길이 메뉴에 보여야 한다.
- (2026-11-26 덧붙임) 구글 플레이는 여기에 더해 **앱 없이 웹에서 삭제를 요청하는 주소**를 요구한다 — 로그인 없이 열리는 `/delete-account`(계정 삭제 안내)를 만들었다. 탈퇴 안내 글은 `kcare-app/lib/account-deletion.js` 한 곳에서 두 화면이 같이 쓴다. `2026-11-26-google-play.md`.
