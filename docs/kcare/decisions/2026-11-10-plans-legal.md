# 2026-11-10 — 두 요금제를 앱 안에 · 약관 3종

11/06 랜딩 요청을 반영하고 남겨 둔 두 가지("확인이 필요한 것" 1 · 2번)를 처리했다.
둘 다 "최선으로 채워 달라"는 요청이라, 근거가 있는 것은 채우고 **알 수 없는 값은 지어내지 않고 빈칸으로 두었다** (5 · 6장).

- 약관 문서가 없다 → 이용약관 · 환불 정책 · 개인정보 처리방침을 쓰고 공개 화면으로 열었다.
- 앱 안쪽이 예전 요금이다 → 가구별 요금제를 정하는 방법을 정하고, 보호자 · 어르신 화면을 두 요금제로 바꿨다.

## 1. 가구의 요금제를 어떻게 정하나

| 정한 것 | 내용 |
|---|---|
| 어디에 두나 | 가구 기록의 `plan` 칸 — `{ key: "basic" \| "care", by, at }`. 없으면 '지정 전' |
| 누가 정하나 | 관제 **센터 관리자**. 관제 › 어르신 관리 › `[요금제 지정]` (지정 뒤에는 `[요금제 변경]`) |
| 언제 | 가입 상담에서 요금제가 정해진 뒤. 상담 결과를 관제가 옮겨 적는다 |
| 남는 것 | 사유(4자 이상) 필수. 어르신 수정이력에 `요금제: 지정 전 → 안심 기본` 한 줄, 감사로그에도 남는다 |
| 지정 전 화면 | 보호자 멤버십 · 마이, 어르신 마이가 **`요금제 확인 중`**. 금액 · 포함 내용 · 해지 비용을 보이지 않는다 |
| 관제가 놓치지 않게 | 지정 전인 가구는 관제 '지금 처리할 일'에 `요금제 지정 전`이 뜬다 (칸이 열린 채로) |
| 시연 화면 | 로그인하지 않은 시연(`/demo`)은 전담 케어를 예시로 보인다 |
| 두 분 가구 | 금액 대신 `상담에서 안내` (요청서 6장: 두 분 요금은 금액 없이) |
| 보호자 · 어르신 | 요금제를 직접 바꾸는 단추는 없다. 전처럼 상담 요청만 보낸다 |

보호자나 어르신이 가입 때 스스로 고르게 하지 않은 이유: 요청서의 가입 흐름이 "가입 상담에서 요금제와 결제 방식을 정한다"이고,
계약서 · 기기 설치 · 자동 결제 등록이 모두 상담 뒤 사람 손을 거친다. 앱에서 고른 값과 계약서가 어긋나면 그게 사고다.

금액과 구성은 `kcare-app/lib/plans.js` 한 곳이다. 서비스 소개 요금표, 앱 안 멤버십, 관제, 약관이 모두 여기를 읽는다.
금액이 바뀌면 `FEE` 의 숫자만 고친다.

## 3. 월 요금 결제 — 카드 등록 입구를 닫았다

11/06 결제 범위 결정("토스는 해주세요 같은 그때그때 결제만, 월 요금은 자동이체 대행")에 맞췄다.

- 멤버십 화면의 `카드 등록하기 / 카드 바꾸기`를 없앴다.
- `/pay?kind=billing` 은 "여기서는 등록하지 않습니다" 안내만 보인다. `/api/payments/billing` 은 410 으로 닫았다.
- 결제 방법(카드 · 계좌 자동이체 · 무통장 입금)을 정하면 **어느 것이든** 관제 '지금 처리할 일'에 안내 요청이 간다 (전에는 카드만 빠졌다).
- 앱은 자동 결제 날짜를 모른다. '다음 결제일'을 지웠다. 결제일은 계약서에 적는 것으로 약관에 썼다.

다시 열어야 하면 git 기록의 `pages/api/payments/billing.js` 와 `lib/toss-server.js` `issueBillingKey` 를 쓴다.

수탁 업체에 대해 알고 있는 것 (문서에는 넣지 않았다 — 실제 설정을 확인하고 넣어야 한다):

- 데이터베이스는 배포 안내(`DEPLOY.md` 4장)대로면 Supabase, 리전은 서울을 권했다. 실제 프로젝트 리전을 확인해야 한다.
- 화면 · API 는 Vercel, 함수 위치는 서울(`vercel.json` `icn1`).
- AI 답변(`pages/api/ai.js`)은 키를 넣었을 때만 국외 AI 제공사로 질문과 기록 일부가 나간다. 화면에는 'AI'로만 적는 원칙이 있지만,
  **처리방침의 수탁자 · 국외 이전 항목은 법으로 적어야 하는 것**이라 업체 이름과 국가를 넣어야 한다. 넣을지, 넣는다면 표기를 어떻게 할지 확인이 필요하다.
- 보관 국가가 국외로 확인되면 처리방침 5장에 국외 이전 항목(받는 곳 · 국가 · 항목 · 시기와 방법)을 써야 한다.

## 7. 바꾸지 않은 것 — 어긋나 있다

| 어긋남 | 상태 |
|---|---|
| 해주세요 취소 **환불 금액** | 정책은 24시간 · 50%. 앱은 금액을 계산하지 않고 관제가 환불을 처리한다 (3일 전까지 바로 취소, 그 뒤 관제 승인). 자동 계산은 넣지 않았다 |
| 추가 이용 금액 "3일 뒤 자동 결제" | 약관에는 적혀 있고 앱에는 그 기능이 없다 (전부터 열려 있던 결정) |
| 시연용 가입 상담(`/demo-onboarding`), 경영 콘솔(`/admin`), 파트너 수수료(`/sales`) | 예전 요금(`lib/config.js` `PRICING`) 그대로. 고객에게 보이지 않는 시연 · 내부 화면이다 |
| 위치정보 | 약관과 동의 항목은 있고, 위치를 모으는 코드는 아직 없다 |
| 요금제 칸의 권한 | 화면이 센터 관리자에게만 단추를 보인다. 서버가 칸별로 막지는 않는다 (관제가 고치는 다른 기록과 같은 방식). 실제 청구는 자동이체 계약이 기준이다 |
| `/pay/result` 의 카드 등록 분기 | 코드는 남아 있다. 들어올 길이 없고, 들어와도 서버가 410 으로 거절한다 |
