## 1. 방문 리포트 — 자택 · 요양병원 · 미팅 (설계서 §3)

- **방식 고르기**: 방문·리포트 탭의 '방문 리포트 작성' 카드 맨 위에 `🏠 자택` `🏥 요양병원` `☕ 미팅` 같은 폭 버튼(`aria-pressed`).
  처음 값은 가입 때 저장한 거주 형태. 고르면 가구 기록(`visit.loc`)에 남아 관제 방문관리 · 보호자 리포트가 같은 방식을 본다. 제출한 뒤에는 못 바꾼다.
- **자택 · 요양병원 — 같은 양식(확정)**: 리포트 상단 문장 · **21가지 점검 n / 21**(몸 · 마음 · 집 각 7 · 그룹마다 n / 7) · 총평 · 사진 ·
  보호자께 부탁드려요(보호자) · 어르신께 남길 말(어르신) · 내부 메모(🔒 내부 · 점선 카드) · [미리보기] [리포트 제출].
  필수 5개(혈압 · 걸음 · 균형 · 복약 · 문턱 · 바닥 · 가스 · 전기)가 남으면 `필수 n개 남음`으로 꺼진다. 빈 칸 안내는 필수 `필수 · 내용 적기` / 나머지 `내용 적기`.
  요양병원 전용 목록(병실 7 · `CHECKUP_HOSPITAL`)은 지우지 않고 남겨 두었다 — 전용 양식을 만들 때 `lib/checkup.js` `checkupFor` · `lib/ops-mgmt.js` `requiredFor` 두 곳만 고치면 된다.
- **미팅 (집 근처 카페 · 확정)**: 21가지 점검 · 사진 없이 — 기간 줄(`MM.DD – MM.DD · 만남 MM.DD (요일)` / `집 근처 카페 · 시간`) ·
  만나서 나눈 이야기(어르신 말씀 · 컨시어지가 본 것 · 부탁하신 것[어르신 · 보호자] · 전해 달라신 말, 상태 칩 눌러서 바꿈 · 처음 양호) ·
  생활 반응(모션 감지 센서 · 자동, 처음 관찰) · 몸 신호(갤럭시핏 · 자동 + 컨시어지가 챙길 것) · 종합(4단계 · 처음 관찰 · 총평 · 보호자께 부탁드려요) · 내부 메모.
- **미리보기(세 방식 공통)**: 시트 위 탭 `보호자 리포트`(A4 세로 · 크게 보기 / 화면 맞춤 · 내부 메모 빠짐) · `어르신 앱`(`지현 선생님이 남겼어요` + 자택은 어르신께 남길 말 /
  미팅은 부탁하신 것 · 다음에 오는 날) · `관제`(검수 상태 · 방문 `자택 · n인` / `외부 미팅 · 카페` · 체크인 · 사진 · 점검 `n / 21` / `해당 없음` · 내부 메모).
- **제출 뒤 흐름(세 방식 공통)**: 제출 → `관제 검수 중` → 관제 검수 승인 · 보호자 리포트 발송 → `가족에게 발송됨`(한 번 반짝).
  토스트 `제출했어요 · 관제 검수를 기다려요` / `관제 검수 완료 · 보호자 앱에 발송`(컨시어지 화면을 켜 둔 채 관제가 보내면 몇 초 안에).
  관제 알림 줄 `박지현 · 김순자 안심방문 리포트 제출` / `… 미팅 리포트 제출`, 관제 방문 상세 머리 `김순자 고객 미팅` · `박지현 · 김순자 미팅 리포트`.
- 보호자 마이 › 방문 리포트 · A4 인쇄본(`/report/visit`)에 미팅 모양을 더했고, 자택 리포트에도 '보호자께 부탁드려요'가 실린다.
  어르신 홈에 관제가 보낸 리포트의 `○○ 선생님이 남겼어요` 한 줄(보내기 전에는 없다 · 다음 리포트가 가면 그것으로 바뀐다).
- 관제 방문 상세: 미팅은 점검 `해당 없음` · 대화 기록 · 상태 4단계 · 보호자께 부탁드려요 · 내부 메모(관제 · 컨시어지만)를 그대로 본다.

## 2. 고객 탭 — 이름 목록 → 상세 (설계서 §2 · 목업 방식 확정)

- 첫 화면 `내 담당 고객 n명` — 성 한 글자 · `이름 (나이)` · `동네 · n번째`(첫 방문 전이면 `첫 방문 M/D`) · `자택`(회색) / `요양병원`(파랑) · ›. 상세 내용은 누른 뒤에만.
- 줄을 누르면 상세로 **바뀌고**(아래로 펼치기 아님) 맨 위 `‹ 고객 김순자 (78) · 대치동`의 ‹ 로 목록에 돌아온다.
  상세 순서: 선호 카드(🔒 내부 · `오늘 알게 된 선호` 입력) · AI 동행 브리핑(🔒 내부 · 미확정 표시) · 건강 정보(어르신 · 보호자 — 질환 칩 · 복용약을
  아침 · 점심 · 저녁 · 자기 전으로 · 수정 기록 줄 · `복용약 · 질환 수정`) · 다음 진료 예약(어르신 · 보호자 캘린더의 진료 일정).
- 예전 목록 줄에 있던 제안 수락 · 소개 · 케어 프로필 링크는 상세 머리로, 홈 안전진단 카드는 상세 아래로 옮겼다.

## 3. 오늘 › 지금 카드에서 추가 이용 금액 보내기 (설계서 §1)

- **지금 카드가 맡는 건**: 내가 맡은(주 · 짝) 해주세요가 진행 중 → 오늘 끝남 → 오늘 예정 순. 없으면 전처럼 오늘의 중심 업무(예시 일정).
  버튼 줄 `관제센터 연락` + `진행 시작` / `완료 (체크아웃)` / `방문 화면 열기`.
- **보이는 때**: 서비스가 끝난 뒤(완료 = 체크아웃). 그때 버튼 줄 바로 밑에 카드 전체 폭 `추가 이용 금액 보내기`.
  진행 중에는 보내지 않는다 — 아래 해주세요 목록의 진행 중 카드에서도 버튼을 뺐다(전에 보낸 청구의 상태만). 오늘 이전에 끝난 건(사흘 안)은 전처럼 아래 '끝난 것'에서 보낸다.
- **시트**: `추가 이용 금액` / `김순자 고객 · 든든 병원동행` / ✕ — 예약한 시간(읽기) · 실제 이용(− / + 30분, 처음 예약 + 30분) · 추가 시간(`없음`) ·
  추가 금액(서비스 메뉴 30분 단가 · `lib/booking.js` — 하드코딩 없음) · 받는 분(구두로 동의한 분 · 처음 어르신) · 받는 분께 보일 메모(추가 시간에 맞춘 기본 문구) ·
  결제 기한(보낸 날 + 3일) · `n원 청구 보내기`(추가 시간 0이면 `추가 시간이 없어요`). 보내면 토스트 `어르신 앱과 관제에 보냈어요` / `보호자 앱과 관제에 보냈어요`.
- **보낸 뒤 상태 줄**: `결제 대기`(주의색) `추가 이용 30분 · 10,000원` / `어르신께 보냄 HH:MM · ○월 ○일 (요일)까지` ·
  `결제 완료`(완료색) / `어르신 결제 HH:MM` · `자동 결제`(완료색) / `기한 지남 · 등록 카드 HH:MM`.
- 받는 분 화면 · 관제 화면은 10/22에 만든 그대로다(받은 쪽에만 결제 카드 · 관제 지금 처리할 일 · 해주세요 관리 표 · 결제 수단은 저장된 값).
  관제 표의 빈 칸 문구만 `아직 청구가 없어요. 컨시어지 오늘 › 지금 카드 › 추가 이용 금액 보내기로 시작해요.`

## 설계서 · 목업을 그대로 옮기지 않은 곳

| 설계서 · 목업 | 앱 | 이유 |
|---|---|---|
| 리포트 상단 문장 — 고칠 수 있는 칸 | 가입상담 시트가 지정한 문구 그대로(`REPORT_HEADLINE`) · 고치는 칸 없음 | 실무진이 정한 문구 · 보호자 앱 · 알림톡 공용 |
| 미팅 A4 '두 기록이 겹친 곳 · 밤잠' 상자 | 만들지 않음 | 목업에 적힌 예시 글이고 입력 칸이 없다 — 겹친 것은 컨시어지가 총평에 적는다 |
| 생활 반응 · 몸 신호 값(무반응 0회 · 6:40 · 새벽 5회 · 착용 2일 …) | 데모 화면에만 목업 예시 값. 테스트 가구 · 센터는 `기록이 아직 연결되지 않았어요` | 센서 · 갤럭시핏 연동 전 — 값을 지어내지 않는다. 생활 반응 상태 칩은 센서 기록이 있을 때만 보호자에게 보인다 |
| 미팅은 필수 없이 바로 제출 | 테스트 가구는 총평이 있어야 제출(데모는 바로) | 2026-10-19 점검 C-01 — 보호자에게 갈 글이 없는 리포트는 관제가 반려만 했다 |
| '어머님 말씀' | '어르신 말씀' (보호자 리포트도) | 어르신이 아버님일 수 있다 |
| 보호자 A4 '지난달과 달라진 것' · 몸/마음/집 상태 칩 | '관찰 · 주의로 적은 것' · '몸 · 확인 n/7' + 컨시어지가 고른 상태 개수 | 앱에는 지난달 비교 값이 없다. 자택 리포트는 종합 판정을 만들지 않는다(고른 것만 싣는다) |
| 미리보기 어르신 앱 '마음사서함 선생님 목소리 1개' | 뺐다 | 어르신 홈의 마음사서함 칸은 그대로 있고 개수는 어르신 화면이 따로 센다 |
| 방식 고르기 — 방문·리포트 탭 맨 위 | '방문 리포트 작성' 카드 맨 위(위쪽 방문 수행 카드들 아래) | 방문 수행 화면은 설계서에 없어 그대로 |
| [미리보기][리포트 제출] — 리포트 양식 바로 아래 | 동행 완료 리포트 카드 아래 | 앱은 방문 리포트와 저장한 동행 기록을 같이 낸다 (동행 카드는 설계서에 없어 그대로) |
| 건강 정보 수정 줄 '… · 3곳 알림' | '… · 어르신 · 보호자 · 관제 3곳 반영' | 어르신 복약 · 보호자 마이가 같은 값을 읽고 관제에는 알림 줄이 간다. 어르신 · 보호자에게 따로 알림을 보내지는 않는다 |

| GPS 체크인 · 체크아웃 | `진행 시작` · `완료 (체크아웃)` | 해주세요의 기존 단계 그대로 |
| 고객 목록 토스트 '시안에서는 김순자 고객만 열려요' | '예시 고객 — 김순자 고객만 열려요' | 앱의 나머지 고객은 예시 데이터라 상세 기록이 없다 |
| 받는 분 결제 버튼 주황(#E0552B) · 기한 빨간 글씨 | 10/22 그대로(금색) | 빨강은 위험 신호(SOS · 낙상) 전용 |

미팅 상태 4단계에는 `위험`(설계서 0-2 색)이 들어 있다 — 위험 신호를 적는 자리라 빨강 규칙과 같다.
선호 카드 '오늘 알게 된 선호'는 가구 기록에 쌓는다(20줄 · 관제 · 컨시어지만 — 보호자 · 어르신 앱에는 안 나간다). 관제 화면에는 아직 이 칸이 없고 커뮤니케이션 · 감사로그에 기록이 남는다.

## 아직 정해야 할 것 (설계서 1-9 · 5절 — 바꾸지 않았다)

- 자동 결제 사전 동의 문구(가입 · 해주세요 신청서) — 법률 검토. 기한 지난 건의 실제 자동 결제(서버 스케줄러 · 빌링)는 여전히 없다(10/22 문서 그대로).
- 계좌 이체 입금 확인 단계 · 받는 분 '선생님께 묻기' 버튼 · 한 서비스에 여러 번 청구 · 서비스별 30분 단가 확정.

## 그 밖에 같이 고친 것

- 컨시어지 화면의 시트에 `role="dialog"` · 이름(스크린리더가 시트로 읽는다).
- 토스트(`.ds-toast`)가 화면 절반 폭에 갇혀 짧은 글도 두 줄로 접히던 것 — 글 길이만큼(어르신 · 보호자 화면 토스트도 같다).
- 스모크(`npm run smoke`)가 `/concierge` 의 고객 상세 · 방문 리포트(자택 · 미팅) · 발행 전 미리보기 · 관제 탭을 눌러 같은 규칙으로 본다 —
  미리보기 A4의 header · footer 가 화면 머리 영역과 겹치던 것(landmark-unique)을 여기서 잡았다.
