# 2026-11-18 계정 관리 · 접속 화면 재점검

가족마다 기록을 나눈 뒤(2026-11-12) 가입 · 로그인 · 계정 · 가족 관리 화면과 그 뒤의 서버 규칙을 다시 봤다.
화면은 가입 → 승인 → 로그인 → 초대 → 정지 · 옮기기까지 실제로 눌러 봤고, 서버 코드는 따로 한 번 더 읽어 권한 구멍을 찾았다.

## 정해야 할 것 — 고치지 않았다

- **비밀번호 찾기 · 바꾸기가 없다.** 지금은 관제가 계정을 `[삭제]`하고 같은 아이디로 다시 가입해야 한다 (가족 기록은 남는다). 정식 판매 전에 '관제의 임시 비밀번호 발급 + 본인 비밀번호 바꾸기'가 필요하다.
- **본인이 하는 회원 탈퇴가 없다.** 회사가 보낸 처리방침은 "회원 탈퇴 시 24시간 이내 파기" · "앱 내 [설정 > 내 정보 관리]"를 적는다. 애플 심사도 앱 안 계정 삭제를 요구한다 (5.1.1(v)).
- **보호자 5명** — 약관대로 서버에서 막을지 (지금은 안내만).
- **초대는 누가** — 약관은 "주 보호자의 초대"인데 앱은 어르신 · 부 보호자도 초대 링크를 만든다 (2026-10-14 현장 요청).
- **파트너 화면의 '내 코드로 들어온 신청'** — 가족 기록을 주지 않게 되면서 늘 비어 있다. 추천 링크(`/consult?ref=`)로 들어온 상담 신청은 관제 '상담 신청'에만 보인다. 파트너에게 보여 주려면 상담 신청 표에서 읽어야 한다.

## 알고 둘 것 (버그는 아니다)

- 담당 컨시어지는 **이름**으로 맞춘다 — 같은 이름의 컨시어지가 둘이면 둘 다 그 가족을 본다.
- 서버가 여러 대일 때 계정 · 담당 변경은 서버마다 15초까지 늦게 따라온다 (가족을 지운 직후 다른 서버의 관제 탭이 저장하면 빈 줄이 다시 생길 수 있다).
- 가입 응답이 폰에 닿지 못하면 다시 누를 때 "이미 쓰는 아이디"가 뜬다 — 다른 아이디로 다시 신청하면 승인 대기가 둘 생긴다 (관제가 하나를 거절).
- 휴대폰 번호는 형식을 검사하지 않는다 (선택 칸).
- 결제 승인 경로의 계정 확인은 코드로만 봤다 (승인까지 가려면 토스 키와 실제 결제창이 필요하다). 결제 시작 경로는 실행해 확인했다.
