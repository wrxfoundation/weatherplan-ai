# 어르신 화면 현장 테스트 반영 — 실제 녹음 · 달력 예약 · 응급 대응 · 자녀 초대 (2026-10-14)

요청: 강도완 님 현장 테스트 문서 '어르신' — 기본 로직 1~5 · 연동 확인 1~5 · 수정사항 1~8 (화면 캡처 7장).
가장 큰 원인은 하나였다 — **녹음이 시뮬레이션**이었다 (길이만 재고 '전달됨'을 보였다). 그래서 '말로 남기기'가 실제로
녹음되지 않았고, 마음사서함에서 들리지 않았고, 보안 설정(Permissions-Policy)이 마이크까지 막고 있었다.

## 녹음 — 정한 것

- 녹음은 Supabase `voice_clips` 표(새 표 · `supabase/voice-clips.sql`)에 두고, 가구 기록에는 id 만 남긴다.
  같은 가구(센터) 계정만 듣는다 — 다른 센터는 id 를 알아도 못 받는다. **30일 뒤 지운다.**
- 어르신 · 보호자 녹음은 1분, 컨시어지 답장은 2분까지. 녹음기에는 32kbps 를 부탁한다 (1분 약 240KB).
- **음성 인식(STT)은 붙이지 않았다** — 2026-09-10 결정 1의 권고 A(현행 유지) 그대로. '말로 부탁'의 글은 담당 컨시어지가
  듣고 쓴다 (사람이 확인한 글이라 오인식이 없다). B안(컨시어지 음성만 자동 변환)은 실서비스 설계 때 따로 정한다.
- 데모(로그인 없이)는 녹음을 그 기기 메모리에만 둔다 — 서버에 올리지 않는다.
- 빨강은 쓰지 않았다 — 녹음 중은 금색 (빨강은 SOS · 낙상 전용).

## 결정 요청 — 해주세요 결제 시점 (연동 확인 5번)

**요청.** "활동이 끝나면 등록된 카드로 자동 결제 + 인보이스 발송."

**지금.** 2026-10-05 결정대로 **부탁할 때 먼저 결제**한다 (토스 결제창 · 테스트 키). 카드를 등록하는 화면은 있지만
카드 키(빌링키)를 서버에 보관하지 않아(`pages/api/payments/billing.js` 는 가린 카드 정보만 돌려준다) 나중에 청구할 수 없다.

| 선택지 | 내용 | 필요한 것 |
|---|---|---|
| A 현행 유지 | 부탁할 때 먼저 결제 · 거절 · 취소는 환불 | 없음 (지금 동작) |
| B 후결제 | 활동 완료 때 등록 카드로 자동 결제 + 인보이스 | 토스 **자동결제(빌링) 계약** · 카드 키 서버 보관(암호화 표 · 접근 기록) · 완료 때 청구 API · 실패 때 다시 청구 · 알림 · 인보이스(화면 · 메일) · 취소 · 환불 규정 |
| C 섞기 | 금액이 정해진 것은 먼저 결제, **시간제(응급 대응 1시간당)**는 끝난 뒤 정산 | B의 준비 전부 + 시간 기록(컨시어지 시작 · 종료) |

**실무 권고.** 베타 동안은 A. 응급 대응은 1시간당이라 끝나야 금액이 정해지므로 실서비스에서는 C가 맞다 —
토스 자동결제 계약이 먼저다. 계약 · 정책이 정해지면 서버 쪽부터 붙인다. 금액 · 수수료는 지어내지 않는다.

## 알아 둘 것

- 기기마다 녹음 형식이 다르다 (mp4 · webm). 아이폰 ↔ 안드로이드 서로 듣기를 현장에서 확인한다 (TEST-SCENARIOS F-10).
- 녹음을 보내는 중에 화면을 떠나면 그 녹음은 보내지지 않는다 — 서버가 받았다고 답해야 '전달했습니다'가 뜬다.
- 초대 링크는 로그인 비밀 값(`NEXTAUTH_SECRET`)으로 서명한다 — 그 값을 바꾸면 이미 보낸 링크는 무효다.
- 단독 배차 0 원칙은 그대로다 — 이번 변경은 배차 경로를 건드리지 않았다.
