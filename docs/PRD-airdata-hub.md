## 1. 배경 & 기회

### 1.1 우리가 이미 가진 것

백서 v0.3은 "측정 → 보상 → 판매" 전 과정을 XRPL 위에서 자동화하는 데이터 생태계를 정의했다.

- **공급(수집망)**: DePIN 방식 — 일반 가정·사무실·건물에 실내(IAQ)/실외(OAQ) 측정기를 설치한 기여자에게 WLBN 토큰 보상. 기기 신원은 라이선스 NFT(XLS-20), 데이터 무결성은 머클루트 온체인 앵커링, 보상은 품질 점수 × 등급 배수 기반 에폭(24h) 고정 예산 배분.
- **정산(결제 레일)**: x402 프로토콜(HTTP 402 기반 온체인 결제), 선불 크레딧(고빈도 API용), AMM(XLS-30)을 통한 WLBN↔RLUSD 교환, 수취 WLBN 50% 소각.
- **판매 대상(수요자)**: 이미 명확하다 — ① 가전 제조사(R&D·마케팅) ② 스마트홈 플랫폼 ③ 지자체·환경/보건 서비스 ④ 건설사·인테리어 기업(리포트) ⑤ **AI 에이전트**(사람 개입 없는 M2M 구매자).

### 1.2 비어 있는 것 — 이 PRD가 채우는 곳

백서 기술사양(Step 1~6)은 **데이터 플레인**(지갑, 토큰, NFT, 오라클, AMM, 결제 게이트웨이 원리)을 설계했다. 그러나 수요자가 실제로 데이터를 **발견 → 평가 → 구매 → 활용 → 재구매**하는 **사용자 접점(플랫폼)**은 아직 없다.

> 데이터가 아무리 좋아도, 제조사 R&D 담당자가 "우리 동네 격자의 7월 절대습도 분포"를 5분 안에 눈으로 확인하고 법인카드/크레딧으로 결제해서 CSV를 받을 수 없다면 매출은 발생하지 않는다.

**본 PRD의 제품**: 수요자(사람)와 AI 에이전트(기계)가 모두 고객으로 접속하는 데이터 커머스 플랫폼. 핵심 차별점은 **AI 데이터 컨시어지 에이전트**(wellbian AI 확장)가 카탈로그 탐색·질의 작성·견적·구매·리포트 생성을 대화로 대신해 주는 것, 그리고 외부 AI 에이전트가 회원가입 없이 x402로 자율 결제하며 데이터를 사 가는 **M2M 스토어프런트**다. 단, 셀프서브와 M2M만으로 초기 매출은 서지 않는다 — §1.4의 하이브리드 유통 전제에 따라 **사람 영업(직접 영업·파트너 대행사)이 딜을 닫는 경로를 1급 채널로 함께 설계**한다.

### 1.3 기존 코드베이스와의 관계

| 기존 자산 | 재사용 방식 |
|---|---|
| `pages/api/claude.js` | 복잡도 모델 라우터(`claude-opus-4-8`/`claude-haiku-4-5-20251001`), 프롬프트 캐싱 규약(정적/동적 분리), CORS 화이트리스트 패턴을 컨시어지 에이전트에 그대로 적용 |
| `lib/tools.js` | tool-use 스키마 컨벤션(name/description/input_schema, 한국어 설명) 위에 데이터 질의 tool 8종 추가 |
| `koreaapi/` | "AI 에이전트가 호출 가능한 검증된 데이터 레이어 + provenance/Skill Score + llms.txt" 패턴을 MCP 서버 설계에 재사용 |
| `dcmap-web/` | Leaflet 커버리지 맵, "근거 없는 수치는 '데이터 대기'로 표기(가짜 수치 금지)" 정직성 UX 원칙, DATA_ASSET.md의 자산화 사고방식 |

### 1.4 전략 전제 — 하이브리드 유통 시대

AI 에이전트가 데이터를 전량 사고파는 시대는 오고 있지만 **아직 오지 않았다**. 당분간 실제 매출은 사람이 닫는 계약에서 나온다: 가전 제조사는 품의·법무 검토·연간 예산으로 움직이고, 지자체는 조달 절차를 탄다. 따라서 본 플랫폼은 **사람이 파는 채널과 AI가 파는 채널을 동시에 지원하는 하이브리드 유통**을 1급 설계 전제로 삼고, 시간이 갈수록 자동화 채널의 비중이 커지는 점진 전환을 설계에 내장한다.

| 채널 | 누가 파나 | 누가 사나 | 계약·결제 형태 | 주력 시기 |
|---|---|---|---|---|
| **C1. Sales-led (영업 주도)** | KWeather 영업(AE) · 파트너 대행사 | 엔터프라이즈 제조사·지자체 (P1 P2 P4) | 데모 → 견적서(볼륨 할인 규칙) → 연간 계약·세금계산서 → 크레딧 프로비저닝 | R0~ **초기 매출의 중심** |
| **C2. Self-serve + AI 어시스트** | 플랫폼 (컨시어지가 사람 구매자를 보조) | 개별 팀·중소기업·스타트업 (P1 P3 P5) | 카드/PG 크레딧 충전, 단건 리포트 | R1~ |
| **C3. M2M (AI 자율 유통)** | 플랫폼의 기계 표면 (x402·MCP) | AI 에이전트 (P6) | x402 온체인 건당 결제, 사람 개입 0 | R0 데모 증명 → R2~ 실매출 |

**운영 원칙**

- **일물일가**: 공시 단가는 채널과 무관하게 동일하다. 영업 채널의 여지는 임의 할인이 아니라 **공개된 볼륨 할인 규칙과 계약 기간**으로만 만든다 — 채널 간 가격 컨플릭트 방지.
- **fulfillment는 전부 플랫폼**: 영업이 닫은 딜도 키 발급·크레딧·사용량·리포트는 100% 플랫폼에서 처리한다(엑셀 수기 정산 0). 영업 채널은 플랫폼 밖의 예외가 아니라 **플랫폼 위의 역할**이다.
- **같은 상품, 같은 가드레일**: 어떤 채널로 팔려도 프라이버시 가드레일(§8)·provenance 규격은 동일하다. 영업·데모 경로에도 예외 없음.
- **전환 트리거 기반 투자 이동**: C3 매출 비중·재구매 에이전트 지갑 수·x402 완주율이 임계(§13)를 넘으면 C3 투자를 확대한다. 목표 믹스(가정): R1 — C1 ≥ 70% → R2 — C1 55 / C2 35 / C3 10 → R3 — C1 45 / C2 35 / C3 20 (%).

- 본격 CRM 구축 — 리드 큐는 경량 기능만, 외부 CRM 연동은 OI-14
- 원본(비집계·비식별화 이전) 데이터 판매 — **어떤 요금제로도 제공하지 않는다**

## 3. 타겟 고객 & 페르소나 — "데이터를 팔 대상"

백서가 정의한 수요자를 구매 의사결정 단위로 구체화한다. **P6(AI 에이전트)은 사람이 아니라 소프트웨어이지만 1급 고객**으로 취급하며, 하이브리드 유통(§1.4)에 따라 **판매자 측 사용자(P7 — 영업·파트너)**도 페르소나에 포함한다.

### P1. 가전 제조사 R&D 엔지니어 — "현장 데이터가 없다"

- **JTBD**: 제습기/공기청정기/에어컨의 제어 알고리즘을 실제 거주 환경 분포(절대습도, 침투율, 환기 패턴)로 학습·검증하고 싶다.
- **페인**: 출하 후 제품이 만나는 실제 환경을 알 수 없어 "최악 조건" 과잉 설계 또는 성능 미달. 실험실 데이터·기상청 실외 데이터로는 실내를 알 수 없다.
- **구매 트리거**: 신제품 개발 사이클 착수, 장마·폭염 시즌 리뷰.

- **성공 기준**: 데이터를 사내 분석 환경(Python/BI)에 2주 내 통합, 알고리즘 개선 근거 확보.

### P6. AI 에이전트 (M2M 고객)

- **정의**: 제조사·리서치 기업·개인 개발자가 운영하는 자율 에이전트. 회원가입·카드 등록이 불가능한 대신 **블록체인 지갑으로 스스로 결제**한다.
- **JTBD**: 태스크 수행 중 필요한 공기질 데이터를 발견(discovery)하고, 가격을 확인하고, 결제하고, 기계가 읽을 수 있는 형태로 받는다.
- **사는 것**: 모든 SKU의 API 형태. x402 건당 결제 또는 (반복 고객화 시) 크레딧.

### P7. KWeather 영업 담당(AE) & 파트너 대행사 — "파는 사람" (판매자 측 사용자)

- **정의**: 구매자가 아니라 **판매자 측 1급 사용자**. 하이브리드 시대(§1.4)의 초기 매출을 실제로 만드는 주체. 내부 AE는 엔터프라이즈·지자체 딜을 닫고, 파트너 대행사는 광고주(P2)의 캠페인 운영을 대행한다 — 기존 `agency-board.jsx`(광고대행사 AE 콘솔)로 검증된 사용자층.
- **JTBD**: 리드를 받아 데모로 설득하고, 견적서를 만들고, 계약 후 고객 조직을 개통(프로비저닝)하고, 갱신 시점에 사용량 근거로 업셀한다.
- **페인**: 데이터 상품은 눈에 안 보인다 — 미팅에서 보여줄 화면이 없으면 팔 수 없다. 견적·개통·정산이 수기면 딜마다 운영 비용이 폭증하고 실수가 정산 사고가 된다.

**판매 채널과의 관계 (§1.4)**: 위 단가는 채널 불문 동일한 공시가다. 영업 주도(C1) 계약은 같은 단가에 **공개 볼륨 할인 규칙**을 적용한 연간 선구매(크레딧 일괄 프로비저닝) 형태를 취한다 — 별도 SKU가 아니라 계약·결제 방식의 차이일 뿐이다.

**무료 티어**: 플레이그라운드에서 격자 3개·최근 7일·집계 통계만 무료 체험(계정 불요, rate limit). 전환 장치이자 P6 에이전트의 스키마 학습용.

- **US-09 (k-익명성)**: Given 조건 조합을 만족하는 기기가 5대 미만인 질의가 / When 어떤 경로(콘솔·API·에이전트·MCP)로 들어와도 / Then 개별 값이 아닌 `PRIVACY_K_ANONYMITY` 거부와 완화 제안(넓은 격자·기간 확대)이 반환되고, 시도는 감사 로그에 남는다. **어떤 응답에도 5 단위 반올림 전의 원시 카운트가 노출되지 않는다.**
- **US-03 (에이전트 비용 승인)**: Given 유료 tool 호출이 필요한 대화에서 / When 컨시어지가 실행 전 예상 비용을 고지하면 / Then 사용자의 명시적 승인(버튼/응답) 후에만 차감이 일어나고, 조직 설정의 일일 자동 승인 한도(기본 0 = 항상 확인) 내 호출은 생략 가능하다.
- **US-13 (수동 프로비저닝)**: Given 체결된 계약(금액·기간·SKU 스코프)이 계약 레코드로 등록되어 있을 때 / When AE가 크레딧 프로비저닝을 요청하고 **별도의 두 번째 운영자가 승인**하면 / Then 조직 크레딧이 증가하며 계약 레코드·감사 로그에 연결된다. 단독 승인, 계약 한도 초과, 계약 미등록 프로비저닝은 시스템이 거부한다.

## 7. AI 에이전트 상세 설계

플랫폼의 AI는 **두 층**이다. (a) **컨시어지 에이전트** — 플랫폼 안에서 사람을 보조하는 우리 에이전트. (b) **M2M 표면** — 외부 AI 에이전트가 고객으로 접속하는 프로토콜 표면(§6 M7). 이 절은 (a)를 상세화한다. 컨시어지는 대상에 따라 **고객 모드**(수요자의 구매·질의 보조)와 **영업 코파일럿 모드**(내부 AE·파트너 보조, §7.8)로 나뉜다 — 하이브리드 시대에는 "사는 사람"만이 아니라 **"파는 사람"도 AI로 무장**시키는 것이 전환기의 경쟁력이다.

### 7.1 아이덴티티 & 원칙

- 이름: **wellbian AI** (기존 캐릭터 확장 — "날씨 광고 컨설턴트"에서 "공기질 데이터 컨시어지"로 도메인 추가). WLBN 토큰과 세계관 일치.
- 데이터 출처 표현은 "케이웨더 실내외 관측망" 기준으로 통일한다. 시스템 프롬프트에 케이웨더 외 외부 출처(기상청·KMA·ECMWF 등) 언급을 추가하지 않는다 (CLAUDE.md 금지사항 준수).
- **수치 무결성**: 에이전트가 말하는 모든 수치는 tool 결과에서만 온다. tool이 거부(k-익명성)하면 에이전트도 수치를 만들지 않는다.

### 7.2 모델 & 호출 규약 (기존 `pages/api/claude.js` 규약 준수)

Tool 스키마 컨벤션은 기존 `lib/tools.js`와 동일(한국어 description, 명시적 enum). **유료 tool은 서버 측에서 `confirmed: true` 파라미터 없이는 실행되지 않는다** — 에이전트가 우회할 수 없도록 프롬프트가 아닌 API 레이어에서 강제(§7.5).

### 7.5 가드레일 (프롬프트가 아닌 시스템으로 강제)

| 위협 | 방어 |
|---|---|
| 프롬프트 인젝션으로 유료 tool 무단 실행 | 유료 tool은 서버가 세션 상태의 사용자 승인 토큰 검증 후 실행. 에이전트 출력만으로 차감 불가 |
| 에이전트를 통한 차분 공격 (질의 반복 유도) | 에이전트 경유 질의도 동일 키의 일일 질의 예산·필터 제한·감사 로그를 통과 — 우회 경로 없음 |
| 수치 환각 | 응답 후처리: 수치 토큰이 tool 결과에 없으면 재생성 요구(검증기). 리포트는 수치 전부 tool 결과 참조 ID와 링크 |
| 명단 유출 요청 ("가구 주소 알려줘") | 정적 프롬프트에 거부 정책 + API에 개인 단위 엔드포인트 자체가 부재(구조적 불가) |
| 개인정보 추정 대화 (CO₂로 재실 추정 등) | 개인·특정 가구 단위 추정 요청 거부, 코호트(집계) 단위로만 응대 |

### 7.6 리포트 파이프라인 (Vercel 제약 대응)

`vercel.json`의 `maxDuration` 30초·region `icn1`은 불변(CLAUDE.md). 리포트 생성(다중 질의 + 장문 생성)은 30초를 초과할 수 있으므로:

1. `POST /v1/reports` → 결제 확인 → 잡 레코드 생성 → **202 Accepted + job_id** (30초 내 완료)
2. 워커가 단계 분할 실행(질의 수집 → 분석 → 집필 → 렌더). 각 단계는 30초 내 청크로 설계, 큐/크론으로 체이닝
3. `GET /v1/reports/{id}` 폴링 또는 웹훅 통지 → 완료 시 결과 URL

### 7.7 품질 평가

- **골든 평가셋**: 페르소나별 대표 질의 30문항(정답 tool 시퀀스·비용 고지 여부·거부 처리 포함)을 릴리스마다 회귀 평가.
- 평가 축: tool 선택 정확도, 비용 고지 준수율 100%(P0), 수치 무결성(환각 0), 거부 시 완화안 제시율.

### 7.8 영업 코파일럿 모드 (내부 AE·파트너 전용)

- **접근**: 내부 AE·승인된 파트너 계정만. 데모 워크스페이스(FR-1002)·견적 도구(FR-1003)에 연결되며, 고객 조직의 크레딧을 차감하는 유료 tool은 이 모드에 노출되지 않는다.
- **용도**: 미팅 전 브리핑("이 제조사 관심 지역의 커버리지·판매 가능 격자·샘플 통계 요약"), 페르소나별 제안 포인트(P1 R&D → 절대습도·침투율 / P2 마케팅 → 도달 견적 스토리 / P4 → provenance·조달 대응), 견적 초안(`sales_quote_draft`), 반론 대응(명단 비전달 원칙 설명 스크립트).
- **경계**: 코파일럿에도 프라이버시 가드레일(§8)이 동일 적용된다 — 데모·브리핑 어디에도 k-익명성 미달 수치·개인 단위 데이터는 존재하지 않는다. 견적 확정·프로비저닝은 tool이 아니라 승인 워크플로(FR-1003/1004)에서만 일어난다.
- **프롬프트 구성**: 고객 모드와 동일한 정적 프롬프트 캐시를 공유하되, 모드·권한은 동적 컨텍스트 블록에서 주입(캐시 무효화 방지).

## 8. 프라이버시·컴플라이언스 요구사항

**백서 §9 원칙 그대로 계승하되, 플랫폼은 "집행 지점"이다.** 비식별화(5단계: geohash5 공간 뭉개기 → 1시간 집계 → 주기 가명 ID → k-익명성 → 속성 구간화)는 데이터 플레인에서 완료되지만, 차분 공격 방어와 명단 비전달은 **질의를 받는 플랫폼 API 레이어에서만 집행 가능**하다.

### 8.1 플랫폼이 집행하는 가드레일 (NFR-P, 전부 P0)

| ID | 규칙 | 집행 지점 |
|---|---|---|
| NFR-P1 | 카운트 응답은 5 단위 반올림 | 게이트웨이 응답 직전 |
| NFR-P2 | 동시 필터 최대 3개 | 질의 파서 (콘솔 UI는 4번째 필터 입력 자체 불가) |
| NFR-P3 | 키·조직별 일일 질의 예산, 초과 시 `QUERY_BUDGET_EXCEEDED` | 게이트웨이 |
| NFR-P4 | 반올림 후 25가구 미만 → 응답 거부 | 게이트웨이 |
| NFR-P5 | k-익명성: 격자 내 기기 5대 미만 → 자동 광역 병합 시도, 불가 시 거부 | 데이터 플레인 + 게이트웨이 이중 |
| NFR-P6 | **명단 비전달**: 개인·기기 단위 조회 API를 만들지 않는다(스키마 차원 부재). 캠페인 발송은 플랫폼 대행, 광고주 수신 데이터는 집계·리드뿐 | 아키텍처 |
| NFR-P7 | 모든 질의(성공·거부) 감사 로그 3년 보존, 프라이버시 파라미터 변경 이력 필수 | 감사 저장소 |
| NFR-P8 | 위치는 어떤 표면(맵·API·리포트·에이전트)에서도 geohash5(≈4.9km)보다 정밀하게 노출 금지 | 전 표면 |

### 8.2 법률 검토 (백서 리스크 "필수" — 출시 전 선행)

- 개인정보보호법: 비식별 집계 데이터의 가명·익명정보 판정, 처리 위탁 구조(캠페인 대행 발송) 검토.
- 위치정보법: 격자화된 위치의 개인위치정보 해당 여부.
- 표시광고·정보통신망법: 캠페인 알림의 광고 표기·수신 동의 체계(기여자 가입 시 동의).
- **법무 검토 완료는 R1(외부 고객 결제) 출시 게이트**다.

### 8.3 결제 컴플라이언스

- 가상자산 규제(가상자산이용자보호법 등) 검토 전까지 **국내 법인 고객 기본 결제는 원화 PG·세금계산서**로 하고, RLUSD/WLBN 결제는 테스트넷 PoC와 해외/에이전트 트래픽에 우선 적용한다(OI-8).
- 크레딧은 선불전자지급수단 해당 여부 검토(전자금융거래법).

- **포털 홈**: Hero(한 문장: "실내외 공기질 데이터, 필요한 만큼 사세요"), 커버리지 맵(판매가능/수집중 격자), 페르소나별 진입 카드 4종(P1·P2·P4·P5), "AI 에이전트이신가요? → /.well-known/x402" 링크(P6). 디자인은 기존 시스템(Pretendard, Teal #4EB3A8 / MossDark #14443B, glassmorphism) 준수.

- **빈/로딩/에러 상태**: 커버리지 없음 = "데이터 대기"(가짜 수치 금지), 온체인 검증 중 = 진행 표시(3~5초 기대치 안내), 프라이버시 거부 = 정책 설명 링크.
- **컨시어지 패널**: 모든 콘솔 화면 우측 하단 상주. tool 실행 카드(무엇을 조회했는지 투명하게), 비용 승인 버튼, 결과를 질의 빌더로 보내기.

## 13. 지표 & 계측

### 13.1 KPI 트리

- **North Star: 월 순 데이터 매출 (Net Data Revenue)** — 3개 SKU 합산, 환불 차감.
  - 획득: 포털 방문 → 플레이그라운드 실행률 ≥ 25% → 가입 전환 ≥ 10%
  - 활성화: 가입 → 첫 유료 질의 ≥ 40%, 충전 → 첫 차감까지 ≤ 24h
  - 수익: 조직당 월 크레딧 소진액, SKU 믹스, 리포트 재구매율 ≥ 30%
  - 유지: 월 활성 API 키, 90일 조직 리텐션
  - M2M: 402 발급 → 결제 완주율, 에이전트 재방문(동일 지갑) 비율
- **채널 믹스 (§1.4 하이브리드)**: 매출을 채널 태그(FR-1007)로 분해 — 목표(가정) R1 C1 ≥ 70% → R2 C1 55 / C2 35 / C3 10 → R3 C1 45 / C2 35 / C3 20. **C3 투자 확대 트리거**: C3 매출 비중 ≥ 10% 또는 재구매 에이전트 지갑 ≥ 50개 지속.
- **영업 퍼널 (C1)**: 리드 → 미팅 → 견적 → 계약 전환율, 딜당 견적~개통 리드타임 ≤ 1시간, 계약 갱신율, 파트너 경유 매출 비중.
- **가드레일 지표 (감시)**: 프라이버시 위반 응답 **0건**(절대), 질의 거부율(너무 높으면 커버리지·UX 문제), 결제 검증 실패율 < 1%, 컨시어지 비용 고지 준수 100%, 프롬프트 캐시 적중률 ≥ 80%, 수동 프로비저닝 오류 0건(이중 승인), 채널 태그 누락 0.
- **생태계 연동 지표 (참고)**: B2B 매출 대비 쿠폰 발행액(40% 상한 게이지), 월 매출 5,000만원(쿠폰 상환 개방 임계) 진척.
