# 조직 3계층 · 개인식별번호 · R/B · 계층 정산

권역(총판) → 지역(대리점) → 셀러 3계층과, 그 위에서 도는 R/B·정산서의 구현 지도.
숫자·규칙을 바꿀 때 **여기 적힌 단일 소스 파일만** 고치면 전 화면이 같이 움직인다.

## 1. 개인식별번호

```
A            1            J1234
권역(총판)   지역(대리점)  셀러코드(영문 1 + 숫자 4)
└─ A         └─ A1        └─ A1J1234
```

**상위 코드는 하위 코드의 접두사다.** `'A'` ⊂ `'A1'` ⊂ `'A1J1234'` — 소속 판정이 문자열 비교
하나로 끝나므로 정산·권한·검색이 전부 같은 규칙을 쓴다. 부모 id 를 따라 올라가는 조회를 만들면
언젠가 한 경로가 규칙을 빠져나가므로 쓰지 않는다.

- 혼동 문자 **I·O 는 쓰지 않는다** (`org.CODE_LETTERS`). 전화로 코드를 불러 줄 때 1·0 과 섞인다.
- 지역 코드는 권역 안에서 1~9. 9개를 다 쓰면 더 못 연다 — 권역 분할이 정책상 정답이다.
- 셀러코드는 **순번이 아니라 난수**다. 순번이면 코드만 보고 조직 규모가 드러난다.
- **개인회원은 코드가 없다.** 조직에 속하지 않으므로 R/B·정산 화면이 전부 닫힌다.

| 대상 | 코드 | 예 |
|---|---|---|
| 총판 | 영문 1 | `A` |
| 대리점 | 총판코드 + 숫자 1 | `A1` |
| 셀러 | 대리점코드 + 영문 1 + 숫자 4 | `A1J1234` |

## 2. 단일 소스 파일

| 무엇 | 어디 |
|---|---|
| 코드 체계·발급·소속 조회·세션→신분 | `src/lib/org.js` |
| 계층 정산 합산·마스킹·CSV 행 | `src/lib/settle.js` |
| R/B 분해(등급별로 볼 줄만 골라 준다) | `src/lib/rb.js` |
| 리베이트 단가표·건당 +@ 단가 | `src/lib/commission.js` (`RATE_CARD.hidden`) |
| 권역 코드 ↔ 영업단 | `src/lib/constants.js` (`UNITS[].region`) |
| +@ 표기 명칭 | `db.policies.opexLabel` — 어드민 조직·회원 화면에서 변경 |

**세션 → 신분 판정은 `org.bizIdentity()` 한 곳뿐이다.** R/B 노출 여부와 정산 열람 깊이가
전부 여기서 나온다. 화면마다 `session.role === ...` 을 쓰기 시작하면 언젠가 한 곳이 샌다.

## 3. R/B (사업자 전용)

계산기 **상부**에 소비자 월 납부금과 완전히 분리된 카드로 얹는다(`components/RbPanel.jsx`).
`bizIdentity` 가 null 이면 컴포넌트 자체가 렌더되지 않는다 — 개인회원·비로그인은 DOM 에도 없다.

| 등급 | 보이는 줄 |
|---|---|
| 셀러 | R/B 단가 · 고객 추가지원(매장 부담) · 내 수당 |
| 대리점 | R/B 단가 · 건당 영업비(대리점) |
| 총판 | R/B 단가 · 건당 영업비(총판) |
| 본사 | 전부 |

> **공시지원금을 R/B 에서 빼면 안 된다.** 그건 통신사가 내는 돈이다. 셀러 수당에서 빠지는 것은
> 매장이 자기 R/B 에서 얹어 주는 **추가지원금**뿐이다. 둘을 합쳐 넣으면 내 수당이 늘 0 으로 찍힌다.

## 4. 계층 정산

```
상위 금액 = 하부 금액의 합 + 영업비(건당 +@)

셀러   = 본인 영업이익
대리점 = Σ(소속 셀러) + 영업비(셀러 판매 건당 대리점 몫)
총판   = Σ(소속 대리점) + 영업비(권역 판매 건당 총판 몫)
```

### 열람 깊이 (`reveal`)

| 보는 사람 | 깊이 | 실제로 보이는 것 |
|---|---|---|
| 본사 | ∞ | 총판 → 대리점 → 셀러 **전부 실명** |
| 총판 | 1 | 대리점까지 실명, 그 아래 셀러는 `***` |
| 대리점 | 1 | 자기 셀러까지 실명 |
| 셀러 | 0 | 본인 금액만 |

마스킹은 **화면이 아니라 `settle.maskTree()` 가 건다.** 이름만 `***` 로 바꾸고 금액은 남긴다 —
합계가 검증 가능해야 하기 때문이다. 가려지는 것은 "누구인가" 뿐이다.

### 화면

| 계층 | 경로 | 세션 |
|---|---|---|
| 셀러 | `/office/settlement` | `{ role: 'partner', tenantId }` |
| 대리점 | `/agency` | `{ role: 'agency', agencyId }` |
| 총판 | `/regional` | `{ role: 'regional', distributorId }` |
| 본사 | `/admin/settlements` | `{ role: 'admin' }` |

드릴다운 컴포넌트는 `components/SettleDrill.jsx` 하나를 4곳이 공유한다. 금액을 누르면 한 단계
아래가 펼쳐지고, 마스킹된 행은 더 펼칠 수 없다.

## 5. 회원가입

`/signup` — 개인/사업자 분기. 사업자는 **추천인(권역 총판) → 지역(대리점) → 등급**을 고르면
그 자리에서 식별번호가 발급된다. 발급 코드는 화면에서 `org.issueSellerCode()` 로 미리 뽑아
액션 payload 에 담아 보낸다 — 리듀서 안에서 난수를 굴리면 같은 액션을 재생할 때 다른 코드가 나온다.

신규 사업자는 **`status: '대기'`** 로 시작하고, 본사 어드민 > 조직·회원에서 승인한다.
승인 전에도 식별번호와 R/B 조회는 열려 있다(정산 대상만 아니다).

## 6. 스모크

`scripts/qa-org-smoke.cjs` — 가입 분기·식별번호 형식·등급별 R/B 노출·드릴다운 마스킹·
**합계 검증(하부 합 + 영업비 = 총액)**·어드민 조직 관리까지 한 번에 본다.
금액은 화면 포맷이 아니라 `data-amount` 속성으로 읽는다.
