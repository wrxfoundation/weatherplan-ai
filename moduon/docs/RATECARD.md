# 정책 단가표 · 셀프개통 마진 · 사업자 R/B

통신사에서 받은 정책 단가표가 **요금제 목록** · **셀프개통 가격** · **사업자 R/B** 셋을 동시에 굴린다.
같은 표를 읽으므로 세 화면의 숫자가 어긋날 수 없다.

## 1. 단가표 (`src/lib/ratecard.js`)

현재 적용: **KT 정책 단가표 K1 (2026-09-18~)**

리베이트 = **단말 × 요금제 × 가입유형**

| 축 | 값 |
|---|---|
| 요금제 | **3종 고정** — 초이스 110(유튜브 프리미엄) · 초이스 90(유튜브 프리미엄) · 베이직 4GB |
| 단말 | 9종 수록 + `그 외` 1행 (Z플립8 · Z폴드8 · Z폴드8 Ultra · S26 · S26+ · S26 Ultra · 아이폰18 P/PM · A376 · A276) |
| 가입유형 | 3종 (010 신규 · 번호이동 · 기기변경) — 단가표 열 순서 그대로 |

### 구간표가 아니라 고정 요금제다

이전 판은 월정액 하한으로 구간(110K/90K/61K/49K/37K)을 골랐다. 이번 표는 요금제를 **이름으로 못 박았다**.
그래서 월정액으로 추론하지 않고 `planId` 로만 찾는다 — `rebateOf({ deviceId, planId, join })`.

**요금제 목록의 원천도 이 파일이다.** `phones.PHONE_PLANS` 가 `RATE_CARD.plans` 에서 파생되므로,
화면에서 **단가표에 열이 없는 요금제를 고를 수 있는 경우가 원천적으로 없다.**

```js
export const PHONE_PLANS = RATE_CARD.plans.map((p) => ({ id: p.key, ... }))
```

### 그 외 · 미반영

- 표의 숫자는 **만원 단위**라 파일에서 원으로 환산한다(× 10,000).
- 단말 매핑은 `DEVICE_ROW`. **표에 이름이 없는 모델은 전부 `그 외` 행**으로 떨어진다.
  현재 `그 외` 로 가는 판매 단말: A56 · 아이폰 17 · 17 프로 · 17 프로 맥스.
- 시트에 `그 외` 행이 없어 **각 칸의 최솟값**으로 채워 두었다(결과적으로 아이폰18 P/PM 줄과 같다).
  높게 잡으면 고객 지원금을 과다 약속해 셀러가 손해를 보므로 **낮은 쪽**으로 둔다. 확정값이 오면 그 줄만 교체.
- **인터넷 결합 수수료는 미반영**(`RATE_CARD.excludes`). 고객이 보는 *가족결합 요금할인*(`phones.BUNDLE`)은
  통신요금 할인이라 리베이트와 무관하다 — 둘을 섞지 않는다.
- `plans[].monthly` 는 시트에 없어 월 납부금 계산용으로 채운 값이다. `assumed: true` 인 줄(베이직 4GB = 37,000)은 확인이 필요하며
  어드민 화면에 **확인 필요** 배지로 표시된다.

> **단가표가 바뀌면 `RATE_CARD.plans` 와 `RATE_CARD.devices` 만 교체한다.**
> 요금제 선택지 · 셀프개통 가격 · R/B · 스모크가 함께 갱신된다.

## 2. 셀프개통 — 고정 마진만 남기고 전부 고객에게

```
고객 지원금 = 정책 리베이트 − 회사 고정 마진
할부원금   = 출고가 − 공시지원금 − 고객 지원금
월 납부금  = 할부금(원리금균등) + 요금
```

- 고정 마진은 `db.policies.selfMargin` (기본 **100,000원**), **어드민 > 정책 관리**에서 변경.
- 마진을 바꾸면 온라인구매 목록·상세의 가격이 **자동으로** 따라 움직인다.
- 리베이트가 마진보다 작으면 고객 지원금 0, 마진도 리베이트까지만 — **마이너스 마진을 만들지 않는다**.
- 셀프개통 모드에서는 기존 "추가지원금 = 공시의 15%" 규칙을 **쓰지 않는다**(이중 계상 방지).
  `calcPhoneQuote({ policyMargin })` 에 숫자를 주면 셀프개통 모드, `null` 이면 기존 규칙.

### 검증된 예 (마진 100,000 기준)

| 조합 | 리베이트 | 고객 지원금 | 할부원금 | 월 납부금 |
|---|---|---|---|---|
| Z폴드8 · 번호이동 · 초이스 110 | 470,000 | 370,000 | 2,282,600 | 211,060 |
| S26 · 번호이동 · 초이스 90 | 450,000 | 350,000 | 425,000 | 108,820 |
| 아이폰17프로 · 기기변경 · 초이스 110 (**그 외**) | 270,000 | 170,000 | 1,360,000 | 170,210 |
| Z플립8 · 010 신규 · 베이직 4GB | 0 | 0 | 1,065,000 | 84,150 |

마지막 줄이 바닥 처리다 — 리베이트 0이면 고객 지원금도 마진도 0이고, 음수가 생기지 않는다.

## 3. 사업자 R/B

`/calculator/phone` 상부 R/B 블록이 **같은 단가표**를 읽는다. 근거 한 줄에
단가표명 · 적용일 · **단말 행**(그 외면 `단가표 미수록 → 그 외 적용`) · **요금제명** · 가입유형을 찍는다.

- 단가표가 아는 요금제면 그 값이 곧 단가다 — **0원도 단가표의 답**이므로 데모 단가표로 덮지 않는다(`card.covered`).
- 알뜰폰·렌탈은 단가표에 없으므로 기존 정액표(`commission.js`)로 받친다.
- 등급별로 보이는 줄은 그대로다 — 셀러는 내 수당, 대리점·총판은 건당 영업비, 개인회원은 **블록 자체가 없다**.

## 4. 어드민에서 눈으로 대조하기

**어드민 > 정책 관리**에 단가표 전문이 **시트와 같은 단위(만원)·같은 행 순서**로 올라와 있다(`data-t="rate-card"`).
그 아래에 **판매 단말 → 단가표 행 매핑**이 한 줄로 찍히므로, 매핑이 틀리면 바로 보인다.

## 5. 스모크 (`scripts/qa-ratecard-smoke.cjs`)

| 무엇 | 어떻게 |
|---|---|
| 단가표 값이 엑셀과 같은가 | 어드민 미리보기 대표 4조합 + 표 전문에서 `Z플립8` · `그 외` 행 9칸을 문자열로 대조 |
| 요금제가 단가표에서 나오는가 | 계산기의 요금제 버튼 `data-id` 가 `choice110,choice90,basic4g` 와 정확히 일치 |
| 마진 산식이 맞는가 | `리베이트 − 마진 = 고객 지원금` 직접 검산 + 리베이트 0 조합에서 고객·마진 모두 0 |
| 마진이 가격을 움직이는가 | 마진을 300,000 으로 올리고 온라인구매 실구매가가 **정확히 200,000 상승**하는지 |
| 사업자에게 단가표가 보이는가 | R/B 단가·근거 문구, 가입유형·요금제·단말을 바꿨을 때 다른 열/행을 읽는지, 0원이 0원으로 나오는지 |
| 그 외 처리가 보이는가 | 아이폰17프로 선택 시 300,000 + 근거에 `단가표 미수록 → 그 외 적용` |
| 인터넷 결합 미반영 고지 | 어드민 화면에 `인터넷 결합 수수료` · `미반영` 문구 |
| 개인에게 안 보이는가 | 개인 세션에서 R/B 블록 개수 0 |
