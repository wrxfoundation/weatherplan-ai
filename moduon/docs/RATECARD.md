# 정책 카드 — 단말 가격표 · 셀프개통 마진 · 사업자 R/B

`src/lib/ratecard.js` 한 파일이 **두 개의 표**를 들고 있다. 2차 시트부터 칸의 의미가 바뀌었기 때문이다.

| | 표 | 칸의 의미 | 쓰이는 곳 |
|---|---|---|---|
| `PRICE_CARD` | KT 단말 가격표 K1 (2026-09-18~) | **고객이 내는 단말 판매가(할부원금)** | 요금제 목록 · 소비자 가격 |
| `REBATE_CARD` | KT 정책 단가표 K1 (리베이트) · **직전 수령분** | 리베이트 | 사업자 R/B 전용 |

2차 시트에 리베이트 열이 없어, R/B 가 근거를 잃지 않도록 직전 수령분을 `REBATE_CARD` 로 남겨 뒀다.
새 리베이트 표를 받으면 `REBATE_CARD` 만 교체한다.

## 1. 단말 가격표 (`PRICE_CARD`)

판매가 = **단말 × 요금제 × 가입유형 × 할인방식**

| 축 | 값 |
|---|---|
| 요금제 | 2종 — 초이스 110(유튜브 프리미엄) · 베이직 4GB |
| 가입유형 | 초이스110은 번호이동·기기변경만, 베이직4GB는 010 신규·번호이동·기기변경 |
| 할인방식 | 공시지원 · 선택약정 (시트의 두 열) |
| 단말 | 10종 — 모델명 코드(F776 · F971 · F976 · S942 · S947 · S948 · AIP18P · AIP18PM · A376 · A276) |

### 가격표가 이긴다

가격표에 값이 있으면 **그 값이 곧 할부원금**이다. 출고가 − 공시지원금 − 추가지원금을 계산하지 않는다 —
회사 마진은 이미 가격에 반영돼 있다. 화면의 지원금 줄은 표시용으로 `출고가 − 판매가` 를 역산해
`가격표 반영 할인` 한 줄로 보여 준다(공시 + 15% 두 줄을 쓰지 않는다 · 이중 계상 방지).

### 세 가지 상태

| 상태 | 뜻 | 화면 |
|---|---|---|
| `covered` | 표에 값이 있다 | 그 값이 할부원금. 근거 줄에 `가격표 적용가` |
| `blocked` | 표가 다루는 단말인데 칸이 `X`(또는 그 요금제에 없는 가입유형) | 해당 버튼 **비활성**, 근거 줄에 `취급하지 않는 조합` |
| `unlisted` | 표에 없는 단말 | 기존 경로(출고가 − 공시지원금 − 추가지원금). **임의의 가격을 만들지 않는다** |

- 현재 `unlisted` 인 판매 단말: **A56 · 아이폰 17 · 17 프로 · 17 프로 맥스**.
- 가격표는 **KT 전용**이다. 다른 통신사 견적에는 쓰지 않는다(`carrier` 불일치 시 `unlisted`).
- 단말·요금제를 바꿔 현재 조합이 `blocked` 가 되면, 고를 수 있는 첫 조합으로 자동으로 옮긴다(빈 화면 방지).
- `plans[].monthly` 는 시트에 없어 월 납부금 계산용으로 채운 값이다. `assumed: true`(베이직 4GB = 37,000)는 확인 대기.

> **가격표가 바뀌면 `PRICE_CARD.plans` 와 `PRICE_CARD.devices` 만 교체한다.**
> 요금제 선택지 · 소비자 가격 · 스모크가 함께 갱신된다.

## 2. 셀프개통 고정 마진 — 가격표가 못 채우는 조합에만

```
(가격표 covered)  할부원금 = 가격표 값
(그 외)           고객 지원금 = 리베이트 − 회사 고정 마진
                  할부원금   = 출고가 − 공시지원금 − 고객 지원금
```

- 고정 마진은 `db.policies.selfMargin` (기본 **100,000원**), **어드민 > 정책 관리**에서 변경.
- 가격표가 값을 주는 조합은 이 경로를 **타지 않는다** — 마진이 이미 가격에 반영돼 있다.
- 리베이트가 마진보다 작으면 고객 지원금 0, 마진도 리베이트까지만 — **마이너스 마진을 만들지 않는다**.

### 검증된 예 (24개월 할부)

| 조합 | 근거 | 할부원금 | 월 납부금 |
|---|---|---|---|
| Z폴드8 · 번호이동 · 공시지원 · 초이스110 | 가격표 140만 | 1,400,000 | 171,990 |
| Z폴드8 · 기기변경 · 공시지원 · 초이스110 | 가격표 145만 | 1,450,000 | — |
| S26 · 기기변경 · 공시지원 · 초이스110 | 가격표 42만 | 420,000 | 128,600 |
| 아이폰17프로 · 기기변경 · 초이스110 | **미수록** → 리베이트 25만(아이폰17류) − 마진 10만 | — | — |

## 3. 리베이트 카드 — 사업자 R/B · 셀프개통 지원금의 원천 (2026-10-01 개편)

**집주소** = 통신사 → 정책(차수·적용일) → 표(5G·LTE…) → 단말 행(용량) → 요금구간(하한 월정액) → 가입유형 → (할인방식) ⇒ 금액(원)

- **표(섹션)** — 한 시트에 5G·LTE 표가 따로 있으면(SKT 예시) 표마다 요금구간이 다르다. 카드는 `sections[]` 로 담는다(예전 카드 모양도 `sectionsOf` 로 읽는다).
- **할인방식** — 가입유형 아래가 공통/선약으로 나뉘면 값이 `{ support, select }`. 설계 화면의 할인 방식(단말지원/선택약정)에 맞는 칸을 쓴다. 나뉘지 않은 표(KT K1)는 한 값.
- **용량** — '갤럭시S26 512G' 같은 용량별 행은 `storage: '512GB'` 로, 그 용량을 고를 때만 쓴다. 없으면 용량 없는 행.

- **단말 행**은 시트 표기 그대로(`갤럭시 S26류`) 두고, 그 행에 속하는 우리 단말 id 를 `devices` 에 단다.
  `류`·`(전체)` = 시리즈 전체(S26류 = S26·S26 울트라), 모델번호 목록(`A256, A366`)은 번호로 맞춘다.
  어느 행에도 안 붙은 5G 단말은 대체 행 **그외 5G** 를 쓴다(A56).
- **요금구간**은 이름이 아니라 **하한 월정액**으로 찾는다 — 요금제 월정액 ≥ min 인 가장 높은 구간.
  초이스 110(110,000) → `110K`, 베이직 4GB(37,000) → `37K이상`. 시트마다 구간 이름이 달라도 매핑을 다시 하지 않는다.
- 표가 아는 조합이면 그 값이 곧 단가 — **0원도 표의 답**(`covered`). `X` 는 취급 안 함(`blocked`, 0원).
- 기본값(시드)은 KT **K1 원본 시트**(2026-09-18) 14행 × 5구간. `qa-data-check` ⑥ 이 원본 파일(`scripts/fixtures`)을
  업로드 인식기로 다시 읽어 시드와 같은지 매번 대조한다.
- 다른 통신사 카드가 없으면 KT 카드로 받친다(기존 동작). SKT·LG U+ 시트를 올리면 그 통신사 견적부터 그 값을 쓴다.
- 알뜰폰·렌탈은 표에 없으므로 기존 정액표(`commission.js`)로 받친다.
- 등급별로 보이는 줄은 그대로 — 셀러는 내 수당, 대리점·총판은 건당 영업비, 개인회원은 **블록 자체가 없다**.

### 단가표 업로드 (`src/lib/rebateImport.js` · 어드민 › 정책 관리)

양식을 통일하지 않는다. 시트를 이렇게 읽는다:

1. **가입유형 머리 행** — 010/신규 · MNP/번호이동 · 기변/기기변경 이 3번 이상 나오는 행
2. **요금구간** — 그 위 칸(병합 포함)의 글자에서 하한: `110K` `61K이상` `9만원대` `69,000원`
3. **단말 행** — 머리 행 아래로 값 칸이 절반 이상 찬 행. 첫 값 열 왼쪽의 가장 가까운 글자가 단말 표기
4. **단위** — 시트의 `단위:` 표기, 없으면 크기로 추정(최대 1,000 이하 = 만원)
5. **통신사·차수·적용일·환수 고지** — 시트 이름 › 파일 이름 › 본문(가장 많이 나온 통신사)
6. 표 아래 **인터넷·결합 구역과 그 안내문은 읽지 않는다**(인터넷 결합 수수료 미반영)
7. **표 밖 특별 정책**(추가지원금·부가서비스 가감·USIM 단독·선약 개통 차감·청소년·워치 번들)은 이름만 알리고 계산에 넣지 않는다 — 규칙은 운영팀이 정한다
8. **수식으로 만든 이름 칸**이 빈 칸을 참조해 0 이 되면(LG 예시 `=T7`) 그 행은 이름 없음으로 표시하고, 시트의 절반 이상이 그러면 기본으로 반영에서 뺀다
9. **구간 숫자 vs 적힌 요금제** — '69 이상'에 라이트59 처럼 숫자보다 낮은 요금제가 적혀 있으면 경고(구간을 무엇으로 볼지 운영팀 결정)

검증 파일: `scripts/fixtures/kt-k1-rebate-20260918.xlsx`(KT 원본, 연락처 제거) · `kt-k2-rebate-test.xlsx`(금액 바꾼 사본) · `moduon-sample-skt-lg.xlsx`(운영팀 예시, 금액 임의)

반영 전 미리보기: 인식 결과 · 경고 · **지금 표와 다른 칸 강조** · **바뀌는 R/B(우리 단말 × 요금제 × 가입유형)**.
통신사·차수·적용일·구간 하한·단말 매핑은 화면에서 고칠 수 있고, **고친 매핑은 다음 업로드에 기억**한다
(`db.policies.rebateAliases`, 키 = `통신사|시트 표기`). 적용일이 미래면 **예약**, 잘못 올렸으면 이력에서 **지우기**.
xlsx 는 의존성 없이 읽는다(`src/lib/xlsx.js` — zip + XML). `.xls`·암호 파일은 이유를 말하고 거절한다.

## 4. 어드민에서 눈으로 대조하기

**어드민 > 정책 관리** (`/admin/policies`)

- `data-t="price-card"` — 가격표 전문. **시트와 같은 단위(만원)·같은 행 순서·모델명 코드까지** 그대로. `X` 는 취급 불가.
- `data-t="rate-card"` — 지금 쓰는 리베이트 카드(기본값/업로드 배지) · 판매 단말 → 행 매핑 · 업로드 이력 · 단가표 업로드.
- 각 표 아래 **판매 단말 → 표 행 매핑**이 한 줄로 찍히므로 매핑이 틀리면 바로 보인다.
- **인터넷 결합 수수료는 미반영**(`PRICE_CARD.excludes`)임을 같은 카드에 고지.

## 5. 스모크 (`scripts/qa-ratecard-smoke.cjs`)

| 무엇 | 어떻게 |
|---|---|
| 가격표 값이 엑셀과 같은가 | 어드민 표 전문에서 6개 행을 `모델명,상품명,값 10개` 문자열로 통째 대조 |
| 요금제가 가격표에서 나오는가 | 계산기 요금제 버튼 `data-id` 가 `choice110,basic4g` 와 정확히 일치 |
| 가격표가 실제 가격이 되는가 | 폴드8 번호이동 140만 → 기변 145만 → S26 기변 42만, 할부원금 직접 읽기 |
| 이중 계상이 없는가 | 가격표 모드 내역에 `추가지원금(15%)` 줄 없음 + 15% 토글 비활성 |
| `X` 조합을 막는가 | 010 신규 · 선택약정 버튼 `disabled`, 전 조합 X면 `취급하지 않는 조합` 안내 |
| 미수록 단말 처리 | 아이폰17프로 → `가격표 미수록` 안내 + 방식 제한 없음 + 계산값으로 견적 산출 |
| 마진이 제 자리에만 걸리는가 | 어드민 미리보기 `data-src` 가 가격표 행은 `price`, 미수록 행만 `margin` |
| R/B 가 살아 있는가 | 리베이트 표 470,000 → 기변 430,000, 개인 세션에서 블록 0 |
| 업로드가 실제로 반영되는가 | `qa-rebate-import-smoke` — 같은 파일=변화 없음, 바꾼 파일=바뀌는 5건·강조 3칸, 반영 후 설계 화면 R/B, 매핑 기억, 예약, 지우기, 잘못된 파일 |
| 인터넷 결합 미반영 고지 | 어드민 화면에 `인터넷 결합 수수료` · `미반영` 문구 |
