# 정책 단가표 · 셀프개통 마진 · 사업자 R/B

통신사에서 받은 정책 단가표가 **셀프개통 가격**과 **사업자 R/B** 두 화면을 동시에 굴린다.
같은 표를 읽으므로 두 화면의 숫자가 어긋날 수 없다.

## 1. 단가표 (`src/lib/ratecard.js`)

현재 적용: **KT 동판 단가표 K1 (2026-09-18~ 즉개)**

리베이트 = **기기군 × 요금제 구간 × 가입유형**

| 축 | 값 |
|---|---|
| 기기군 | 14종 (Z플립8 · Z폴드8류 · S26류 · 25류 · 아이폰18P/PM · 아이폰17류 · 아이폰17E · Z플립7 · Z폴드7 · A256류 · A376류 · 그외 5G · LTE 전모델 · SM-A165) |
| 요금제 구간 | 5종 (110K · 90K↑ · 61K↑ · 49K↑ · 37K↑) — 월정액 하한으로 고른다 |
| 가입유형 | 3종 (010 신규 · 번호이동 · 기기변경) — 단가표 열 순서 그대로 |

- 표의 숫자는 **만원 단위**라 파일에서 원으로 환산한다(× 10,000).
- 우리 단말 id → 기기군 매핑은 `DEVICE_GROUP`. 표에 없는 모델은 **그외 5G** 로 떨어진다(0원 방지).
- **단가표가 바뀌면 `RATE_CARD.groups` 만 교체한다.** 셀프개통·R/B·스모크가 함께 갱신된다.

## 2. 셀프개통 — 고정 마진만 남기고 전부 고객에게

```
고객 지원금 = 정책 리베이트 − 회사 고정 마진
할부원금   = 출고가 − 공시지원금 − 고객 지원금
월 납부금  = 할부금(원리금균등) + 요금
```

- 고정 마진은 `db.policies.selfMargin` (기본 **100,000원**), **어드민 > 정책 관리**에서 변경.
- 마진을 바꾸면 온라인구매 목록·상세의 가격이 **자동으로** 따라 움직인다.
- 리베이트가 마진보다 작으면 고객 지원금 0, 마진도 리베이트까지만 — **마이너스 마진을 만들지 않는다**.
- 셀프개통 모드에서는 기존 "추가지원금 = 공시의 15%" 규칙을 **쓰지 않는다**(이중 계상 방지).
  `calcPhoneQuote({ policyMargin })` 에 숫자를 주면 셀프개통 모드, `null` 이면 기존 규칙.

### 검증된 예 (마진 100,000 기준)

| 조합 | 리베이트 | 고객 지원금 | 할부원금 | 월 납부금 |
|---|---|---|---|---|
| Z폴드8 · 번호이동 · 초이스110 | 470,000 | 370,000 | 2,282,600 | 211,060 |
| S26 · 번호이동 · 초이스90 | 450,000 | 350,000 | 425,000 | 108,820 |
| 아이폰17프로 · 기기변경 · 초이스110 | 250,000 | 150,000 | — | 171,100 |

## 3. 사업자 R/B

`/calculator/phone` 상부 R/B 블록이 **같은 단가표**를 읽는다. 근거 한 줄에
단가표명 · 적용일 · 기기군 · 요금제 구간 · 가입유형을 찍어 어디서 온 숫자인지 확인할 수 있다.

- 알뜰폰·렌탈은 단가표에 없으므로 기존 정액표(`commission.js`)로 받친다.
- 등급별로 보이는 줄은 그대로다 — 셀러는 내 수당, 대리점·총판은 건당 영업비, 개인회원은 **블록 자체가 없다**.

## 4. 스모크 (`scripts/qa-ratecard-smoke.cjs`)

| 무엇 | 어떻게 |
|---|---|
| 단가표 값이 엑셀과 같은가 | 어드민 미리보기 표에서 대표 3조합의 리베이트를 읽어 원본과 대조 |
| 마진 산식이 맞는가 | 표의 세 행에서 `리베이트 − 마진 = 고객 지원금` 을 직접 검산 |
| 마진이 가격을 움직이는가 | 마진을 300,000 으로 올리고 온라인구매 실구매가가 **정확히 200,000 상승**하는지 |
| 사업자에게 단가표가 보이는가 | R/B 블록의 단가와 근거 문구, 가입유형·요금제를 바꿨을 때 다른 열/구간을 읽는지 |
| 개인에게 안 보이는가 | 개인 세션에서 R/B 블록 개수 0 |
