# 차량 이미지 연동 (제휴사 에이씨렌트카)

## 지금 상태

차량 카드·상세는 **SVG 실루엣**으로 나온다. 매핑을 채운 차종만 사진으로 바뀌고,
나머지는 그대로 실루엣이라 화면이 깨지지 않는다.

## 왜 핫링크(`<img src="https://acrentcar.com/...">`)를 쓰지 않나

같은 그룹사라 이미지 사용 권한은 문제가 아니다. 문제는 **운영 안정성**이다.

- 우리 트래픽을 제휴사 서버 대역폭이 감당하게 된다 — 우리 방문자가 늘수록 그쪽 비용이 는다
- 그쪽이 경로를 바꾸거나 잠깐 죽으면 **우리 상품 목록이 통째로 빈다**. 우리 배포와 무관하게, 예고 없이
- Referer 차단·CORS 로 조용히 깨지는 사고가 잦다. 브라우저 콘솔에만 남아 한참 뒤에 발견된다

받아서 우리 도메인에서 서빙하면 셋 다 사라진다. 그래서 빌드 시점에 내려받아 자체 호스팅한다.

## 붙이는 법

### 0. 매핑을 자동 생성한다 (권장)

58개를 손으로 적을 필요 없다. 제휴사 목록 페이지에서 뽑아낸다.

```bash
node scripts/map-car-images.mjs https://acrentcar.com/…차량목록페이지
```

네트워크가 막혔거나 이미지가 스크립트로 그려지면, 브라우저에서 목록을 다 띄운 뒤
**저장(Ctrl+S)** 한 HTML 을 넘긴다. CSV(모델명,이미지경로) 도 받는다.

```bash
node scripts/map-car-images.mjs ./saved.html
node scripts/map-car-images.mjs ./list.csv
```

무엇을 찾았고 무엇을 못 찾았는지 전부 출력한 뒤 `cars.js` 의 마커 사이만 다시 쓴다.
`더뉴`·`올뉴`·`신형` 같은 수식어와 공백은 걷어내고 매칭하며, 긴 이름을 먼저 잡아
"그랜저 하이브리드"가 "그랜저"로 잘못 붙지 않는다.

자동 매칭이 틀렸거나 못 잡은 차종은 `MANUAL_IMAGES` 에 넣는다 — 스크립트가 덮어쓰지 않는다.

### 1. (수동) 매핑표를 직접 채운다 — `src/lib/cars.js`

```js
export const PARTNER_IMAGES = {
  'palisade': '00000000461',   // 우리 차종 id : 제휴사 기본 ID
  'grandeur': '00000000498',
  // ...
}
```

우리 차종 id 는 같은 파일 `CAR_MODELS` 의 `id` 다 (`palisade`, `grandeur`, `ioniq5` …).

제휴사 값은 **변형 접미사를 뗀 기본 ID** 다. 제휴사는 한 차량에 이미지 3종을 두는데
(`_list` 썸네일 · `_main` 상세 대표컷 · `_detail_1~3` 갤러리), 접미사는 코드가 붙인다.
`00000000461_list` 처럼 접미사째 넣어도 `baseId()` 가 걷어내지만, 기본형으로 적는 게 맞다.

목록 페이지에 없고 상세만 아는 차종은 `MANUAL_IMAGES` 에 같은 형식으로 넣는다.
`imagePathOf` 는 `MANUAL_IMAGES` 를 먼저 보므로 자동 매칭보다 우선하고,
`map-car-images.mjs` 는 이 블록을 건드리지 않는다. 자동 매칭이 다른 경로를 잡으면
스크립트가 "MANUAL_IMAGES 가 덮어쓰는 차종" 으로 알려준다 — 그때 수동 항목을 지우면 된다.

```js
export const MANUAL_IMAGES = {
  'g80': '00000000612',
  'gv80': '00000000611',
}
```

### 2. 받는다

```bash
npm run build     # prebuild 에서 자동 실행
# 또는 단독으로
node scripts/fetch-car-images.mjs
```

`public/assets/cars/{차종id}.jpg` 로 저장된다. 이미 있으면 건너뛰므로 재실행이 안전하다.
실패한 건은 경고만 남기고 그 차종만 SVG 로 표시된다 — **빌드가 멈추지 않는다.**

### 3. 배포

평소대로 `npm run deploy`. 받아둔 이미지가 산출물에 포함돼 우리 도메인에서 서빙된다.

## 매핑표를 손으로 만들지 않으려면

제휴사에 **차량 목록 + 이미지 경로**를 CSV/JSON 한 장으로 요청하는 편이 빠르다.
그쪽 DB에는 이미 `차량ID · 제조사 · 모델명 · 이미지경로` 가 있을 것이다. 받으면
모델명으로 우리 `CAR_MODELS` 와 자동 매칭해 `PARTNER_IMAGES` 를 생성할 수 있다.

크롤링으로 이 표를 역산하는 것보다 정확하고, 제휴사가 차를 추가할 때마다
다시 훑을 필요도 없다.

## 현재 매핑 상태

현대 20종은 매핑 완료(저장해 주신 목록 페이지에서 자동 생성). 나머지 34종은 아직 없다.

**나머지를 채우려면** 제조사별 목록 페이지를 같은 방식으로 저장해서 한 번씩 돌리면 된다.
스크립트는 마커 사이를 통째로 다시 쓰므로, 여러 브랜드를 한 번에 넣으려면
저장한 HTML 들을 하나로 합쳐서(`cat a.htm b.htm > all.htm`) 넘기는 편이 편하다.

```bash
cat 현대.htm 기아.htm 제네시스.htm 수입차.htm > all.htm
node scripts/map-car-images.mjs ./all.htm
node scripts/fetch-car-images.mjs
```

매핑이 없는 차종은 그대로 SVG 실루엣이라 화면은 정상이다 — 채운 만큼만 사진이 된다.

## 자동 갱신

"오토클래스가 사진을 바꾸면 우리도 자동으로" — 두 층이 있고 성격이 다르다.

| 무엇이 바뀌나 | 필요한 일 | 어떻게 |
|---|---|---|
| 사진 내용만 (경로 그대로) | 이미지 재수집 | `fetch-car-images.mjs` 가 조건부 요청으로 바뀐 것만 받는다 |
| 차종 추가·삭제 (경로가 바뀜) | 매핑 재생성 | `map-car-images.mjs` 를 목록 페이지에 다시 돌린다 |

### 층 1 — 배포할 때마다 최신 (지금 바로 동작)

`npm run deploy` 안의 prebuild 가 `fetch-car-images.mjs` 를 돌린다.
`.manifest.json` 에 ETag·Last-Modified 를 남겨 두고 다음 실행 때 되돌려주므로,
**서버가 304 를 주면 내려받지 않는다.** 제휴사 대역폭을 아끼고 실행도 빠르다.
바뀐 사진만 새로 받아 배포에 실린다.

```bash
npm run deploy                          # 변경분만 갱신 후 배포
node scripts/fetch-car-images.mjs --force   # 검증자 무시하고 전부 다시
```

갱신에 실패하면 **이전 이미지를 유지한다** — 제휴사가 잠깐 죽어도 우리 사이트는 멀쩡하다.

### 층 2 — 사람 없이 주기적으로 (`.github/workflows/car-images.yml`)

매주 월요일 오전 3시(KST)에 목록 페이지를 다시 훑어 매핑을 갱신하고, 바뀐 이미지를
받아 배포한다. 수동 실행(workflow_dispatch)도 된다. 켜려면 두 가지가 필요하다.

1. **`scripts/car-sources.txt` 에 제조사별 목록 페이지 URL 을 채운다.**
   비어 있으면 워크플로는 아무것도 하지 않고 끝난다(지금 상태).
2. **리포지토리 Secrets 에 `VERCEL_TOKEN`.** 없으면 매핑 변경만 커밋하고 배포는
   건너뛴다 — 그 경우 로컬에서 `npm run deploy` 를 한 번 돌리면 된다.

매핑은 텍스트라 리포에 커밋되지만 이미지는 gitignore 라 남지 않는다.
그래서 배포까지 워크플로가 해야 사이트에 반영된다.

## 주의

- 이 컨테이너(개발 세션)는 egress 정책으로 `acrentcar.com` 에 접근할 수 없다.
  다운로드 스크립트는 **로컬에서** 실행해야 한다.
- 스모크가 화면에 제휴사 도메인이 직접 걸리지 않는지 검사한다(핫링크 회귀 방지).
