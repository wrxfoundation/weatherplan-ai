# 구글 플레이 등록 준비 (2026-11-26)

K-CARE(kcarelife.com)를 구글 플레이에 올리기 위해 **앱 쪽에서 미리 해 둘 수 있는 것**을 해 두고,
**회사가 Play Console 에서 직접 해야 하는 것**을 순서대로 적었다.

- 정한 것 · 이유: `../../docs/kcare/decisions/2026-11-26-google-play.md`
- 등록 자료(아이콘 · 대표 이미지 · 화면 7장): `google-play/` 폴더
- 구글 규정은 자주 바뀐다. 날짜가 붙은 항목은 **2026-11-26 에 공식 문서로 확인한 것**이고, 제출 직전에 Play Console 화면의 안내로 다시 확인한다 (출처는 맨 아래).

## 한눈에

| | 상태 |
|---|---|
| 웹 쪽 준비 (아이콘 · 매니페스트 · 오프라인 화면 · 앱-도메인 연결 · 계정 삭제 안내) | **됨** — 이 배포에 들어 있다 |
| 등록 자료 (아이콘 512 · 대표 이미지 1024×500 · 화면 7장) · 등록 문구 초안 | **됨** — 올리기 전에 회사가 확인 (4장) |
| Play Console 답안 초안 (데이터 보안 · 콘텐츠 등급 · 건강 앱 선언 등) | **초안 있음** — 회사가 확인 뒤 입력 (5장) |
| 조직 개발자 계정 (D-U-N-S 번호) | **회사가 할 일** — 가장 오래 걸린다 (1장) |

| 심사용 계정 · 개인정보 처리방침 확정 | **회사가 할 일** (1장) |

## 0. 어떤 방식으로 올리나

K-CARE는 웹앱이다. 플레이에는 **웹을 그대로 여는 안드로이드 앱(Trusted Web Activity · TWA)** 으로 올린다.

- 앱을 열면 주소창 없이 kcarelife.com 이 뜬다. 화면과 기능은 웹과 같다 — **웹을 배포하면 앱도 같이 바뀐다** (앱을 다시 올릴 필요가 없다).
- 그 대신 앱과 도메인이 서로를 확인해야 한다 (3장 '앱-도메인 연결'). 확인이 안 되면 앱이 열리지 않는다.
- 휴대전화에 크롬(또는 TWA 를 지원하는 브라우저)이 있어야 주소창 없이 뜬다.
- **웹에서 안 되는 것은 이 앱에서도 안 된다** — 삼성 헬스 · Health Connect 값 읽기, 백그라운드 알림은 따로 만드는 안드로이드 앱(컴패니언)이 맡는다. 그 앱은 이 문서의 범위가 아니다.
- 애플 앱스토어는 규정 · 심사 방식이 달라 이 문서의 범위가 아니다.

## 2. 이번에 웹 쪽에 넣은 것

| 무엇 | 어디 | 왜 |
|---|---|---|
| PNG 앱 아이콘 4개 (192 · 512, 일반 · 마스커블) | `public/icons/` · `public/manifest.webmanifest` | 안드로이드 앱 아이콘은 PNG 여야 한다. 마스커블은 원 · 둥근 사각으로 잘려도 심볼이 남게 여백을 뒀다 |
| 앱 시작 주소 `/start` | `middleware.js` | 앱을 열면 소개 화면이 아니라 **로그인한 사람은 자기 화면, 아니면 로그인 화면**으로 간다 |
| 오프라인 화면 | `public/sw.js` · `public/offline.html` | 인터넷이 끊겼을 때 빈 화면 대신 안내 · 119 · 고객센터 전화 단추. TWA 품질 기준(끊김 · 없는 주소에서 앱이 죽지 않을 것)에 필요하다 |
| 앱-도메인 연결 주소 `/.well-known/assetlinks.json` | `pages/api/assetlinks.js` · `next.config.js` | 환경변수 두 개만 넣으면 켜진다 (3장) |
| **계정 삭제 안내** `/delete-account` (로그인 없이 열림) | `pages/delete-account.jsx` · `lib/account-deletion.js` | 플레이는 계정을 만드는 앱에 '앱 안에서 지우는 길'과 '**앱 없이 웹에서 삭제를 요청하는 주소**'를 둘 다 요구한다. 앱 안의 길은 내 정보 관리(회원 탈퇴)다 |

서비스 워커는 **오프라인 안내만** 한다 — 화면 · 기록을 저장해 두지 않는다 (옛 화면이 남는 일이 없다).

## 3. 앱 꾸러미(.aab) 만들기 — 패키지 이름을 정한 뒤

회사 PC 에서 한다. **서명 키는 회사가 보관한다** (잃어버리면 업로드 키 재설정을 구글에 신청해야 한다).

1. **이 배포를 먼저 올린다** (kcarelife.com 에 `/manifest.webmanifest` · `/sw.js` · `/start` 가 살아 있어야 한다).
2. https://www.pwabuilder.com 에 `https://kcarelife.com` 을 넣고 → **Package for stores → Android**.
   - Package ID: 정한 패키지 이름 (예: `com.kcarelife.app`)
   - App name `K-CARE` · Launcher name `K-CARE` · Start URL `/start`
   - Signing key: **New** (새로 만들기) — 내려받은 zip 안의 `signing.keystore` · `signing-key-info.txt` 를 안전한 곳에 둔다
   - (명령줄을 쓰는 사람은 Bubblewrap 으로 같은 것을 만들 수 있다: `npx @bubblewrap/cli init --manifest https://kcarelife.com/manifest.webmanifest`)
3. Play Console → 앱 만들기 → **내부 테스트** 트랙에 `.aab` 를 올린다.
4. Play Console 의 **앱 서명** 화면(앱 무결성 메뉴 안)에서 **SHA-256 인증서 지문**을 복사한다 — '앱 서명 키 인증서'의 것은 꼭, 업로드 키의 것도 같이.
5. **Vercel 환경변수 두 개**를 넣고 다시 배포한다.

   | 이름 | 값 |
   |---|---|
   | `ANDROID_PACKAGE_NAME` | 패키지 이름 (예: `com.kcarelife.app`) |
   | `ANDROID_SHA256_FINGERPRINTS` | 4에서 복사한 지문. 여러 개면 쉼표로 잇는다 (`AA:BB:…:FF,11:22:…:99`) |

6. 확인: 브라우저에서 `https://kcarelife.com/.well-known/assetlinks.json` 을 연다 → 패키지 이름과 지문이 보이면 된다 (값이 없으면 `not-configured` 404).
7. 내부 테스트 링크로 휴대전화에 설치해 본다 → **주소창 없이** 로그인 화면이 뜨면 연결된 것이다. 주소창이 보이면 지문이 틀린 것이다.
8. Play Console 의 **App bundle explorer** 에서 **대상 API 수준이 36(Android 16) 이상**인지 본다. 2026-08-31 부터 새 앱은 36 이상이어야 올라간다. 낮으면 도구를 최신판으로 올려 다시 만든다.

> 5를 하기 전에 앱을 설치하면 앱이 바로 닫히거나 주소창이 보인다 — 고장이 아니라 연결 전이라 그렇다.

## 5. Play Console 답안 초안

'앱 콘텐츠' 메뉴의 항목들이다. **앱이 지금 실제로 하는 것**을 기준으로 적었다 — 기능이 바뀌면 답도 바꿔야 한다.

### 5-1. 앱 액세스 권한 — "일부 기능이 제한됨" → 심사용 계정 안내

관제에서 **심사 전용 가족**을 하나 만들어 예시 기록을 넣고, 보호자 · 어르신 계정을 승인해 둔다 (실제 고객 가족을 쓰지 않는다).
아이디 · 비밀번호는 **Play Console 에만** 적는다 (메신저 · 전자우편으로 돌리지 않는다). 심사가 끝난 뒤에도 업데이트 심사 때 쓰이니 지우지 않는다.

## 6. 심사에서 걸릴 수 있는 곳

| 무엇 | 지금 | 권하는 것 |
|---|---|---|
| 처리방침과 양식이 어긋남 | 처리방침이 '안내본'이고 수탁자 이름이 실제와 다르다 | 제출 전에 확정본으로 바꾼다 (1장 6번) |
| 계정을 지워도 가족 기록이 남음 | 남는 것 · 이유 · 삭제 요청 방법을 `/delete-account` 에 적었다 | 구글은 법적 사유 등으로 남기는 것을 **밝히면** 허용한다. '남은 가족의 서비스 제공'을 사유로 둘지 회사가 확정한다 |
| 음성 메시지 30일 삭제 | 30일이 지난 것은 그 가족이 **다음 녹음을 할 때** 지워진다 (정해진 시각에 도는 삭제가 아니다) | 양식 · 처리방침에 '30일 뒤 자동 삭제'라고 적으려면 날마다 도는 삭제를 붙인다 |
| AI 답변 | 보호자 홈에 AI 어시스턴트가 있고, 답변을 신고하는 단추는 없다 | 구글의 AI 생성 콘텐츠 정책은 AI 대화가 중심인 앱에 '앱 안 신고 수단'을 요구하는 것으로 안다 (원문은 이번에 확인하지 않았다 — 제출 전에 확인). 우리는 중심 기능이 아니지만, 지적받으면 신고 단추를 붙인다 |
| 건강 표현 | 화면에 '낙상 의심' · 심박이 나온다 | 등록 문구 · 스크린샷에서 진단처럼 읽히는 표현을 피한다 (4장) |
| 심사자가 로그인하지 못함 | 가입에 승인이 필요하다 | 심사용 계정 (5-1) — 가장 흔한 반려 사유다 |
| 웹 껍데기 앱 | 화면이 웹과 같다 | 주소창 없이 열리고(앱-도메인 연결), 끊겼을 때 안내가 뜨고, 스크린샷이 실제 화면이면 된다 |

## 8. 문제가 생기면

- **앱이 열리자마자 닫힌다 / 주소창이 보인다** — `assetlinks.json` 의 지문이 틀렸거나 환경변수를 넣고 다시 배포하지 않았다 (3장 5~7).
- **오프라인 화면이 이상하다 · 서비스 워커를 끄고 싶다** — `public/sw.js` 의 내용을 아래로 바꿔 배포한다 (설치된 기기에서 스스로 빠진다).

  ```js
  self.addEventListener("install", () => self.skipWaiting());
  self.addEventListener("activate", (e) => e.waitUntil(self.registration.unregister()));
  ```

- **계정 삭제 주소를 바꿨다** — Play Console 데이터 보안 양식의 URL 도 같이 바꾼다.
