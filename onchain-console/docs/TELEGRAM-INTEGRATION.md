# 텔레그램 연동 가이드 — 커뮤니티 운영 대시보드

> **구현 완료.** 이 문서가 설명하는 것은 이제 `server/` 아래에 실제 스크립트로 있습니다.
> 실행 순서는 **`server/README.md`** 를 보세요. 이 문서는 왜 그렇게 만들었는지의 근거입니다.
>
> | 문서의 항목 | 구현 |
> |---|---|
> | 초대 링크 선생성 | `server/bootstrap-invites.mjs` (12종) |
> | 구독자 수 폴링·일별 롤업 | `server/collect.mjs` |
> | chat_member 웹훅 | `server/webhook.mjs` (공개 HTTPS URL 필요) |
> | 화면 연결 | `public/live/community.json` → `src/data/liveSource.ts` |

커뮤니티 대시보드의 텔레그램 지표를 실데이터로 전환하기 위한 실행 순서입니다.
각 지표의 수집 가능 여부는 화면의 **데이터 연동 현황**·**채널 연동 상태** 카드와 일치합니다.

## 0. 준비물
- 텔레그램 공지 채널 1개 + 대화방(그룹) 1개
- BotFather로 생성한 봇 토큰 (`TELEGRAM_BOT_TOKEN`)
- 봇을 **채널·그룹의 관리자**로 추가 (구독자 수 조회·이벤트 수신에 필요)

## 1. Bot API로 바로 되는 것 (추가 개발 없이 수집 가능)

| 지표 | 호출 | 주기 | 비고 |
|---|---|---|---|
| 구독자 수 | `getChatMemberCount` | 5분 | 채널·그룹 각각 |
| 채널 기본 정보 | `getChat` | 1일 | 제목·설명·초대링크 |
| 가입·이탈 이벤트 | Webhook `chat_member` | 실시간 | **`allowed_updates`에 `chat_member` 명시 필요** (기본 미포함) |
| 대화방 메시지·응대 | Webhook `message` | 실시간 | 메시지 수·활성 참여자·미응답 시간 산출 |
| 차단·스팸 처리 | `banChatMember` 등 | 수시 | 운영 액션 기록 |

**유입원 분해(가장 중요)** — `createChatInviteLink`로 채널별 초대 링크를 미리 만들어 두면,
`chat_member` 이벤트의 `invite_link` 필드로 **어느 경로에서 들어왔는지** 정확히 집계됩니다.

권장 링크 세트 (대시보드 "텔레그램 유입원"과 1:1 대응):
- `signup_done` — 사전신청 완료 화면 안내 (최대 유입원)
- `x_profile` — X 프로필 링크
- `linktree` — 링크트리
- `weather_app` — 날씨앱 알림·홈페이지
- `partner_flare` / `partner_tl` — 외부 파트너 소개용 (파급 효과 측정)

> 초대 링크를 미리 나누지 않으면 유입원 분해는 **사후 복원이 불가능**합니다. 채널 개설 시점에 함께 만들어 두세요.

## 2. Bot API로 안 되는 것 (별도 작업 필요)

| 지표 | 사유 | 대안 |
|---|---|---|
| 게시물별 조회수 | Bot API 미제공 | MTProto 클라이언트(TDLib/Telethon)로 채널 메시지 `views` 조회 |
| 채널 통계 그래프 | Bot API 미제공 | MTProto `stats.getBroadcastStats` (구독자 수 조건 충족 시) |

MTProto는 **사용자 계정 세션**이 필요하므로, 운영 계정 하나를 읽기 전용으로 분리해 사용하고
세션 파일은 서버 시크릿으로만 보관하세요.

## 3. 다른 채널
- **X**: 무료 티어는 읽기가 사실상 막혀 있습니다. 팔로워·노출·참여는 당분간 **수동 입력**하거나 유료 티어를 검토하세요.
- **링크트리**: 공개 API가 없습니다. 모든 링크에 **UTM 파라미터**를 붙이고 GA4로 클릭을 집계하세요.
- **검색어**: 네이버 데이터랩 API(검색어 트렌드) + 구글 서치콘솔 API(실제 유입 검색어·노출·CTR) 조합.
  대시보드의 "주의 검색어"(투자·에어드랍·사칭)는 서치콘솔 쿼리에서 키워드 규칙으로 분류합니다.

## 4. 수집 주기·보관
- 실시간 이벤트는 Webhook으로 받아 원본 저장 → 일 단위 롤업
- 구독자 수처럼 스냅샷 성격인 지표는 5분 간격 폴링 후 **일별 최종값**만 보관
- 대시보드의 기간 필터(오늘·어제·3·7·14·30일)는 **일별 롤업**을 합산하는 구조이므로,
  일별 순증 값만 정확히 쌓으면 모든 기간이 자동으로 맞습니다

## 5. 주의
- 봇 토큰·MTProto 세션은 서버 환경변수로만 관리하고 프론트에 노출하지 않습니다
- 대화방 메시지 원문을 저장할 경우 개인정보 처리 방침에 수집 항목·보관 기간을 명시해야 합니다
- 공지 채널은 **하루 3회 이내** 발행 규칙이 있으므로, 대시보드의 공지 카운터로 초과 발행을 방지합니다
