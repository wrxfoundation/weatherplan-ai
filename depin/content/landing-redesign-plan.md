## 0-B. 전략 프레임 — 랜딩이 갖는 4가지 상태

판매 기간이 짧고(9/15~30) 수요는 커뮤니티에서 밀어넣는 구조이므로, **판매 랜딩은 고정 페이지가
아니라 시점별로 전환되는 판매 머신**으로 설계한다.

| 상태 | 기간 | 랜딩 히어로 CTA | 비고 |
|---|---|---|---|
| S1 티저 | ~9/14 | 「출시 알림 받기」(이메일) | 카운트다운, 커뮤니티 채널 링크 |
| S2 판매 중 | 9/15~매진 | 「지금 구매」+ 실시간 잔여 카운터 | 본 기획의 중심 |
| S3 매진 | 매진 순간~ | 「2차 대기 등록」 자동 전환 | §7 대기페이지로 연결 |
| S4 2차 판매 | 10/3~ | 우선권자 선오픈 → 일반 오픈 | 점수화 우선권 적용 |

핵심 동선: **커뮤니티(X·텔레그램·XRP KOREA 채널)에서 유입된 방문자가 3분 안에 결제 완료**까지
가는 것. 모든 섹션은 이 동선을 방해하지 않는 순서로 배치한다.

## 2. 판매 랜딩 IA (S2 판매 중 기준)

1. **히어로** — 제품 렌더(공식 투명 PNG) + 한 줄 카피 + **실시간 잔여 수량/제네시스 넘버 진행
   바**(#0101→#5000) + 「지금 구매」. 잔여 카운터가 마중물 심리의 엔진 — 반드시 실데이터 연동.
2. **가격 블록** — 얼리버드 #0101~1000 **450 RLUSD** / 기본 #1001~5000 **650 RLUSD**. 제네시스
   넘버가 라이선스 NFT에 영구 기록됨을 강조(조기 구매 = 낮은 넘버 = 유일한 희소 요소. 수익
   암시 금지 — FAQ Q13/Q22 톤 준수).
3. **작동 원리 3단계** — 측정(공기질) → 검증(품질 평가) → 보상(WLBN 적립). 인포그래픽 1장.
4. **신뢰 블록** — 기술 파트너 표기(8/27 명문화 결과 종속), XRPL·XLS-20/30, 성능인증 표기
   (부처 개편 반영 여부 8/28 인쇄 건과 통일).
5. **FAQ 발췌 6문항** (전체 23문항 페이지 링크) — Q5 환불·Q10 XRP 지원·Q13 보상 원칙 필수 포함.
6. **푸터** — 이용약관·환불 약관·개인정보처리방침·이용자 보호 센터·사업자 정보(판매 주체 표기,
   8/27 종속).

## 3. 구매·결제 플로우 (RLUSD, PG 없음 — 온체인 직접 결제)

```
① 수량 선택 (1인 제한 정책 확인 필요 — 기본안: 지갑당 최대 N대)
② 지갑 연결 (간편 웹3 지갑 내장 / D'CENT 인앱 브라우저 자동 감지 — 기존 온보딩과 동일 스택)
③ 배송 정보 입력 + 이메일 인증 (§4)
④ 약관 동의 — 환불 제한 사유 개별 체크박스 (§5, 법 제17조 제6항 사전표시)
⑤ 결제 (아래 A/B)
⑥ 주문 확정 — 확인 이메일 발송 + MY 주문 생성 + 제네시스 넘버 배정
```

**결제 방식 A (권장)**: 연결된 지갑에 **Payment 트랜잭션 서명 요청** — 금액·수신 주소·Destination
Tag(주문번호)를 사이트가 자동 구성, 사용자는 서명만. 간편지갑·D'CENT 모두 지원 가능.
**결제 방식 B (폴백)**: 수신 주소 + Destination Tag 표시 → 수동 송금 → 원장 감지로 자동 확정.
외부 지갑·거래소 직송용. **주의: 거래소 출금은 Destination Tag 누락 사고가 잦음 — 경고 문구 필수.**

예외 처리 설계: 결제 창 타임아웃(재고 홀드 15~30분) · 금액 불일치(부족분 안내/초과분 반환 절차) ·
RLUSD 트러스트라인 부재 감지 시 설정 가이드 · **RLUSD 미보유자 → 「원화로 준비하기」 구매 가이드
링크**(업비트 KRW 페어 → XRPL판 출금 경로 — 기확인 팩트).

## 4. 이메일 연동 — 개인정보 최소화 원칙

- **수집 4항목만**: 이메일(인증 코드 확인) · 수령인명 · 배송 주소 · 연락처. 그 외 수집 금지.
- **지갑 = 계정, 이메일 ≠ 로그인.** 이메일은 배송·CS 연락 전용. 온체인 데이터(지갑·결제)와
  배송 데이터(개인정보)를 분리 보관 — 유출 시 상호 연결 최소화.
- 마케팅 수신 동의는 **별도 옵트인**(기본 해제). 배송 완료 후 보존 기한 명시(전자상거래법 기록
  보존 의무와의 조화는 법무 확인 항목).
- 2차 대기 등록(§7)도 동일 원칙: 이메일+지갑주소만.

## 6. 주문 조회(랜딩 내 관리) — 구매 관리 기능

진입: 지갑 연결 또는 이메일+주문번호 (플랫폼 MY와 별개 — 랜딩이 자체 보유).

- **주문 카드**: 상태(결제 확인 → 배송 준비 → 발송[송장] → 완료) · 제네시스 넘버 · 결제 트랜잭션
  해시(익스플로러 링크) · 수량.
- **리딤 상태**: 미사용 / 사용(NFT 발급 일시) — **환불 가능 여부를 자동 표시**(7일 창 카운트다운 +
  제한 사유 발생 시 사유 명시. 판정 로직 = 온체인 NFT 발급 기록 조회, 약관과 동일 기준).
- **환불 요청 폼**: 사유 선택 → 접수 → CS 파이프라인(단일 1선 데스크 모델)로 라우팅.
- 배송 주소 변경(발송 전 한정) · 리딤코드 도용 신고(무효화·재발급 절차 진입점 — 플랫폼 어드민
  기능과 세트).

## 7. 2차 대기페이지 — 1차 사전신청 시스템 재활용 (v1.2 전면 교체)

**원천 자료 수령(8/25)**: ① `kw_event_plan_selfhosted_20260817.pdf` — 서우 설계 참여 이벤트
운영안(자체 호스팅: 미션·응모권·순번·S그룹 추첨을 사전신청 페이지 안에서 전부 처리, 외부 도구
배제) ② `wellbian_promo_package_4.zip` — 실제 구축 페이지(index/apply/done/me/invite + wb.js).
**v1.1의 임의 배점표·검증 3옵션은 폐기** — 1차 운영안의 이원 구조와 자진 체크 철학이 우선
(현장 설계 우위). 2차는 이 시스템의 문안·일정 치환판으로 만든다.

- **낙수 효과 목표 계승 (케이웨더 포함)**: 이벤트의 목적 = 경품이 아니라 접점 6개(번호 → 번호+
  커뮤니티+채널 구독+자발 확산+판매 후 유지). **케이웨더 유튜브·인스타가 미션에 포함되어 케이웨더
  채널도 낙수 효과를 누리는 구조**(1차 목표 계열: 케이웨더 채널 +1,000명).
- **이원 구조 계승**: **응모권(추첨 확률)** — 대기 등록 완료 10 · 소식 공유 6 · 커뮤니티 참여 5 ·
  케이웨더 앱 설치 5 · 친구 초대 5/명(상한 10명) · X 팔로우 3 · **케이웨더 유튜브 구독 3 ·
  인스타 팔로우 2** · 매일 방문 1 / **순번 점수(그룹 확정)** — 등록 100 · 구매 의사 20 · 커뮤니티
  20 · 초대 30. 순번엔 검증 가능 항목만, 팔로우·구독은 응모권만(순번 무관).
- **S그룹 구조 계승**: 미션 완료자 중 응모권 가중 추첨 1,000명 = 2차 판매일(10/3) 최선 구매 그룹.
  미당첨자는 순번 점수로 A/B 자동 편입("떨어져도 완전히 잃지 않음"). 추첨 시드 마감 전 공개 =
  재현 가능한 공정성.
- **검증 철학 계승**: 팔로우·구독은 어떤 도구로도 통제 불가 → **자진 체크 + 저배점 + 화면 고지**
  ("완료 여부는 직접 체크하시는 방식이며, 사실과 다른 경우 해당 응모권은 인정되지 않습니다").
  시스템 검증은 우리 DB 항목만(등록·초대 본인확인·앱 가입 번호 대조).
- **어뷰징 3방어 계승 (시작부터 ON)**: 초대 상한 10명 · 동일 기기/통신망 초대 미인정 · 단시간
  대량 초대 보류 후 확인 — 2차도 구매 순서가 걸려 판돈이 큼.
- **1차 → 2차 치환표**:

| 1차 요소 | 2차 적용 |
|---|---|
| 접수 8/25~9/12 · 판매 9/15 | 접수 = 1차 매진 시점~9/30 · 판매 10/3 (**"마감은 판매 사흘 전" 원칙 유지 → 마감 9/30**) |
| 미션 필수 = 사전신청 완료 | 2차 대기 등록 완료 |
| 중간 추첨 9/5 (참여 하락 방지) | 접수 중반 1회 재산정 |
| S→A→B→일반 오픈 (9/15) | S→A→B→일반 오픈 (10/3) |
| 페이지 5종 + wb.js CONF | 그대로 이식 — deadline·links·문안만 교체 |

- **계층 설계 (권고 8/25 — 결정 대기)**: 2차 10,000대에도 **S/A/B/일반 그대로 계승** — 물량
  2배 = 매진 압력 절반이라 계층 추가는 경계 분쟁 표면적만 늘림(1차의 "추첨 = 다툼 제거" 철학
  역행), S/A/B는 이미 학습된 언어(문구·CS·wb.js 재사용), 이월자도 점수 유지로 A/B 자동 흡수.
  신설 파라미터 2개만 결정: ① **S 정원** — 1,000 유지 권장(희소성 보존, 상한 2,000) ② **현장/
  온라인 물량 분리** — 10/3 행사장 부스 판매는 그룹 밖이므로 사전 배분(예: 현장 500~1,000대)
  + 미소진분 온라인 반환. 미분리 시 "S인데 현장보다 늦다" 모순. XRP KOREA 채널분은 리퍼럴
  트래킹 축으로 온라인 풀 내 처리(계층 아님).
- **이월 정책 (결정 필요)**: 1차 사전신청 참여자의 점수·응모권을 2차로 이월할지. 운영안 취지
