# Measured Room — 집 하나의 공기 시뮬레이션 (v0.3, 2026-09-02)

서우 제안: "실내 공간에 디바이스로 공기 측정하는 것을 시뮬레이션하는 VR 월드". 단일 HTML(Three.js r128, cdnjs) —
거실·침실·부엌 세 공간, 상황(요리·창문·밤)마다 바뀌는 장면 사진 위에 기기(GLB)·먼지·김·바람을 투명 3D 레이어로 얹고,
PM2.5·CO₂가 변하면서 5분마다 기록 하나가 쌓인다.

- 용도: 10/3 부스 화면(터치), 랜딩 데모, 키노트 클립 소재. 캡션은 항상 "개념 시뮬레이션 · concept render".
- 규칙: 화면에 공기질 등급 라벨 없음(곡선·숫자만) · 토큰·코인 아이콘 없음 · "보상은 테스트 중" 고정 문구 · 실물 사진 대체 아님 · 공식 공개 전 `noindex`.

| | v0.2 | v0.3 |

| 기기 | 절차적 모형(GLB 는 파일 있어야) | 제품 GLB(경량화 1.6MB, 텍스처 1024·메시 단순화)를 CDN 에서 바로 불러와 사진 속 콘솔·협탁·조리대 위에 접지 그림자와 함께 합성, 화면엔 실시간 곡선 |

| 모바일 | 오버레이가 겹침 | 세로 화면은 제목·탭·장면·수치·버튼·기록 순으로 쌓는 레이아웃, 가로 넓은 화면은 사진 위 오버레이 |
| 카메라 | 드래그 오빗 | 사진 기반이라 오빗 없음. 마우스 시차(사진은 조금, 기기는 반대로) |

## 공간과 상황

| 공간 | 버튼 | 사진 상태 | 공기 |
|---|---|---|---|
| 거실 | 창문 열기/닫기 · 밤 지나기 | 저녁(기본) / 창 열림 / 밤 | 저녁엔 사람 숨으로 CO₂ ↑, 창 열면 ↓. 부엌 연기가 조금 넘어온다 |
| 침실 | 창문 열기/닫기 · 밤 지나기 | 저녁 / 밤 / 아침(창 열림) | 밤(23~07시) 닫힌 방에서 CO₂ 가장 높음, 아침에 창 열면 ↓ |
| 부엌 | 요리 시작(10분) · 창문 열기/닫기 · 밤 지나기 | 대기 / 조리 중 / 환기(창 열림) / 밤 | 조리 10분에 PM2.5 급상승, 창 열면 빠짐 |

세 공간이 같은 시계를 쓴다(1초 = 1분, 밤엔 1초 = 12분, 06:30 까지). 기록은 공간마다 5분에 하나, 아래 띠는 지금 공간, 숫자는 지금 공간 / 집 전체.

장면을 바로 열려면 해시: `#space=kitchen&cook=1` · `#space=bedroom&night=1` · `#space=living&window=1` (부스 QR·링크용).

## Vercel 배포 (정적 사이트, 빌드 없음)

```
cd measured-room
vercel --prod
```
- 첫 실행에서 프로젝트 이름은 `wellbian-measured-room`, 프레임워크는 Other, 빌드 명령·출력 디렉터리는 비워 둔다(루트의 index.html 을 그대로 서빙).
- **자산 파일을 따로 넣지 않아도 된다.** 사진 10장과 기기 GLB 는 힉스필드 CDN(CORS `*`, 1년 캐시)에서 바로 불러온다.
- 오래 쓸 배포(공식 공개·부스 오프라인)라면 `sh fetch-assets.sh` 로 `assets/` 에 받아 두면 그쪽을 먼저 쓴다(자세한 것은 `assets/README.md`).
- 외부 의존: three.js(cdnjs) · GLTFLoader(jsdelivr) · Google Fonts. 부스 현장 와이파이가 막히면 두 스크립트를 폴더에 넣고 `<script src>` 를 로컬 경로로 바꾼다.

## 자산 좌표를 손보고 싶을 때

`index.html` 의 `SPACES` 에 공간마다 사진 안 비율 좌표가 있다: `device{u,v,w}`(기기 발 중심, 사진 너비 대비 기기 너비), `pan`(김 나오는 곳), `window`(바람 시작점), `focus`(모바일에서 사진을 어느 쪽 중심으로 자를지).
사진을 새로 만들면 이 숫자만 맞추면 된다. 기기 GLB 정면은 +z(로고 면) — 다른 모델이면 `DEVICE.yaw` 로 돌린다.
