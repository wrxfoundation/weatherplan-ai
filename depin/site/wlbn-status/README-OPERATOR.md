# WLBN 워치(가칭) — 운영 안내

웰비안 WLBN의 원장 기록을 읽어 정리해 보여 주는 화면을, 요금제에 따라 구역을 열어 주는 구독 서비스로 운영하기 위한 묶음이다.
`scripts/build-watch.js` 가 만든 폴더이며, 이 폴더째로 배포한다.

## 무엇을 파는가

| 요금제 | 월 | 연(2개월 무료) | 여는 구역 |
|---|---|---|---|
| 무료 | 0원 | — | 한눈에 · 위치 · 네트워크와 시장 · 읽는 법 |
| 라이트 | 1,900원 | 19,000원 | + 지표 모아보기 · 오늘의 현황 · 설계 대조(잠금 해제 달력) |
| 스탠더드 | 4,900원 | 49,000원 | + 시장과 견주기 · 매매 · 날짜별 흐름 · 풀 두 곳(계산기) · 지갑별 표 · 날짜 지정 |
| 프로 | 9,900원 | 99,000원 | + 회사 표시 계정의 움직임 · 지갑의 생태계 기여 · 온체인 심층 · 지갑 분포 |

- 가격과 구역 나눔은 `lib/edition.js` 의 `PLANS` · `SECTIONS` 한 곳에 있다. 바꾸려면 여기만 고친다.
- **자료는 서버가 걸러서 준다.** 잠긴 구역의 자료는 응답에 들어 있지 않다. `public/snapshot.json`(누구나 받을 수 있다)에는 무료만큼만 들어 있다.
- 상품판에 내지 않는 것: 부정 쪽 지갑 자금 추적 · 이전 풀 기간 표 · 발표 모드 · 지갑의 전체 주소. `EDITION=watch` 이면 `SHOW_ADDR` · `SHOW_BEFORE` 를 켜도 나가지 않는다.
- 이용권은 요청 머리(Authorization)로만 간다. 주소에는 넣지 않는다(주소는 기록에 남는다) — 주소에는 이용권을 알아낼 수 없는 짧은 꼬리표(`k=`)만 붙어 무료 응답의 보관본과 섞이지 않게 한다.
- 유료 요금제의 응답은 함께 쓰는 보관본에 두지 않는다(`private, no-store`). 무료 응답만 15분 보관된다.

## 배포(Vercel)

1. 이 폴더를 새 프로젝트로 올린다(빌드 명령 없음 · 출력 폴더 `public`).
2. 환경변수를 넣는다.

| 이름 | 값 |
|---|---|
| `EDITION` | `watch` — 이 묶음은 넣지 않아도 상품판으로 돈다(묶음 안의 `lib/edition-on.json` 이 고정한다). 그 파일이 빠졌을 때를 대비해 넣어 둔다 |
| `WATCH_SECRET` | 이용권 서명 열쇠. 24자 이상의 무작위 글. 어디에도 적어 두지 않는다 |
| `WATCH_NAME` | 서비스 이름(없으면 「WLBN 워치」) |
| `WATCH_OPERATOR` | 운영 주체 이름 — 화면 아래 고지 줄에 나온다 |
| `WATCH_PAY_URL` | 결제 화면 주소(요금제 창의 「구독하러 가기」) |
| `WATCH_ORIGIN` | (선택) 고지 줄에 덧붙일 한 문장 — 예: 누가 만든 도구인지 |
| `BLOB_READ_WRITE_TOKEN` | Vercel Blob 을 연결하면 생긴다. 없으면 배포에 든 자료에서 매번 이어 받는다 |
| `CRON_SECRET` | 넣으면 매일 예약 실행(`/api/refresh`)을 Vercel 만 부를 수 있다. 넣어 두기를 권한다 |

3. 배포 뒤 주소를 열어 「무료」 줄과 잠긴 구역이 보이는지 확인한다. **「무료」 줄이 없으면 상품판으로 돌고 있지 않은 것이다(`lib/edition-on.json` 과 `EDITION` 이 모두 빠짐) — 그 상태로는 모든 자료가 누구에게나 나간다. 바로 내린다.**
4. 이용권을 하나 만들어 넣어 보고(아래), 그 요금제의 구역이 열리는지 확인한다.

자료는 화면을 열 때 원장에서 이어 받고, 매일 한 번 예약 실행(`vercel.json`)이 무거운 것(잠금 해제 일정 등)을 다시 읽는다.
배포에 넣어 둔 출발 자료를 새로 당기려면 `node scripts/refresh-snapshot.js`(인터넷 필요 · 몇 분) — 이 묶음에서는 `public/snapshot.json` 을 무료만큼만 남겨 쓴다.

## RLUSD로 받기(XRP Ledger)

요금제 창에서 요금제와 기간(1개월 · 1년)을 고르면 받는 주소 · 태그 · 금액이 나온다. 구독자가 그대로 보내면 서버가 원장에서 입금을 찾아 이용권을 만들어 주고, 화면이 스스로 열린다(10초마다 확인). 이용권을 손으로 보낼 필요가 없다.

| 이름 | 값 |
|---|---|
| `WATCH_PAY_ADDRESS` | RLUSD 를 받을 XRP Ledger 주소. **RLUSD 신뢰선이 있어야 받을 수 있다.** 한 글자라도 틀리면(검사 글자가 맞지 않으면) 결제가 켜지지 않는다 |
| `WATCH_KRW_PER_RLUSD` | 1 RLUSD 를 몇 원으로 칠지(없으면 1,400 — 가정값이니 정해서 넣는다). 원화 정가를 이 값으로 나눠 센트 단위로 올린다 |
| `WATCH_PAY_DEMO` | `1` 이면 결제 데모 — 「데모 결제」 단추가 보낸 것으로 치고 30분짜리 이용권을 준다. **실제 운영에서는 넣지 않는다(켜 두면 누구나 무료로 연다)** |

- 값(1,400원 기준 · 월 / 연): 라이트 1.36 / 13.58 · 스탠더드 3.50 / 35.00 · 프로 7.08 / 70.72 RLUSD.
- 기간: 1개월 = 31일 · 1년 = 366일. 끝나는 때 = 입금 시각 + 기간.
- **서버는 주문을 기억하지 않는다.** 주문은 서버가 서명한 글로 구독자의 기기에 있고, 확인을 청할 때 내민다. 입금 시각으로 끝나는 때를 정하므로 몇 번을 물어도 같은 이용권이 나온다.
- 태그는 원장에 공개되지만, 그 태그가 든 서명 주문이 있어야 이용권을 받는다 — 원장을 지켜보는 사람이 남의 입금으로 받아 가지 못한다. 대신 기기를 바꾸거나 기록을 지워 주문 글을 잃으면 화면에서 확인할 수 없다 → 거래 해시를 받아 원장에서 확인하고 `mint-token.js` 로 손수 만들어 준다.
- 받은 양은 거래에 적힌 금액이 아니라 실제로 들어온 양으로 본다(부분 결제로 적게 보내고 많이 보낸 척하는 것을 막는다). 같은 이름을 쓴 다른 발행자의 토큰 · XRP · 금액이 모자란 입금 · 태그가 없거나 다른 입금은 찾지 못한다 — 이런 입금은 손으로 처리한다(되돌려 주기 포함).
- 거래소에서 보내는 구독자는 출금 화면의 태그(메모) 칸에 태그를 넣어야 한다.
- 확인 요청 한 번마다 공개 원장 서버를 한 번 부른다(`XRPL_NODES` 로 바꿀 수 있다).
- 결제 데모만 보여 주려면 `WATCH_PAY_DEMO=1` 만 넣고 `WATCH_PAY_ADDRESS` 는 비운다 — 받는 주소 자리에 「데모 — 받는 주소 없음」이 나오고 원장을 보지 않는다.
- 되돌려 주기 · 세금 계산 · 가상자산으로 대금을 받는 일의 법률 검토는 운영자 몫이다.

## 이용권 손으로 건네기

RLUSD 결제를 켜면 이용권은 스스로 나간다. 아래는 다른 방법으로 결제를 받았거나, 입금은 됐는데 화면에서 확인하지 못한 구독자에게 손으로 줄 때 쓴다. 구독자는 화면의 「요금제 · 이용권」에 붙여 넣는다.

```
WATCH_SECRET=<서버와 같은 열쇠> node scripts/mint-token.js std 31 "메모"
WATCH_SECRET=<서버와 같은 열쇠> node scripts/mint-token.js pro 366
```

- 요금제 `lite` · `std` · `pro`, 뒤의 숫자는 일수.
- 이용권에는 요금제와 끝나는 날만 들어 있다. 서버는 회원 정보를 두지 않는다.
- 이용권은 옮겨 쓸 수 있다(한 사람이 여러 기기에서 쓸 수 있고, 남에게 줄 수도 있다). 막으려면 회원 로그인이 필요하다 — 이 묶음에는 없다.
- 열쇠를 바꾸면 앞서 낸 이용권이 모두 무효가 된다(유출됐을 때 쓰는 방법).

## 지키는 선

- 공개 원장과 공개 사이트의 값만 쓴다. 공개되지 않은 정보를 넣지 않는다.
- 매매를 권하지 않고 가격을 전망하지 않는다. 가격에는 판정 표시를 붙이지 않는다.
- 「보상의 지급량과 가치는 보장되지 않는다」는 문장을 지우지 않는다.
- 웰비안 · 케이웨더의 공식 서비스가 아니라는 고지를 지우지 않는다. 누가 만들고 누가 운영하는지 사실대로 적는다.
- 지갑의 전체 주소는 내지 않는다(`SHOW_ADDR` 를 켜지 않는다).

## 이 묶음에 없는 것(다음에 붙일 것)

- 회원 로그인 · 자동 갱신(기간이 끝나면 다시 결제한다) · 카드 결제 — RLUSD 결제는 들어 있다(위)
- 내 지갑 등록(요금제별 1 · 3 · 10개)과 지급 알림 · 텔레그램 알림
- 주간 리포트 · 보상 내역 내려받기(세금 신고용) · 영문판

## 확인된 것과 확인되지 않은 것

- 확인: 이용권 검증(가짜 여섯 가지 · 기간 끝남) · 요금제별로 걸러진 자료 · 화면의 잠금과 이용권 적용 · 휴대폰 화면 — 원장을 받지 않는 점검용 서버와 실제 핸들러(`api/data.js` · `api/refresh.js`)를 직접 불러 확인했다.
- 확인(RLUSD 결제): 주문 서명 · 입금 찾기(어긋난 경우 여덟 가지 · 부분 결제 · 여러 쪽 기록) · 화면의 결제 단계 — 가짜 원장을 끼운 점검으로. 실제 공개 원장의 기록(RLUSD 입금 13건)을 같은 코드로 읽어 꼴이 맞는 것도 확인했다(읽기만 했다).
- 확인되지 않음: Vercel 에 `EDITION=watch` 로 올린 실제 배포 · **실제로 RLUSD 를 보내 본 결제(한 번도 보내지 않았다)**. 올린 뒤 위 3 · 4번을 해 보고, 결제를 열기 전에 작은 금액으로 한 번 보내 본다.

## 운영자가 따로 챙길 것

- 유료 서비스 운영에 필요한 신고 · 약관 · 환불 규정 · 개인정보 처리방침.
- 가상자산 정보를 유료로 제공하는 데 따른 법률 검토.
- 이 코드를 쓸 수 있다는 허락은 코드 주인과 따로 정한다 — 이 묶음에는 허락 문서가 들어 있지 않다.
