# 사이트 전체 UX·논리 점검 (2026-08-29)

추첨제(사전 구매응모) 전환 직후, 전 상태·전 페이지를 실제로 렌더해서 텍스트를 뽑고
"이 화면이 지금 무엇을 할 수 있는지 스스로 말하는가"를 기준으로 점검했다.
점검 대상 11개: 랜딩 4상태(pre · dday · sale · sold_out) + eb_closed + me + me/waitlist +
waitlist 3종 + orders.

## 요약

가장 큰 구멍은 **추첨제로 바꿔놓고 판매 계열 화면은 그대로**였다는 것.
응모하지 않은 사람이 판매 화면에 들어오면 그냥 살 수 있는 줄 알고 결제까지 갔다가 막힌다.
이번에 고쳤다. 나머지는 판단이 필요한 항목이라 아래에 남긴다.

## 고친 것 (커밋 814748b)

| # | 화면 | 문제 | 조치 |
|---|---|---|---|
| 1 | sale | 추첨 당첨자만 살 수 있는데 안내가 **전혀 없었다**. "지금 구매하기"만 있었음 | 히어로에 상태 배너 + 미구매분 전환 고지. 가격 카드에도 같은 상태 한 줄(히어로를 지나쳐 내려온 사람용) |
| 2 | dday | "예약하면 9월 15일에 여유 있게 구매" — 추첨제에서 **거짓 약속** | "추첨 결과 9월 14일 · 당첨 시 9월 15일 구매" |
| 3 | sold_out | "1차 물량이 모두 판매되었습니다" — 추첨과 무관해 보임 | "당첨자 구매분과 일반 구매 전환분이 모두 소진되었습니다" |
| 4 | GNB | 프리뷰 칩 "완판 화면 보기" | "판매 마감 화면 보기" |
| 5 | 랜딩 | 비보장 고지가 FAQ 안에만 있었음 | ③ 보상 카드로 이전 (본문 노출 확보) |

신규 문구는 5개 언어 모두 채웠다.

## 판단이 필요한 것

### 1. 응모 마감일이 어디에도 없다 ⚠️

지금 화면이 말하는 일정은 이렇다.

```
9/5   사전 구매응모 오픈
9/14  09:00 KST  추첨 결과 메일
9/15  당첨자 구매
```

**"언제까지 응모하면 되는지"가 빠져 있다.** 9/14에 추첨하려면 그 전에 응모가 닫혀야
하는데(9/13?), 사용자는 마감일을 알 수 없다. 지금은 D-day 배지가 "판매 오픈 D-17"만
가리켜서, 응모하러 온 사람이 보는 카운트다운과 실제로 지켜야 할 마감이 어긋난다.

→ **응모 마감일을 정해주시면** 히어로 D-day 배지와 * 주석에 반영하겠다.
   (마감 개념 자체를 두지 않고 "9/13 자정까지" 같은 문장만 넣는 것도 가능)

### 2. 마이페이지·주문조회의 "11월 순차 발송"

랜딩 배송 캡션에서는 지시대로 "11월 중 순차 배송 예정"을 뺐는데,
`/me`와 `/orders/[id]`에는 그대로 있다.

- **남기는 쪽 논리**: 이미 구매한 사람에게 배송 일정은 필요한 정보다
- **빼는 쪽 논리**: 확정 전 일정이라 랜딩에서 뺐다면 여기도 같은 이유가 적용된다

→ 랜딩에서 뺀 이유가 "확정 전이라서"이면 여기도 빼는 게 맞다. 알려주시면 정리하겠다.

### 3. 마이페이지 목값이 650 RLUSD

1차 판매가는 450인데 마이페이지 주문 카드는 650(2차가)으로 되어 있다.
데모 데이터라 실구현 때 실데이터로 대체되지만, **시연 중 혼동을 부를 수 있다.**
450으로 바꿔둘지 알려주시면 반영하겠다.

### 4. sale 화면의 "판매 813대"

추첨제에서 이 숫자가 "당첨자가 구매한 수량"인지 "전체 판매량"인지 화면만 봐서는
알기 어렵다. 상태 배너가 생겨 맥락은 잡혔지만, 라벨을 "당첨자 구매 813대"처럼
바꾸는 것도 방법이다. 우선 그대로 뒀다.

## 확인만 하고 손대지 않은 것

- **`/waitlist` 계열 4개 라우트** — `WAITLIST_ENABLED = false`라서 랜딩으로 리다이렉트된다.
  죽은 라우트가 아니라 **의도된 비활성화**(2차 대기 등록 기능). 나중에 켤 때
  추첨제 문구 기준으로 다시 봐야 한다 — 지금 문안은 선착순 시절 것이다.
- **연동 4단계 안내(`SHOW_SETUP_GUIDE = false`)** — 지시대로 비활성화 상태. 코드는 남아 있어
  값 하나로 되살아난다.
- **`eb_closed` 상태** — 레거시 URL. 판매 계열로 렌더되며 얼리버드 흔적은 없다(QA 확인).

## 상태 흐름 (현재)

```
pre (기본)          응모 접수 중          → 사전 구매응모하기
  ↓ 9/5 이전이면
dday                응모 오픈 카운트다운   → 텔레그램으로 알림 받기
  ↓ 9/14 추첨 → 9/15
sale                당첨자 구매 기간       → 구매하기 (+ 상태 배너)
  ↓ 소진
sold_out            마감                  → 2차 소식 받기
```

각 상태의 GNB 프리뷰 칩이 서로를 가리키도록 되어 있어 내부 시연 시 이동이 가능하다
(QA `qa-b16` 이 네 방향 전부 확인).
