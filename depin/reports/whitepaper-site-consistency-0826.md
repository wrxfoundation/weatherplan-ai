## B. 불일치 — 조정 필요 (원칙: 실기기·실판매가 사실, 백서를 맞추는 방향)

### B1. 센서 구성 — 백서 스키마가 실기기를 거부한다 ★ 최우선
- 백서 텔레메트리 스키마 v1은 `pm1`(PM1.0)·`hpa`(기압)를 **필수 필드**로 두고 범위 검증(RANGES)까지 걸어둠.
- ARC-600DA 공식 사양(사이트 SPECS)에는 PM1.0·기압이 **없음** → 백서 검증 로직대로면 실기기
  페이로드가 422로 거부됨.
- 티어 정의도 연쇄 붕괴: iaq-pro 요건 = +TVOC·기압·PM1.0인데 실기기는 TVOC만 충족 →
  **ARC-600DA가 어느 티어인지 정의 불가** (std와 pro 사이).
- 권장: ① 기기 펌웨어가 PM1.0·기압을 실제로 출력하는지 확인(광산란 모듈은 PM1.0 내부 산출이
  흔함) ② 불가 시 스키마 v1을 실기기 6측정(PM2.5·PM10·CO₂·TVOC·온도·습도) 기준으로 재정의
  (`pm1`·`hpa` optional), pro 티어 요건을 "+TVOC"로 완화하고 ARC-600DA = iaq-pro로 명시.

### B2. 지표 개수 집계 불일치
- 백서 개요 "실내 IAQ **6종**"(미세먼지 묶음+CO₂+TVOC+온도+습도+기압) vs 사이트 표기
  **7항목**(PM2.5/PM10 분리 + 체감온도 포함, 기압 없음).
- 둘 다 자기 기준으론 맞지만 나란히 놓으면 숫자가 충돌. 집계 규약 통일 필요 —
  권장: "측정 6종(PM2.5·PM10·CO₂·TVOC·온도·습도) + 유도 1종(체감온도)" 방식으로 양쪽 통일.
  (측정 원물리량 기준이면 사이트도 6종이라 백서 '6종'과 자연 일치)

### B3. 하드웨어 경제성 축 — BOM 원가 vs 실판매가
- 백서 시뮬레이션의 하드웨어 원가: 55,000 / 120,000 / 210,000원 (BOM 추정) → "36개월 회수" 결론.
- 실제 판매가: 450 / 650 RLUSD ≈ 62만~90만원. **구매가 기준이면 백서 자체 모델(피크 1,838원/월)로
  회수에 약 28년** — 백서의 회수 프레임이 실판매 구조와 다른 세계의 숫자.
- 사이트는 수익·회수를 일절 약속하지 않으므로 **대외 리스크는 현재 없음.** 단 백서를 투자자·
  파트너에게 공유하는 순간 "구매자 경제성" 질문이 즉시 나옴.
- 권장: 백서에 성격 규정 1문단 추가 — "기기 판매가는 측정기 + 플랫폼 참여권의 대가이며,
  보상은 채굴 회수 모델이 아니라 데이터 기여 인센티브" (사이트 발화와 일치시키는 방향).
  회수 시뮬레이션은 '보조/렌탈 시나리오' 항목임을 명시.

### B4. 발행 주체·네임스페이스 혼재
- 백서: `kweather-iaq-telemetry/v1`, "Kweather IAQ Node", Domain `kweather.example` ↔ 같은 문서
  6+장은 `wlbn.wellbianlabs.io`. 케이웨더/웰비안 표기가 문서 내 혼재.
- 확정 방침(토큰 발행 주체 = 웰비안 싱가포르 분리, 8/27 명문화)과 어긋남.
- 권장: 스키마 네임스페이스·노드 명칭을 wellbian-* 로 통일하거나, 백서 서두에 역할 분리
  (케이웨더 = 기술·제조/웰비안 = 발행·판매) 명시 후 표기 규칙 고정. **8/27 법무 안건에 연동.**

### B5. 목업 보상 수치 과대 (사이트 쪽 유일 수정 후보)
- 마이페이지 목업: 128.4 WLBN / 2일 14시간 ≈ 월 1,490 WLBN ≈ 월 1.5만원 상당(쿠폰 환산 10원).
- 백서 정상상태 피크 1,838원/월의 **약 8배**, 부트스트랩 기대치의 2~3배.
- 스크린샷이 유통되면 그 수치가 보상 기대치로 굳음 → 목업을 월 150~180 WLBN 수준
  (예: 누적 13.2 WLBN)으로 하향 권장. (겸사겸사 3,842건도 가동시간과 2시간 오차 — 미세 조정 가능)

### B6. "총 5,000대 한정" 메타 문구
- 사이트 meta description "총 5,000대 한정" vs 완판 화면의 2차 판매 예고 — "1차 5,000대"로
  명확화 권장 (경미).

### B7. "날씨 데이터" vs "공기질 데이터" 카테고리 명칭
- 상표·제품명·계정 바이오 = **날씨 데이터**(Weather Data Token Generator™) ↔ 백서 = **공기질
  데이터** 생태계로 정의하고 "실외를 기상 관측으로 두었다면 침투율은 존재하지 않았다"며 기상
  관측과 의도적으로 구분.
- 논리 모순은 아니나(브랜드 우산 vs 데이터 카테고리) B2B 수요자·규제 설명에서 질문 소지.
- 권장: 백서 개요에 브릿지 1문장 — "'날씨 데이터'는 실내외 생활 기후·공기 환경 데이터의
  브랜드 총칭이며, 본 사양의 데이터 카테고리는 공기질(IAQ/OAQ)이다."

## C. 확인 필요 (팩트 미확정 — 서우/제조/플랫폼)

1. ARC-600DA 펌웨어의 PM1.0·기압 출력 가능 여부 (B1 분기점)
2. CO₂ 센서 방식이 NDIR인지 (백서 iaq-standard 요건 가정)
3. 라이선스 NFT 보유 지갑: 백서 = **기기 지갑**(시큐어 엘리먼트) 모델 / 사이트 문구는 중립이라
   현재 모순 없음 — 온보딩 UX 확정 전 플랫폼개발과 귀속 지갑 확정 필요
4. 스펙 단위 "μm/m³" 오기 정정 여부 (기존 건 — 백서는 µg/m³ 정상 표기라 사이트 원표만 문제)
5. 백서 공개 배포 시: 6+장 WHO 조기 사망 수치 출처 표기 필요 (보건 클레임)
